# SANO Jackpot中奖机制专项维护规范

## 1. 资料定位

本目录是SANO Jackpot中奖机制优化后续设计与交流的统一工作区。本阶段维护Markdown需求文档及管理端SVG、PNG原型，不建立客户端原型或其他技术设计产物目录。

## 2. 信息优先级

发生内容冲突时，按以下顺序判断：

1. 当前会话中用户最新明确确认的业务规则。
2. `需求文档/`中的当前有效产品需求文档。
3. 本目录README和维护规范。
4. 专项目录外的历史需求或交流资料。

## 3. 文档维护

- 当前有效产品需求统一放在`需求文档/`目录。
- 同一需求持续更新当前主文档，不按月份重复建立新版本。
- 文档应明确请求级随机参数、配置校验、中奖判断、奖金结算、状态流转、异常处理、权限和审计要求。
- 已确认规则写入正文；尚未确认且会影响实现的内容放入“待确认事项”。
- 不在产品需求文档中展开数据库表结构、字段类型、接口代码、技术组件选型和详细测试用例，除非后续明确要求。
- 管理端PNG只放在`设计/原型图/`，SVG只放在`设计/源文件/`，相同页面保持同名。
- 当前阶段不输出客户端原型、数据库设计、接口设计或详细测试用例。

## 4. 规则修改约束

- 每笔成功消费请求在配置最小值至最大值之间独立生成随机阈值，不预生成或复用后续请求参数。
- 修改随机阈值规则时，必须同步检查配置最小值、配置最大值和每笔请求独立生成逻辑。
- 修改倍率模板时，必须同步检查价值区间、模板权重和最终中奖概率。
- 修改奖金比例时，必须同步检查实际中奖时奖池金额、奖金公式和奖池扣减。
- 文档不得将“单个礼物数量”“单次赠送请求”和“单次实际消费价值”混为同一概念。

## 5. 每次迭代检查

1. 最新确认规则是否已同步到当前需求文档。
2. 是否先为每笔请求独立生成随机阈值，并在通过阈值后再随机选择模板。
3. 一次请求一次判断、按请求总价值匹配区间的口径是否保持一致。
4. 奖金是否始终按照实际中奖时的奖池金额计算。
5. 是否错误新增了短时间归并、概率递增、最长开奖时限或强制中奖规则。
6. 配置修改是否从后续请求生效，历史请求实际使用的参数是否仍可追溯。
7. 管理端SVG和PNG是否同名、尺寸一致，页面内容是否与需求文档一致。
