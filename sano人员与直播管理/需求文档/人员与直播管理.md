## 2. 背景与目标

运营需要清楚知道自己管理多少BD、哪些代理、哪些主播，代理之间有什么上下级关系，每个人是什么身份，以及相关人员的收入、冻结收益和直播工作情况。

查看路径应支持从整体数量进入具体对象，也支持直接通过列表筛选查找。找到主播后，可以进入个人详情；查看直播间后，可以继续进入实时审核并查看近七天巡查记录。

本期目标：

1. 看清授权范围内的BD、代理、子代理和主播关系。
2. 通过树形代理表格明确区分上下级，并看到每个代理的直属主播结构。
3. 查看主播分成后收入、代理提成收入和主播工作时长。
4. 查看范围内主播的冻结收益。
5. 了解当前在播人员与直播间情况，并能进入实时审核及近期巡查。
6. 优先使用已有字段和已处理数据，完成查询、筛选、汇总及下钻。

本期不引入综合画像评分、经营评级、资金链归因或大规模数据清洗重构。本文不输出数据库表、接口结构、技术架构、视觉原型和程序实现。

## 4. 对象、归属与权限

### 4.1 对象关系

业务对象统一称为“代理”，下级对象称为“子代理”，上级称为“上级代理”；原负责人称谓统一为“代理长”。代理ID标识代理组织，代理长ID标识其关联用户，两者分别保留。

- BD具有所属运营。
- 代理的实际负责人可能是BD，也可能是直属运营。
- 代理可以有上级代理、子代理及直属主播。
- 代理长是与代理关联的用户，代理ID与代理长ID分别保留。
- 主播具有所属代理、负责人和已有身份、实名认证信息。

负责人路径允许“运营 → BD → 代理”，也允许“运营 → 代理”。代理层级按实际上下级关系表达，不根据分成比例推定。

### 4.2 所属运营展示

代理列表的“所属运营”展示实际负责人：属于BD则显示BD，属于直属运营则显示运营人员。建议在姓名、ID旁显示“BD”或“运营”标识，便于区分同名人员。

代理列表的所属运营筛选应覆盖上述两类负责人。其他列表按其已有归属数据展示，不能为了统一页面而把所有代理都强制归到一个BD。

### 4.3 数据范围

1. 普通账号只查看自身权限范围内的对象及相关数据。
2. 例如运营A管理3个BD，可查看这3个BD及其管理链下获授权的代理、子代理、主播和相关业务数据；直属运营负责的代理也进入其实际授权范围。
3. 超级管理员或指定授权账号可以查看全部数据；全量范围由权限决定，不由页面手动填写身份获得。
4. 汇总、筛选候选、列表、树节点、个人详情、抽屉和巡查记录使用一致的范围限制。
5. 搜索ID、修改筛选、展开子节点或直接访问详情均不能扩大可见范围。
6. BD列表和代理列表仅提供查询、查看与关联列表入口，不包含新增、编辑操作。
7. 没有授权数据时展示空状态，不回退到全平台。

### 4.4 归属变更与历史查看

按照点击进入功能时的所属关系确定查看范围。已归属的数据保持原结果，相关归属已由现有数据处理完成。

本功能直接使用已处理的归属及业务记录，不重新归属历史数据，不建立历史责任快照，也不套用旧代理画像专项的历史归属重算机制。

## 5. 通用数据与交互规则

### 5.1 时间范围

- 业务时间沿用现有系统UTC+8口径。
- 业务统计默认近7天，即今天及前6个自然日；今天统计至已有数据更新时点。
- 日期范围筛选作用于相应列表及其详情，收入详情抽屉继承父列表统计时间段。
- 注册时间、创建时间用于筛选对象产生时间，与收入或工作数据的统计时间分开表达。

### 5.2 更新与允许误差

1. 今天的数据由已有定时器更新，当前程序只负责汇总。
2. 允许今天因更新时点不同产生统计误差，不为此增加实时重算链路。
3. 历史数据已固定，不随今天的刷新改变。
4. 工作时长各组成项有对应关系，允许已有计算误差；不人为修改数值使其强制相等。
5. 允许统计误差不表示可以忽略权限、扩大时间范围或把加载失败显示为0。

### 5.3 金额与时长

- 金额单位为美元，字段标题标明“$”。
- 主播总收入采用已有明确总计字段，是分成后所得，不再次扣分成。
- 不通过页面分类列相加替代已有总计字段。
- 金额精度沿用已有业务输出及展示约定，本功能不另建汇率或资产换算规则。
- 主播工作数据的时长单位为分钟（min），明细中的总时长同步标明单位。
- 原始精度与计算差异保留，不通过凑数消除差异。

### 5.4 通用交互

- 列表支持查询、重置和分页；查询条件变化后回到起始页。
- 重置只清除当前列表条件，不扩大账号可见范围；统计列表恢复默认近7天。
- ID支持复制；已有对应详情的对象提供跳转。
- 从代理进入主播列表时携带代理条件；从主播列表进入详情、再返回时保留来源筛选和分页。
- 无数据、真实0、无权限、加载中、加载失败分别表达。

### 5.5 页面与浮层职责

| 承载类型 | 本期用途 | 离开方式 |
| --- | --- | --- |
| 主界面 | 运营概览、七个二级菜单对应的列表和数据页 | 主导航切换或下钻 |
| 子页面 | 主播详情 | 明确返回按钮及面包屑，返回来源列表 |
| 右侧抽屉 | BD详情、收入与工作明细、实时审核、七天巡查 | 关闭回底层页面；同抽屉内返回不等于关闭 |
| 居中弹窗 | 巡查图片大图预览 | 只关闭预览，回到原巡查位置 |

抽屉保留遮罩下的来源内容，不将临时详情误画成新主界面；实时审核与巡查复用同一抽屉。具体来源、返回、关闭和状态保留规则见[交互关系说明](../设计/交互关系说明.md)。

## 7. 代理列表

### 7.1 树形结构

代理列表为可逐层展开、收起的树形表格。每行代表一个代理，通过层级缩进和展开标识表达上下级，原有上级信息字段仍保留。

交互约定：
    
- 展开父节点后加载其子代理，继续按实际关系展开。
- 筛选命中子代理时，应呈现可理解的层级路径；用于定位的祖先节点与筛选命中项明确区分。
- 层级路径不能绕过可见范围限制，也不能把定位用节点混算成筛选命中数量。
- 树展开状态不改变每行直属主播数量。
- 具体树形分页和过滤后的节点承载方式，在后续交互设计中细化。

### 7.2 展示字段

| 分组 | 字段 |
| --- | --- |
| 代理基础信息 | 代理ID、代理名称、代理等级、分成比例、创建时间 |
| 代理长 | 代理长ID、代理长昵称、代理长WhatsApp |
| 负责关系 | 所属运营（实际为BD或直属运营） |
| 直属主播结构 | 主播数量、优质主播数量、超级主播数量 |
| 上级代理 | 上级代理ID、上级代理名称 |
| 上级代理长 | 上级代理长ID、上级代理长昵称 |

共16个业务字段。表格可以分组组织单元格，字段完整性保持不变。

### 7.3 主播数量口径

- 主播数量：当前代理的直属主播总人数。
- 优质主播数量：直属主播中具有优质主播身份的人数。
- 超级主播数量：直属主播中具有超级主播身份的人数。
- 上述三项均不包含子代理主播。
- 身份使用已有业务结果，不新增身份判定算法；各身份人数不强制相加等于主播总人数。

### 7.4 筛选条件

代理ID、代理长ID、上级代理ID、上级代理长ID、代理等级、创建时间段、所属运营、分成比例。

分成比例选项：

| 业务值 | 展示值 |
| --- | --- |
| 0.04 | 4% |
| 0.08 | 8% |
| 0.12 | 12% |
| 0.16 | 16% |
| 0.20 | 20% |

### 7.5 操作

- 主播列表：进入当前代理的直属主播列表，带入代理ID。

## 8. 主播列表与个人详情

### 8.1 展示字段

主播ID、昵称、国家、性别、代理ID、代理昵称、所属运营、身份、实名认证、注册时间。

### 8.2 最终筛选条件

主播ID、昵称、国家、代理ID、性别、注册时间段、是否实名。

以上为本次已确认筛选，不额外加入所属运营、身份或其他筛选项。所属运营、身份仍作为展示字段保留。

### 8.3 个人详情入口

点击主播进入个人详情。个人详情的业务范围为：

- 身份与基础资料。
- 当前代理及负责人归属。
- 直播和工作数据。
- 收益与本人消费数据。
- 冻结收益。
- 当前直播入口及近七天巡查记录。

可参考现有用户详情的资料和业务记录，但不直接要求完整复用旧版七标签画像、评分和风险分析。个人详情的字段组合、布局及消费明细范围尚待细化。

### 8.3.1 详情页返回交互

- 从主播列表点击“查看详情”进入主播详情时，页面标题左侧固定位置展示“← 返回主播列表”按钮。
- 面包屑显示“组织管理 / 主播列表 / 主播详情”，其中“主播列表”可点击返回，作为辅助入口。
- 返回后恢复进入详情前的筛选条件、分页、排序和滚动位置，并定位原主播记录；不将返回等同于重新打开默认列表。
- 若从其他收入、工作等页面进入，返回按钮文案和目标跟随实际来源；本原型使用“来自主播列表”的代表状态。
- 直接打开详情且没有来源上下文时，返回当前权限范围内的主播列表。返回始终遵守当前权限范围。

### 8.4 直播与收入同页展示

- 在主播详情的“直播与收入”区域直接平铺收入构成和每日工作记录，取消“收入构成／工作记录”Tab及对应的外跳链接。
- 收入构成同时展示幸运礼物、普通礼物、游戏，以及单人直播、多人视频直播、音频直播、私聊收入；两个维度不重复相加。
- 每日记录直接展示日期、总收入、总时长、单人直播时长、多人直播时长、上麦时长，时长单位为min。
- 保留当前主播和默认近7天上下文，包含今天；使用已有分成后收入与工作时长结果。
- 主播详情顶部收入和总工作时长摘要也无需跳转到其他列表查看上述内容。实时审核和巡查入口继续保留。

## 9. 主播收入数据

### 9.1 展示字段

| 分组 | 字段 |
| --- | --- |
| 主播 | 主播ID、主播昵称、国家地区、性别 |
| 归属 | 代理ID、代理昵称、代理长ID、代理长昵称、运营人员 |
| 总计 | 总收入（$） |
| 业务类型 | 幸运礼物收入（$）、普通礼物收入（$）、游戏收入（$） |
| 渠道类型 | 单人直播收入（$）、多人视频直播收入（$）、音频直播收入（$）、私聊收入（$） |

### 9.2 筛选条件

主播ID、代理ID、代理长ID、运营人员、统计时间段、国家地区、性别、总收入下限（>=）、总收入上限（<=）。

统计时间段默认近7天，包含今天。

### 9.3 收入口径

- 主播总收入直接读取已有总计字段，是主播分成后实际所得。
- 业务类型与渠道类型是两个分类维度。
- 主播收入明细将业务类型和渠道类型各列在同一张表内平铺，同时显示，不设置两类收入的Tab切换。
- 私聊是渠道类型，与单人直播、多人视频直播、音频直播并列。
- 各渠道都可能包含幸运礼物、普通礼物等业务类型收入。
- 一笔收入可以同时归入一个渠道及一个业务类型，不把两个维度重复相加。
- 已有总计字段为总收入的依据，不通过分类列反推或重新计算总计。
- 本功能不额外创建“收入来源用户”“消费去向”或收入价值评分。

## 10. 代理收入数据

### 10.1 展示字段

代理ID、代理名称、代理长ID、分成比例、所属运营、总收入（$）、直属主播提成收入（$）、子代理提成收入（$）、创建时间。

创建时间表示该代理的创建时间。

原输入中的“提出收入”在本文统一按“提成收入”表述。

### 10.2 筛选条件

代理ID、代理长ID、运营人员、代理创建时间段、统计时间段、总收入下限（>=）、总收入上限（<=）。

代理创建时间段用于筛选代理对象，统计时间段用于限定收入发生周期；两项独立，可同时使用。代理创建时间段默认不限，统计时间段默认近7天，包含今天。

统计时间段默认近7天，包含今天。

### 10.3 查看详情

点击“查看详情”打开当前代理的同一个详情抽屉，抽屉内分三个标签。代理对象和统计时间段继承来源列表；切换标签不改变统计主体。

#### 10.3.1 每日汇总

日期、总收入（$）、直属主播提成收入（$）、子代理提成收入（$）。

#### 10.3.2 主播明细

日期、主播ID、昵称、主播总收入、代理提成比例、主播贡献（$）、父级代理贡献（$）。

#### 10.3.3 子代理明细

日期、子代理ID、昵称、子代理分成比例、代理比例、总贡献（$）。

### 10.4 明细解释与金额归属

- 代理收入及贡献使用已有已处理结果，本功能负责展示和汇总，不新增分层计算。
- 当前代理所得、父级代理所得分别表达，父级所得不混入当前代理收入。
- 主播收入字段按既有输出使用，不为展示代理提成而把主播分成后所得擅自当成新的分成前基数。
- 具体字段与已有结果的映射、子代理“昵称”和“代理比例”的对象说明，需在接口对接时核对并形成字段释义；不另建分账公式。

## 11. 主播工作数据

### 11.1 展示字段

主播ID、昵称、国家、性别、代理ID、代理昵称、所属运营、身份、总时长（min）、单人直播时长（min）、多人直播时长（min）。

### 11.2 筛选条件

已提出的对象筛选：ID、名称、国家代码、性别、所属运营、创建时间段。

本功能还需要有统计时间范围来明确时长对应的周期，默认近7天。原输入中的“创建时间段”具体对应主播注册时间还是其他业务创建时间，后续核对字段含义；不得与工作统计时间混用。

### 11.3 查看详情

点击“查看详情”打开当前主播的每日明细抽屉，继承统计时间段。

抽屉字段：日期、总时长（min）、单人直播时长（min）、多人直播时长（min）、上麦时长（min）。

### 11.4 时长口径

- 总时长、渠道时长、上麦时长已有对应关系，直接采用现有结果。
- 允许已有计算误差，不要求展示值强制满足精确加总等式。
- 本功能不重新定义有效直播，不自行修改上麦与多人直播的时长归属，不引入旧代理经营的房型排除条件。

## 12. 范围汇总与冻结收益

### 12.1 人员数量

BD数量、代理数量、主播总人数、超级主播数量、优质主播数量均限制在当前账号可见范围。

汇总时代理按代理ID去重，人员按对应人员ID去重。代理列表每行统计直属主播；全范围汇总不再重复叠加父子代理的全树人数。

当前关系数量与周期业务金额分别标注，不把“近7天”收入筛选自动解释成只统计近7天新增人员。

### 12.2 收入汇总

- 主播收入汇总采用范围内主播的已有分成后收入结果。
- 代理收入汇总采用范围内代理的已有代理收入结果。
- 主播收入与代理收入主体分别标明，不以一个未定义的“收益总额”混合替代。
- 幸运礼物收入、普通礼物收入等分类汇总遵循主播收入数据的相同分类口径。
- 总充值已移除，页面不为其预留汇总指标。

### 12.3 冻结收益

- 统计主体为当前授权范围内的主播。
- 展示这些主播的冻结收益汇总，不混入范围外主播或其他主体资金。
- 使用现有冻结收益数据，不创建冻结计算、冻结或解冻操作。
- 冻结收益的具体字段、金额时点及是否随业务统计时间段变化，在对接已有数据时核对；不擅自将其解释为近7天新增冻结金额或额外收入。

## 13. 直播间、实时审核与近七天巡查

### 13.1 已确认业务范围

1. 能看到当前权限范围内有多少人在直播。
2. 能通过直播间列表查看直播情况。
3. 从直播间列表打开实时审核，关闭回到直播间列表；从主播详情打开实时审核，关闭回到该主播详情。两种来源均保留底层页面上下文。
4. 根据主播查看近七天巡查记录。
5. 每天默认加载10张图片，支持查看更多。

### 13.2 巡查展示规则

- 从主播详情打开近七天巡查抽屉，关闭回到主播详情。
- 从实时审核进入巡查时复用同一个抽屉，提供“← 返回实时审核”；关闭整个抽屉回到原直播间列表或主播详情。
- 点击缩略图打开居中图片预览弹窗，关闭仅回到原巡查抽屉，保留日期、已加载图片和位置。

- 近七天包含今天，按日期分组展示。
- 每天默认展示最多10张；不足10张展示实际数量，不补足。
- “查看更多”继续加载对应日期记录，不把10张理解为每日存储上限。
- 图片保留已有时间、主播、房间或场次关联，通过图片预览弹窗查看大图。
- 没有图片时明确展示空状态，不能据此自动判断未开播或直播异常。
- 直播截图与已有人工审核或处理记录分别表达，不由图片数量生成审核结论。
- 通过主播详情或直播间进入时，遵守同一权限范围。

### 13.3 后续需细化的内容

- 直播间列表的完整字段、筛选、当前在播人数的已有判定口径。
- 实时审核抽屉中的具体字段和内容布局；右侧抽屉承载方式已确认。
- 最新画面、截图或直播播放的现有能力与展示方式。
- 巡查图片现有采集来源、更新时间和“查看更多”的加载方式。

上述属于已提出功能的细化，不表示已确认新增警告、封禁、推荐分档、评分或处罚操作。

## 15. 验收要点

### 15.1 范围与权限

- 普通运营只能查看其授权管理范围，BD不能通过筛选或ID进入范围外对象。
- 超级管理员及指定授权账号可查看全部数据。
- 运营直属代理与BD负责代理均按实际关系呈现。
- 汇总、树形展开、列表、详情、抽屉、巡查和筛选候选范围一致。
- 已处理归属结果不被页面重新分配，历史数据不因当前查询发生重算。

### 15.2 列表与字段

- 六类核心列表按本文展示字段及各自筛选条件提供查询。
- 代理表格能逐层展开，筛选后能识别上下级。
- 代理每行三项主播数量均为直属人数，展开子代理不改变父行统计。
- 分成比例筛选包含4%、8%、12%、16%、20%。
- 主播列表筛选严格使用已确认的七项条件。
- BD列表与代理列表不展示新增、编辑入口，不包含对应表单或弹窗。

### 15.3 收入与时长

- 主播总收入来自已有分成后总计字段，不再次扣分成。
- 私聊归为渠道类型，业务类型与渠道类型不重复相加。
- 代理收入抽屉含每日汇总、主播明细、子代理明细三个标签，继承对象和时间。
- 工作数据抽屉展示每日总时长、单人、多人与上麦时长，保留允许的计算误差。
- 统计默认近7天且包含今天，今天使用定时更新数据，历史结果保持固定。
- 总充值不再展示；冻结收益仅包含范围内主播。

### 15.4 查看链路

- 代理“主播列表”进入该代理直属主播范围。
- 点击主播可进入对应个人详情并返回来源列表。
- 能从直播间进入实时审核，并按主播查看近七天巡查。
- 巡查每天默认最多10张，可继续查看当天更多图片。
