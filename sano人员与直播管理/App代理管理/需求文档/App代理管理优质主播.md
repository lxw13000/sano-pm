# App代理管理：优质主播

| 项目 | 内容 |
| --- | --- |
| 版本 | V1.2 |
| 日期 | 2026-10-26 |
| 状态 | 本轮核心口径已确认，供产品、设计与研发评审 |
| 涉及端 | App现有公会管理页面 |
| 目标 | 查看当前有效直属优质主播的周直播表现和收入 |

## 1. 已确认范围

在现有“公会管理”页面的“主播管理”区域新增“优质主播”入口，位置为第三行、公会榜单右侧，与其他入口同级，使用现有紫色图标风格。

点击进入“优质主播”页面，展示当前有效的直属优质主播、三项收入汇总、八项主播数据，支持本周、上周或自定义单个完整自然周。

本轮确认：

- 总收入沿用现有主播总收入口径，不强制等于普通礼物收入与幸运礼物收入之和，单位沿用App现有收入单位。
- 自定义仅允许选择一个完整自然周，不支持连续多周合计。
- 历史查询先按查询时当前有效直属名单选人，再统计这些主播在所选周的个人数据，不按当时代理归属或优质身份有效期裁剪。
- 高峰时间段当天是否达标，直接复用程序已有完整算法。

## 2. 名单与权限

1. 名单同时满足：当前直属于该代理、当前优质主播身份有效。公会是App现有页面称谓，直属关系沿用代理业务定义。
2. 不含子代理主播；已失效、已取消、尚未生效的优质主播不入列。身份及关系均读取现有业务结果。
3. 即使筛选上周或更早周期，仍使用当前名单；历史上有效、当前不符合条件的主播不恢复入列。页面明确提示“按当前有效直属名单统计”。
4. 同一主播拥有多个身份或多条相关记录时按主播ID去重，每个主播一条。
5. 没有开播或收入记录的名单成员仍展示，已确认无业务记录的指标为0，不用有收入、有开播作为入列条件。
6. 当前代理范围由登录账号及已有代理管理权限确定，服务端校验；越权时停止展示并按现有无权限流程处理。
7. 每次进入、刷新或切换周重新获取当前名单。一次查询中的汇总、列表和分页使用同一名单及数据截止时点，避免关系变化造成错配；分页失效时重新加载该周完整查询。

## 3. 页面组成

从上到下依次为：页面标题、周筛选、已选日期与时间说明、三个收入汇总、名单说明、主播列表。

- 周筛选提供“本周”“上周”“自定义”。默认本周。
- 展示已应用周的周一至周日日期，统一标注“SANO Time · UTC+8”。
- 展示数据截止时间；本周包含未发生的未来日期，但只统计至截止时点，不提前生成未来天数。
- 收入汇总依次为总收入、普通礼物收入、幸运礼物收入。
- 列表采用表格，每位主播一行、八项字段各自独立成列，顺序为：ID、昵称、总时长、开播天数、高峰达标天数、总收入、普通礼物收入、幸运礼物收入，便于逐行比较直播达成情况。
- 手机表格允许横向滚动，固定左侧ID、昵称两列，默认完整显示总时长、开播天数和高峰达标天数；向左滑动表格查看右侧三项收入，始终可对应主播身份。数字按列对齐，表头注明时长、天数及收入单位；高峰达标天数使用紫色强调，不额外推导整周达标或奖励资格。
- 表头随列表纵向滚动保持可见。表格下方提供横向滚动位置提示；切周成功回到表格左端及列表顶部，返回页面保留已选周、纵向与横向位置。
- 列表按总收入降序，同额按主播ID升序；无额外排序、搜索、审核、奖励或个人详情入口。
- 列表数量较多时分批加载；汇总及名单人数覆盖全部符合条件主播，不随分页改变。返回后保留已选周和滚动位置；再次进入或刷新重新获取数据。

## 4. 指标口径

| 字段 | 定义与展示 |
| --- | --- |
| ID | 主播ID，独立标识，不因昵称过长隐藏ID |
| 昵称 | 当前昵称；过长可换行，不挤压ID和指标 |
| 总时长 | 所选周内已有主播总时长结果，沿用现有范围和精度；展示小时、分钟，超过24小时不折算为天 |
| 开播天数 | 所选周内已有开播日结果，按主播、业务日期去重，一天最多1天；不替换为有效开播天数，不引入新的单场门槛 |
| 满足高峰时间段开播天数 | 既有算法判定达标的每日结果按业务日期去重累计，一天最多1天；页面简称“高峰达标天数” |
| 总收入 | 已有主播分成后总收入，不再次扣分成，不作为代理佣金展示；可以包含两类礼物以外的已有收入 |
| 普通礼物收入 | 所选周内已有普通礼物收入，单位、分成和净额规则沿用现有App口径 |
| 幸运礼物收入 | 所选周内已有幸运礼物收入，单位、分成和净额规则沿用现有App口径 |

三个收入汇总分别累加当前名单内全部主播的对应周收入，使用原始精度计算后展示，不累加已经四舍五入的界面数值。币种、精度、冲正及负值展示沿用现有App，原型用美元两位小数作为示意，不新设币种或换算规则。

总时长读取已有结果，不重新修正时长误差。开播天数与高峰达标天数是两个独立指标，不由总时长反推，也不将高峰达标天数写成周任务审核结果。

高峰算法的时段、阈值、跨日、多场累计和业务日期归属均复用已有实现。本页面仅按所选自然周聚合每日判定，不解析展示文案推断达标，不在App重新计算。日结果缺失时标记统计中，不将缺失视为未达标。

## 5. 单个完整自然周筛选

统一按SANO Time（UTC+8）划分：每周一00:00:00至下一周一00:00:00前。界面显示周一至周日的包含首尾日期，设备时区不改变周归属。

| 筛选 | 行为 |
| --- | --- |
| 本周 | 服务端当前日期所在自然周，统计至当前可用数据截止时点 |
| 上周 | 上一个完整自然周 |
| 自定义 | 在日历中选择一个自然周，整行高亮；确认后只应用该周 |

选择器以周一为第一列。点击某天即选中其所在整周，展示完整起止日期；不设置独立开始、结束日期，不提供小时分钟输入，不允许拖选多周。

不能选择未来周，允许选择当前周；本周行中的未来日期可作为整周范围的一部分显示，不表示这些日期已有数据。打开时默认高亮已应用周。切换月份只浏览，不应用筛选；跨月周在月历补齐相邻月日期，并完整高亮。

点击“确认”才查询，点击“取消”、遮罩或关闭则返回原结果。候选周与“已应用”周分开，查询成功后才更新日期、汇总和列表；失败时不将旧数据标注为新周期。点击本周、上周直接发起查询，成功后列表回顶部。

如果自定义选中本周或上周，确认后对应快捷项高亮；其他周保持自定义高亮。列表数据加载失败时保留待重试目标周，点击重试查询该目标周。

示例时点为2026-10-26：本周2026-10-26～2026-11-01，上周2026-10-19～2026-10-25；自定义示例仅为2026-10-12～2026-10-18。

## 6. 状态与数据完整性

| 状态 | 展示与处理 |
| --- | --- |
| 正常 | 三项收入汇总和主播列表均按同一已应用周展示 |
| 加载中 | 整组汇总和列表显示加载占位，不混用上个周期数据 |
| 无当前有效成员 | 三项汇总为0，展示“暂无当前有效的直属优质主播” |
| 有成员、无业务 | 仍展示所有成员，已确认无业务的指标为0；页面提示“本周暂无直播和收入记录” |
| 首次或切周加载失败 | 保留目标周筛选，内容区展示加载失败及重试；不显示虚假的0金额或空名单 |
| 后续分页失败 | 保留已经加载的该周结果和完整汇总，仅在列表底部提供重试，不重复累计金额 |
| 部分结果缺失 | 缺失项展示“—”并提示统计中；对应汇总标记统计中，不用部分和冒充完整金额；其他完整指标正常展示 |

## 7. 页面与交互交付

以HTML、CSS、JavaScript作为可编辑交互源文件，浏览器直接打开，无需启动服务或下载远程资源。PNG仅为同一HTML的评审截图，不作为交互源文件，不使用SVG模拟页面。

提供20个可直接进入的演示场景，覆盖公会管理入口、三种周数据、左右滚动位置、不同来源的周选择器、空名单、无业务、加载失败、加载中、部分指标缺失，以及多成员分批加载、后续批次失败。

从公会管理点击优质主播进入本周；时间切换实际更新日期、汇总与表格。表格是真实八列，可触摸、鼠标拖动、使用滚动条或左右查看按钮横向滚动；固定ID、昵称，纵向滚动表格时表头吸顶，左右查看同一份数据。返回公会管理再进入保留已选周及表格位置。

日历可翻月、跳转月份，点击整周选中；确认应用，取消、遮罩或Escape关闭并保留原结果。本周与上周自动对应快捷项，未来周禁选，跨月、跨年自然周完整展示。加载失败可重试；正常查询有实际加载过渡；多成员可逐批加载，全量汇总不变，后续批次失败保留已有行并可重试。

独立的演示工具栏可切换场景、重置示例，不属于正式App。数据为本地虚构样例，示例时点固定为2026-10-26 18:00 SANO Time。三个固定示例周以外的历史周使用可复现演示数据，以便操作任意单周；不代表真实历史查询或高峰算法实现。初始“加载中”场景固定展示占位，正常筛选和重试会完成加载；现有业务入口仅保留位置，本次不展开。

不新增实际业务接口、数据库、身份审核、奖励发放、高峰算法或管理后台页面。本轮交付需求文档、HTML/CSS/JavaScript交互源文件、同源PNG截图、页面导航、交互说明、验证记录及生成脚本。
