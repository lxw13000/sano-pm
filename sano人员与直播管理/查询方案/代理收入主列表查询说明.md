# 代理收入主列表查询说明

代理收入主列表保留以下两份最终SQL：

- [程序使用的参数化SQL](代理收入主列表查询.sql)：包含服务端权限和全部前端筛选，参数由数据库驱动绑定。
- [可直接执行的SQL](代理收入主列表查询-直接结果.sql)：固定20个BD/运营账号ID、20261014—20261020，其他筛选为空，无绑定参数和执行计划语句。

另提供[代理日数据参数化SQL](代理日数据查询.sql)及[135937直接查询SQL](代理日数据查询-直接结果.sql)，参见[代理日数据查询说明](代理日数据查询说明.md)。

## 最终业务口径

| 字段 | 计算方式 |
| --- | --- |
| 所属运营昵称 | 最终结果通过sys_user.user_id=operator_id关联，返回nick_name AS operator_nick_name；未匹配时为NULL，不删除代理行 |
| 直属主播数 | 当前sano_user.proxy_id属于本代理的用户，用户ID取sano_user.id |
| 开播人数 | 指定日期内有sano_anchor_data记录的直属主播，期间按用户去重 |
| 有效开播人数 | 至少一天COALESCE(video_minute,0)+COALESCE(many_video_minute,0)>25，期间按用户去重 |
| 开播率/有效开播率 | 对应人数÷直属主播数，百分比保留1位小数；分母为0返回NULL |
| 收入 | 本代理sano_proxy_anchor_data.anchor_income合计，即旗下主播收益 |
| 子代理收入 | 直属子代理记录的parent_proxy_income合计，保留佣金口径 |
| 含子代理收入 | 上述两项原始金额相加后换算美元 |

两项金额均按10,000,000原始单位=1美元，先求和再换算，保留2位小数，不额外处理表注释中的*1000。proxy_income是代理分层佣金，本列表不使用。

有效开播在单条日记录上判断，恰好25分钟无效，不跨天累加；有记录即算开播，包括全零或纯语音记录。子代理只取直接下级，不递归累计孙级。归属沿当前已处理关系，SQL不重建历史归属。

## 程序参数

| 参数 | 含义 |
| --- | --- |
| permission_operator_ids_json | 后端计算的完整可见BD/运营账号ID集合，绑定JSON字符串，例如[111,222]；不能被前端选择替换 |
| can_view_all | 后端认证的全量权限，普通账号0，指定账号1 |
| filter_operator_id | 前端选中的运营账号ID，不选传NULL；与权限范围同时生效 |
| proxy_id、proxy_leader_id、parent_proxy_id、parent_proxy_leader_id | 代理/代理长/上级代理/上级代理长精确筛选，不填NULL |
| stat_start_day、stat_end_day | 整数日期，两端包含；程序默认近7天含今天 |
| proxy_create_start、proxy_create_end_exclusive | 代理创建时间，包含开始、不包含结束；不填NULL |
| direct_anchor_min、direct_anchor_max | 直属主播数上下限，不填NULL，0是有效条件 |
| valid_open_min、valid_open_max | 有效开播人数上下限，不填NULL |
| income_min_usd、income_max_usd | anchor_income收益合计的美元上下限，精确十进制绑定；按原始值筛选，不先四舍五入 |

程序校验日期、上下限、权限参数；普通账号空权限传[]，不能省略权限条件。service_user_id已确认是BD/直属运营账号ID；create_time沿代理表现有字段，未另加审核或删除过滤。

## 返回及执行

两份SQL均返回16个业务字段（含operator_id、operator_nick_name），按收入原始金额倒序，不分页、不统计记录总条数、不在SQL计算页面三项金额总计。前端或服务端用精确十进制累计返回的金额字段；无匹配代理直接返回空结果集。

收入来源ID先合并为候选代理自身及其直属子代理集合，再用单个EXISTS过滤日期范围原始记录。自身主播收益与子代理佣金独立汇总后关联，避免明细交叉倍增。当前使用已有day索引，不新增永久表或索引。

直接查询版权限账号ID：106、108、109、114、117、119、120、121、122、125、129、130、134、135、137、144、148、151、152、103。日期固定为20261014—20261020，需要其他区间时修改主播日表和收入日表两处日期条件。

当前方案用户执行计划记录704ms、2749行，前一版为1068ms；这是单次观测，不保证固定耗时。过程验证、诊断、候选和历史SQL已清理，历史分析Markdown仅作为过程记录。
