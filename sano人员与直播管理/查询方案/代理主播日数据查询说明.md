# 代理收入详情：主播日数据查询说明

- [程序参数化SQL](代理主播日数据查询.sql)
- [135937直接执行SQL](代理主播日数据查询-直接结果.sql)

每份文件包含两个独立SELECT：先查筛选后总条数，再查分页明细。接入MyBatis时分别放入count/list两个select节点，使用同一套查询条件，不把两条SQL放进一个select中执行。程序版沿用:xxx命名参数格式，需替换为MyBatis绑定参数，并处理XML转义或CDATA。

## 范围和粒度

指定sano_anchor_data.proxy_id与live_day起止日期，两端包含。代理ID由接口预先校验查看权限；不再传BD/运营集合，不通过parent_proxy_id查询子代理主播。

表主键(user_id,live_day)已保证一位主播一天一行，直接读取已有日数据，不重复SUM/GROUP BY，不补齐每位主播无记录的日期。通过sano_user.id=a.user_id获取nick；用户表仅补充昵称，不再用u.proxy_id筛掉日数据。昵称缺失时默认保留日记录，昵称搜索时按匹配结果筛选。

## 固定12列

| 列 | SQL字段 | 来源/口径 |
| --- | --- | --- |
| 日期 | stat_date | live_day转换为DATE |
| 主播ID | anchor_user_id | a.user_id |
| 主播昵称 | anchor_nick | sano_user.nick |
| 贡献佣金（$） | contribution_commission_usd | a.proxy_income，不混入父级所得 |
| 直播有效时长（min） | valid_live_minute | video_minute+many_video_minute，NULL按0；即使未超过25也显示实际和 |
| 单人直播时长（min） | video_minute | a.video_minute，NULL按0 |
| 多人直播时长（min） | many_video_minute | a.many_video_minute，NULL按0 |
| 上麦时长（min） | on_mic_minute | 尚未对接，固定NULL，页面留空 |
| 总收入（$） | income_usd | a.income |
| 普通礼物收入（$） | ordinary_gift_income_usd | a.income_luxurious，已由用户确认 |
| 幸运礼物收入（$） | lucky_gift_income_usd | a.income_lucky |
| 游戏收入（$） | game_income_usd | a.income_game，NULL按0 |

五项金额均已确认10,000,000原始单位=1美元，转换为足够精度的DECIMAL后换算，保留两位小数，不额外处理字段注释的*1000。有效时长按用户最新口径，不使用旧设计中的单场关播时长。

## 参数

| 参数 | 含义 |
| --- | --- |
| proxy_id | 必填，具体代理ID |
| stat_start_day、stat_end_day | YYYYMMDD整数，NULL默认数据库会话今天及前6天；抽屉自选周期可显式绑定 |
| anchor_user_id | 可选主播ID，不筛选时传NULL |
| anchor_nick | 可选主播昵称，LIKE包含匹配；NULL或空字符串不限，服务端可统一trim输入 |
| page_size | 分页明细使用，服务端默认20并校验正整数、最大值；须绑定整数，不传NULL |
| page_offset | 分页明细使用，服务端默认0并校验非负整数；须绑定整数 |

程序校验日期格式、开始<=结束。count查询不使用分页参数；list查询的LIMIT/OFFSET必须由程序赋默认值后绑定。MyBatis按Java DTO/Map实际命名调整占位符名称。

默认日期倒序，同日按贡献佣金原始金额（NULL按0）倒序，再按主播ID升序稳定排序。直接执行版固定代理135937、近7天含今天、主播筛选不限、每页20条、第一页；如手工新增主播筛选，应同步修改count/list两处条件。

## 与抽屉其他区域的关系

主播ID/昵称只筛选本标签明细及其总数，不改变抽屉顶部三个代理期间汇总，也不影响代理日数据标签。顶部金额继续使用独立的[代理收入详情汇总SQL](代理收入详情汇总查询.sql)，按代理ID和抽屉日期查询。
