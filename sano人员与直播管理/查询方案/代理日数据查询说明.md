# 代理日数据查询说明

对应设计“代理收入详情 → 代理日数据”抽屉，按某一个已授权代理、指定日期范围展示每日经营情况。主列表原SQL保持不变。

- [程序参数化SQL](代理日数据查询.sql)：代理ID必填，可绑定抽屉统计日期；与主列表一样使用:xxx命名参数。
- [135937直接查询SQL](代理日数据查询-直接结果.sql)：只按代理ID 135937查询，日期动态取数据库会话今天及前6天，无BD/运营集合，无绑定参数。

## 返回字段（设计固定10列）

| 设计列 | SQL字段 | 口径 |
| --- | --- | --- |
| 日期 | stat_date | DATE，一天一行，日期倒序 |
| 代理ID | proxy_id | 当前查询的代理 |
| 直属主播数 | direct_anchor_count | sano_stat_proxy按day_int+proxy_id匹配的people_amount，使用每天已有统计值 |
| 开播人数 | open_anchor_count | 当日有sano_anchor_data记录的直属用户去重人数 |
| 开播率 | open_rate_pct | 开播人数÷直属主播数×100，保留1位小数 |
| 有效开播人数 | valid_open_anchor_count | 当日video_minute+many_video_minute严格>25的直属用户去重人数，NULL按0 |
| 有效开播率 | valid_open_rate_pct | 有效开播人数÷直属主播数×100，保留1位小数 |
| 收入（$） | income_usd | 当日本代理SUM(anchor_income) |
| 子代理收入（$） | child_income_usd | 当日直属子代理SUM(parent_proxy_income)，不递归孙级 |
| 含子代理收入（$） | inclusive_income_usd | 上述两项原始金额先相加，再换算美元 |

anchor_income与parent_proxy_income均为10,000,000原始单位=1美元，先求和再换算，保留2位小数。proxy_income为代理分层佣金，本列表不取其作为收入。收入聚合独立于直播记录、当前主播成员明细，避免已有收入丢失或重复计入。

## 参数与默认周期

| 参数 | 含义 |
| --- | --- |
| proxy_id | 必填，代理表sano_proxy.id |
| stat_start_day | YYYYMMDD整数；NULL默认今天前6天 |
| stat_end_day | YYYYMMDD整数；NULL默认今天 |

抽屉打开时可显式传来源列表已查询周期，之后用抽屉自选周期；默认值仅用于未提供日期的情况。日期两端包含，程序校验日期格式、开始<=结束及合理跨度。默认CURDATE()取数据库会话日期；如业务统一用应用时区，请由服务端计算并显式绑定两个日期。

程序版参数格式与主列表一致，不是原样可粘贴的MyBatis XML。MyBatis中应将:参数改为对应#{参数名,jdbcType=...}，并使用XML转义或CDATA，绑定名称与DTO/Map保持一致。

## 日期、人数和单代理范围

- 日期补齐：指定代理存在时，范围内每个自然日均有一行；无开播或收入记录时相应指标为0。每日人数缺失或people_amount为NULL时保留NULL，不伪装为0；真实人数0仍保留0。代理不存在时直接返回空结果。
- 每日people_amount为0或NULL时开播率、有效开播率返回NULL，界面显示“—”；分母大于0、当天无人开播时为0.0%。
- 有记录即算开播，全零和纯语音日记录也计入；恰好25分钟无效，不跨天累计时长判断。此处使用最新确认的主播日表口径，覆盖旧设计中按房间close_time计算的说明。
- 直属主播数现使用用户提供的sano_stat_proxy.people_amount，每日分别取值；已确认主键(day_int,proxy_id)唯一，因此在日历与指定代理上按完整主键LEFT JOIN，单日最多匹配一条，不SUM/MAX人数、不计入子代理、不使用当前sano_user人数代替历史日人数。direct_members只用于定位已有主播日记录。
- 子代理只取直接下级。服务端在查询前完成目标代理ID权限校验，SQL只按该具体代理查询，不再接收BD/运营集合；子代理贡献不套用子代理所属运营筛选，只读取归目标代理的parent_proxy_income，不返回范围外代理资料。

## 抽屉期间汇总

本SQL只输出10个设计列，不额外返回全局汇总、记录总数或分页。期间开播/有效人数不能累加每日人数，期间比率不能平均每日比率。三项期间收入汇总使用[代理收入详情汇总参数化SQL](代理收入详情汇总查询.sql)，传同一代理ID和相同日期；可直接执行[135937汇总SQL](代理收入详情汇总查询-直接结果.sql)，默认近7天含今天。该SQL仅返回一行income_usd、child_income_usd、inclusive_income_usd，直接对原始anchor_income及直属子代理parent_proxy_income汇总后换算，不累加已四舍五入的每日金额。

## 验证

已按内存SQLite适配执行20项逻辑检查，初版曾覆盖两版一致、7天含今天、日期倒序、补零、权限/管理员、无代理/无成员、每日人数去重、25分钟边界、NULL时长、跨天不累加、收入字段独立性、直属子代理不递归、日期边界和自选周期。未连接业务MySQL执行，实际访问索引与耗时需结合该单代理执行计划验证；当前主播日记录改为成员×日期组合后按(user_id,live_day)完整主键等值查询；收入查询保持单代理范围策略，不复制主列表的平台日期扫描方式。

## 按单代理入口修正

代理日数据入口已经确定一个具体代理，当前SQL仅有proxy_id、stat_start_day、stat_end_day三个程序参数；已删除permission_operators、JSON_TABLE、BD/运营ID集合和can_view_all。服务端在调用前对这个代理ID做权限校验，SQL不重新按运营范围找代理。目标代理自己的成员与收益，以及其直属子代理贡献，均从这个代理ID展开。

修正后通过19项内存SQLite适配检查：两版一致、仅三个程序参数、代理ID精确范围、可独立查询子代理及其直接下级贡献、日期和默认7天、补零、人数/时长/收益口径及NULL。此版不在SQL内执行运营集合权限筛选，权限由接口在调用前校验。未连接实际MySQL执行。

## 首次耗时反馈后的完整主键定位

用户反馈首次超过23秒，随后计划显示根节点231ms、9行，查询日期实际为20261012—20261020（9天）。该次迭代器时间不等于此前首次执行的完整请求耗时，不能据此直接判定23秒只在客户端，缓存、负载、优化准备及取数阶段均需同条件测量。

已确认计划中的live_daily为227ms，占本次主要耗时：318个直属用户逐个按PRIMARY(user_id)读取，平均26.2条历史记录后过滤日期，最终保留604条。收入仅3.81ms，不调整收入路径。

当前两份日SQL仅重写live_daily：direct_members先与calendar_days组合，再STRAIGHT_JOIN sano_anchor_data FORCE INDEX(PRIMARY)，同时以a.user_id=m.user_id AND a.live_day=calendar.live_day等值关联。预期日表应按(user_id,live_day)完整主键精确查找，而不是只按user_id读取历史；318人×7天最多2226个点查组合（用户本次9天则2862个），没有记录的点不计入开播人数。默认日期仍为近7天含今天，不修改用户选择日期的规则。

重写后19项内存SQLite适配业务检查通过，收入、权限边界、默认周期、日期补齐及10列均不变；查询性能须用更新后的实际MySQL计划确认。对照时使用同代理、同日期，观察日表索引键是否同时包含user_id、live_day，并分别记录首次及后续直接查询耗时。

## 当日人数来源确认

用户提供sano_stat_proxy表：主键(day_int,proxy_id)，people_amount为该代理当日人数。已在两份日SQL的daily_metrics中按population.day_int=d.live_day AND population.proxy_id=p.proxy_id直接关联，返回people_amount AS direct_anchor_count；删除原member_stats COUNT。两项比率自动使用对应日期分母。未改用该表的open_amount、effective_open、open_rate或income字段，开播与收入仍沿用此前确认口径。

当前24项内存SQLite适配检查通过，增加每日人数变化、主键唯一关联、真实0、缺失记录/NULL、历史日比率、其他代理及范围外记录不串入、当前成员增多不覆盖历史人数等检查；仍未在业务MySQL环境验证本次修改的执行计划与耗时。此前关于没有日人数快照的说明已由本次提供的表结构更正。

## 期间汇总SQL使用

程序参数为proxy_id、stat_start_day、stat_end_day；日期NULL时默认数据库会话今天及前6天。接口预先校验目标代理权限和日期。代理存在但无收入时返回三个0，不存在则空结果。直属子代理关系取sano_proxy.parent_id，不递归孙级，不使用代理分层佣金proxy_income作为收入。

两份期间汇总SQL通过11项内存SQLite适配检查，覆盖直接版与程序版、日期边界、独立子代理查询、无目标/无收入、NULL金额、字段独立性、子代理贡献及先加原始值后舍入。实际MySQL耗时未测。

主播日数据采用[独立参数化SQL](代理主播日数据查询.sql)及[135937直接执行SQL](代理主播日数据查询-直接结果.sql)，参见[主播日数据字段及分页说明](代理主播日数据查询说明.md)。本标签按sano_anchor_data.proxy_id和日期读取每主播每日一行，昵称来自sano_user.nick；主播ID/昵称筛选不改变代理期间汇总。
