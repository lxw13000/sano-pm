# 提现管理 UE 走查与优化说明

版本：V1.4，2026-10-22。

## 当前结论

运营应在主列表确定处理范围，抽屉只承担核单、填写参数、提交和看结果。原先把筛选、勾选、六项状态卡以及重复进度消息放进抽屉，增加了操作和理解成本。本版按用户最新意见简化，主列表全部字段直接展示。

## V1.4 补充：提交二次确认

按用户最新要求，初审、复审提交均增加二次确认，包括通过、退款和下一固定子批次。确认弹窗展示本批范围、金额、处理结果及本次渠道／换号或退款理由。默认焦点在“返回修改”，确认前不产生业务动作；取消不丢草稿，确认时重新校验，防止重复和过期提交。

确认完成只关闭确认弹窗，原抽屉继续跟踪结果。本次明确增加二次确认，取代早期版本对普通通过不额外确认的设想。

## 当前布局

1. 本批概览：笔数、提现合计、提现方式。
2. 单一结果摘要：仅提交后展示，并随真实状态更新。
3. 本批订单：固定完整记录，逐笔状态、失败原因及提交记录。
4. 本次处理：红色加粗核单提示、展开／收起开关、处理参数及提交按钮。
5. 底部：最近刷新说明和关闭，提交与关闭不并排。

“先核对上方订单，再填写并提交本次处理”放在本次处理标题旁，红色加粗。收起参数后标题、提示和开关仍可见；展开／收起只属于处理块，不放在结果进度中。

## 删除的冗余设计

| 旧设计 | 当前调整 |
| --- | --- |
| 主列表隐藏／展开完整字段 | 全部字段展示，宽度不足横向滚动 |
| 抽屉内全部、可复审、打款中、已结束、未受理、已勾选等筛选 | 移除，固定显示本批完整记录 |
| 抽屉内复选框、全选、取消勾选 | 移除，范围已在主列表确定 |
| 六项状态计数卡 | 移除，顶部仅本批笔数、金额和方式 |
| 提交轮次消息与结束进度重复 | 合并成一条动态摘要，不重复展示 |
| 展开参数后可以原批再次执行 | 提交后参数仅查看，失败或未受理另进固定子批次 |

摘要示例：“本批已结束 2 / 3 笔 · 打款失败 1 笔”；全部结束为“本批已结束 3 / 3 笔 · 全部已结束”。受理记录与业务状态在表格中逐笔查看，不把受理成功当成打款成功。

## 保留的业务规则

主列表初审可跨提现方式，复审必须同一方式。渠道只列该方式配置且可用项，支持自动选择，本次指定不修改全局配置。换号明确是／否，后台逐笔处理。复审退款理由必填且用户可见，内部备注独立。

六种状态不变：待审核、驳回已退款、打款中、打款失败、打款成功、已退款。打款失败即需复审。初审、复审均用抽屉，提交后不自动关闭，30 秒刷新及手动刷新保留。

## 持续处理失败订单

原批提交后禁止再次整批执行。存在明确失败时，提供“复审失败订单 N 笔”入口；初审失败有多种提现方式时，按方式分别进入固定子批次。未受理通过独立入口建立下一批。进入新批只是核单和设置，不自动提交；可返回原批完整结果。

需要自定义某些订单一起处理时，仍从主列表勾选确定，抽屉不再提供第二套选单界面。

## 详情与批次回看

详情保持左右分栏弹窗，左收款与订单信息、右完整生命周期。其他空字段可收起，时间轴保持正序且有最新定位。最近处理批次允许关闭后处理别的批再回看；原型仅保留本次页面打开期间最近 10 批，正式产品需持久化查询。

## 验证与交付

交互验证覆盖提交二次确认、取消不执行、确认时状态变化拦截、防重复点击，以及固定批次、红色提示、参数开关归属、单一结果摘要、只读记录防重复提交、失败与未受理子批次、30 秒刷新、最近批次回看、43 笔分页及窄桌面布局，见 [验证记录](验证记录.md)。

本轮为原型走查和浏览器交互验证，未替代实际运营人员试用。原版见 [V1.0 归档](归档/2026-10-22-UE优化前/README.md)。
