# 提现管理交互关系

## 页面层级

| 层级 | 入口 | 承载形式 | 返回 |
| --- | --- | --- | --- |
| 提现管理 | 资金管理 → 提现管理 | 主列表 | 保留筛选及位置 |
| 单笔／批量初审 | 待审核订单行初审／勾选后批量初审 | 右侧抽屉 | 手动关闭回来源列表 |
| 单笔／批量复审 | 打款失败订单行复审／勾选后批量复审 | 右侧抽屉 | 手动关闭回来源列表 |
| 订单详情 | 列表订单号／详情、抽屉订单号／详情 | 左右分栏居中弹窗 | 关闭回实际来源：列表或原抽屉 |

```text
提现管理列表
  ├─ 初审抽屉 → 提交 → 保持打开 → 刷新实际状态
  │    └─ 订单详情弹窗 → 关闭 → 原初审抽屉
  ├─ 复审抽屉 → 提交 → 保持打开 → 刷新实际状态
  │    ├─ 再次失败 → 勾选失败项 → 再次复审 → 继续刷新
  │    └─ 订单详情弹窗 → 关闭 → 原复审抽屉
  └─ 订单详情弹窗 → 关闭 → 原列表
```

## 选择与提交

- 列表仅待审核、打款失败可勾选。混合状态不允许统一初审或复审，不静默过滤。
- 初审可跨提现方式；复审必须同一方式，历史渠道无需一致。
- 抽屉内的完整订单集合保持不变；勾选集合与完整集合分开维护。
- 初审只能提交仍为待审核的订单；复审只能提交打款失败订单。
- 成功受理后清除该笔勾选。再次失败不会自动勾选，需运营主动选择。
- 部分提交未受理在对应行显示，保留该项勾选；其他已受理订单不可重复提交。
- 初审不通过退款完成为“驳回已退款”，复审退款完成为“已退款”。

## 抽屉保持与刷新

- 初审和复审均不因提交成功、打款成功、退款成功或全部结束而自动关闭。
- 每 30 秒刷新本批订单，也可手动刷新，标明最近刷新时间。
- 自动刷新不清空参数草稿、不跳动滚动位置、不改变抽屉的完整订单集合。
- 关闭按钮或 Escape 手动关闭；提交期间禁止关闭和重复提交；点击遮罩不关闭。
- 关闭后结束本抽屉定时器；重新打开不会叠加轮询。

## 订单详情

- 维持弹窗，扩大宽度，左右同时可见：左当前详情、右历史时间轴。
- 两侧独立滚动，不使用订单信息／历史记录页签。
- 顶部固定当前订单号、状态和刷新；刷新更新当前信息及历史，保留滚动位置。
- 时间轴从上到下为实际发生顺序，记录每次打款、复审、换号和结果。
- 换号使用“原 → 新”关联；自动渠道还要记录实际渠道。
- 抽屉上叠加详情时，关闭详情恢复原抽屉及草稿，不把用户送回列表。

## 键盘及可读性

抽屉／详情打开时焦点进入浮层，Tab 在当前浮层内循环，关闭后焦点返回来源控件（来源控件仍存在时）；Escape 优先关闭最上层详情。状态文字与颜色并用，金额与币种同行，长编号可换行和复制。窄桌面保留左右分栏，宽表在内部滚动，不让整页横向溢出。
