# SANO用户任务体系页面原型

## 原型说明

- 管理端页面：23张，统一为1672×941；主页面、操作状态、抽屉和弹窗按业务层级分别展示。
- App H5页面：19张；常规页面为940×1640，周/月奖励与任务模块组合页为可滚动长页。
- `原型图/`中的PNG用于评审和分享，`源文件/`中的SVG作为可编辑源文件保留。
- `生成工具/`保存SVG生成和PNG渲染脚本，输出目录已经与工具目录分离。
- 页面中的主播、周期、任务、结果和奖励均为原型示例数据，不代表真实线上数据。
- 任务项页面展示任务参数JSON、结果结构JSON、运营说明和用户说明；任务执行器不感知奖励。
- 任务模块页面配置模块周期、任务组合、小周期完成数量与连续要求，以及模块奖励策略。
- 数值阶梯表单采用“计奖依据任务 + 计奖指标 + 通用档位”，不与收入、邀请等具体业务绑定。
- H5模块进度按“已完成任务项数/模块任务项总数”展示；天数、条数、次数等属于具体任务进度。
- H5模块列表和模块内任务列表使用公共组件；模块列表只展示模块级概述，任务详情根据任务标识及结果结构JSON加载对应实现。
- 模块奖励优先突出金币和钻石，存在其他资产时显示“奖励详情”并通过弹窗逐项展示。
- H5顶部按日、周、月切换；日任务使用日期选择器，周/月仅保留当前周期和上一周期。
- 周/月超过上一周期的未领取奖励视为已放弃；H5不设置独立奖励记录页。
- 原型文件使用`端类型-一级模块-二级功能-页面序号-页面名称`命名，例如`admin-01-02-03-管理关联任务抽屉`、`H5-02-01-02-日任务日期选择器`。
- 页面编号一经分配即保持稳定；新增页面只在所属二级功能下追加页面序号，文档展示顺序不反向改变文件编号。
- 同一用户可以拥有多个身份，但各身份周期快照、任务结果、审核与奖励记录独立，不跨身份复用。
- 身份取消、失效或禁止后，已经进入待领取的奖励仍可领取；未达标、审核不通过或尚未形成待领取凭证的数据不可补领。
- 配置菜单拆分为任务库、任务模块、用户身份三个子菜单，不再使用任务库内的二级页签。
- 任务库采用左右结构，左侧筛选和选择任务项，右侧直接完成任务详情查看、新增、编辑与保存，不再使用任务项抽屉。
- 任务模块主页面保留“基础信息、关联任务、奖励配置”三段完整展示；关系和奖励的实际修改使用抽屉，选择对象和编辑单条明细使用弹窗。
- 任务模块基础信息包含奖励类型；阶梯奖励配置通过任务来源JSON声明来源任务和结果指标路径。
- 奖励类型只在模块基础信息中修改；奖励配置抽屉只维护当前奖励类型对应的明细或阶梯档位。
- 周期任务详情中的材料审核入口打开独立材料审核弹窗，完成截图查看、逐条审核、用户可见理由和任务结果汇总。
- 奖励管理使用“周期奖励结算记录”，未达标、审核不通过、待领取和已领取均保留结算结果。
- 周期奖励结算记录采用列表与右侧详情抽屉两张原型；列表不在底部加载详情，抽屉使用结构化奖励明细并将原始JSON默认折叠。

## 信息架构

- 用户任务体系配置
  - 任务库
  - 任务模块
  - 用户身份
- 用户身份成员
- 周期任务审核
- 周期奖励结算记录
- App优质主播模块
  - 身份申请与状态
  - 日/周/月周期切换
  - 日任务日期选择器
  - 周任务本周/上周
  - 月任务本月/上月
  - 当前周期任务与材料提交
  - 任务模块详情与任务列表
  - 具体任务结果详情
  - 上一周期或历史日期奖励与主动领取
  - 历史任务模块列表、模块详情与冻结任务详情
  - 奖励组合与奖励详情弹窗
  - 分享奖励模块、分享任务详情与上传入口
  - 模块未完成与无奖励说明
  - 整周期审核不通过与用户可见理由
  - 规则说明

## 重新生成

在PowerShell中执行：

```powershell
.\设计\生成工具\generate-prototypes.ps1
.\设计\生成工具\render-prototypes.ps1
```

只重渲染指定页面：

```powershell
.\设计\生成工具\render-prototypes.ps1 -Names 'H5-02-02-01-周任务本周','H5-02-02-02-周任务上周奖励待领取'
```

生成脚本输出SVG到`源文件/`；渲染脚本从`源文件/`读取SVG并输出PNG到`原型图/`。
