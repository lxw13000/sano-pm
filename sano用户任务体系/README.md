# SANO用户任务体系专项

本目录集中管理SANO用户任务体系相关的需求、产品策略、管理端与App设计、原型源文件、生成工具和需求输入资料。当前第一阶段以优质主播用户身份为落地场景，后续可继续扩展签约主播、活动任务、成长任务及其他用户任务类型。

## 当前设计主线

体系采用“用户身份 + 任务模块（组）+ 任务项 + 模块奖励”的组合策略：

- 用户身份关注有哪些身份、资格和规则，通过关联关系决定该身份需要完成哪些任务模块。
- 身份与任务模块关联只保存身份ID、任务模块ID和App展示顺序。
- 任务模块配置日、周或月周期，关注任务组成、每项任务的周期完成要求和模块奖励策略。
- 任务库关注具体任务定义、任务周期、参数JSON、结果定义JSON、独立执行器和统一任务结果，任务项不配置奖励。
- 任务执行器按照任务项的结果结构JSON输出`completed`、`resultText`、`metrics`和`detailData`；具体任务详情由任务标识对应的实现解析，模块聚合器计算最少完成周期数与最长连续周期数。
- 模块内全部任务要求完成才获得模块奖励；奖励策略支持无奖励、固定奖励和按任务指标阶梯奖励。
- 奖励支持金币、钻石、经验、热度、穿戴道具和直播间礼物等多资产组合。
- 系统按完整自然周期和用户身份分别生成快照；同一用户可以拥有多个身份，但各身份任务结果与奖励独立、不跨身份复用。
- 每个用户身份周期生成一条周期奖励结算记录，区分未达标、审核不通过、待领取和已领取；存在奖励时生成多明细待领取凭证，由用户一次领取。身份后续取消、失效或禁止不撤销已经进入待领取的奖励；未达标或审核不通过不得补领。

## 目录结构

- `需求文档/`：当前有效产品需求、策略说明、流程和页面规则。
- `设计/原型图/`：用于评审和分享的PNG页面原型。
- `设计/源文件/`：可编辑、可重新生成的SVG原型源文件。
- `设计/生成工具/`：与当前原型配套的SVG生成与PNG导出脚本。
- 原型文件按`端类型-一级模块-二级功能-页面序号-页面名称`稳定编号，新增页面不会引起其他模块重排。
- `资源/需求输入/`：用户提供的思维导图、政策输入和原始需求资料。
- `资源/历史需求/`：迭代前的历史需求文档，仅供追溯，不作为当前实现依据。
- `维护规范.md`：本专项后续文档、设计和资源的维护规则。

## 当前有效范围

当前产品需求文档和`设计/`目录中的42张原型为本阶段有效基线（管理端23张、App H5 19张）。`资源/历史需求/`中的内容用于理解历史背景；当其与当前产品需求文档冲突时，以当前产品需求文档为准。

## 重新生成原型

1. 运行`设计/生成工具/generate-prototypes.ps1`，输出SVG到`设计/源文件/`。
2. 运行`设计/生成工具/render-prototypes.ps1`，输出PNG到`设计/原型图/`。

后续本专项相关的需求交流、规则调整和原型迭代，默认在本目录内进行，不再以`8月/`或更早月份目录作为工作入口。
