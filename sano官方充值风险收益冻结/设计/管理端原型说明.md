## 字段与操作规则

1. 风险用户 `del_flag = 0` 为封禁中；人工解除后写入 `del_flag = 1`、`del_time`。原型中的 `auto_del` 仅表示是否允许自动解除，未模拟自动任务。
2. 汇总记录的 `refund = 0` 显示“未解除”，`refund = 1` 显示“已解除”。抽屉只加载本次符合条件的未解除汇总记录；底部按钮按用户一次性处理全部记录，每条写入同一 `refund_user`、`refund_time`。
3. 只有 `当前时间 ≥ del_time + 24 小时`，退款操作才可进入抽屉。提交时服务端仍须再次校验权限、用户状态、时间与可解封记录，并在同一事务中更新本批汇总记录。
4. 本次处理后若该用户没有其他未解除汇总记录，用户表的 `refund` 变为 1，并记录用户级 `refund_user`、`refund_time`；若还有不在本次条件范围内的记录，则保持未完成并提示待核对。重复提交不得重复处理已解除记录。
5. 冻结列表中的当前冻结数只合计汇总表 `refund = 0` 的钻石；日数据保留已解除历史，满足“总数 = 未解除 + 已解除”。
6. 风险录入员仅能加入名单；风险解除员仅能人工解除；退款操作员在独立的“解封钻石（退款）”页面查看全部风险名单和执行退款。风险充值用户页面不显示退款入口与用户级退款结论。

## 退款前的充值价值核对

- 点击“退款操作”打开批量解封抽屉。充值查询范围为用户封禁日 `create_time` 至解除日 `del_time`，**首尾自然日均包含**；只统计 `sano_wallet_recharge.status = 2` 的成功充值。
- 官方充值美元：`producer_type IN (0, 1)` 的 `money` 之和。三方充值美元（含币商）：其余渠道之和，其中 `producer_type = 4` 的 `money` 先除以 `10000`。
- `充值价值 = 取整数部分[(官方美元 + 三方美元) × 10000 × 0.84]`。
- `待解封钻石 = 取整数部分[SUM(sano_wallet_diamond_freeze.diamond) / 1000]`；仅纳入同一自然日区间内该用户 `type != 0 AND refund = 0` 的汇总记录。抽屉下半部分展示的记录与此计算采用同一筛选条件。所有钻石展示均采用该单位。
- 当充值价值小于待解封钻石时，退款列表和抽屉均提示“该用户充值金额价值小于待解封钻石，请谨慎操作，建议核实充值后再解封”。**这只是提醒，不阻止解封**；也不新增核对快照或风险留痕字段。批量更新仍逐行记录汇总表既有的 `refund_user`、`refund_time`。

## 实施前需要统一的口径

- `sano_wallet_diamond_freeze.refund` 的表注释是“是否解除”，用户表 `refund` 的表注释是“是否退款”。本原型分别用“汇总记录解除”与“用户级退款完成”表达；实际账务动作及命名应在接口设计时统一。
- 国家、昵称不在这三张表中，原型按用户资料补充展示。
- 逐笔表没有直接指向汇总表复合主键的外键；原型按消费者、上账用户、主播、入账日和类型关联。真实查询需确认 `user_id`、`consume_user_id` 的方向、`EDiamondFreezeType` 枚举及跨日入账规则。
- 风险用户表以 `user_id` 为主键，只能存当前一条状态。原型中的人工解除说明仅存在页面内存；本轮未新增充值核对留痕。
- 这版按最新三表和三页流程绘制。既有核心设计文档中的“充值比例自动切换、180 天到期资格、独立人工审核申请”尚未映射到本组三表，应在开发前确认是否仍属于本期。

原型按钮只修改当前浏览器页面的演示数据，刷新后复原，不会触发真实退款或钻石账务。运行 `生成预览.js` 可重新生成预览图，并检查权限、筛选、明细对账、自然日充值核对、提示但不阻断、24 小时限制和按用户批量解封状态。
