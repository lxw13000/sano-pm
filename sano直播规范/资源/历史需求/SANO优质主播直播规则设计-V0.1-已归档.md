## 2. 设计目标

建立优质主播在单人直播和多人直播场景下的统一质量标准，确保规则具备以下能力：

1. 主播能够在开播前理解必须做到的事项和禁止行为。
2. 运营能够使用统一口径发现、取证和判定违规。
3. 警告、奖励取消和资格取消能够按累计次数准确执行。
4. 多人直播中能够明确房主对嘉宾和麦位质量的管理责任。
5. 每次判定和处置均可追溯，并为复核或申诉保留证据。

## 3. 适用范围与角色

### 3.1 适用对象

- 已获得SANO优质主播资格的主播。
- 正在申请或处于考察期的主播，可将本规范作为审核依据；具体是否累计正式警告待确认。
- 多人直播中的房主和上麦嘉宾。

### 3.2 适用场景

- 单人直播。
- 多人直播、连麦或派对房等包含房主和嘉宾麦位的直播。
- 高峰时段直播。高峰时段的具体时间范围由运营配置，当前尚未给出。

### 3.3 角色责任

| 角色 | 主要责任 |
| --- | --- |
| 优质主播 | 保持形象、内容和互动质量，遵守独家直播要求，及时整改违规行为 |
| 多人房房主 | 持续提供主要内容，管理嘉宾和麦位，及时处理低活跃或低质量嘉宾 |
| 嘉宾 | 出镜并进行真实、持续、有效的互动 |
| 审核/运营 | 发现和复核违规，保存证据，执行警告、奖励或资格处置 |
| 系统 | 记录违规次数、处置状态、通知结果和操作日志，避免重复计次 |

## 4. 优质主播正向直播标准

| 编号 | 规则 | 设计化判定口径 | 状态 |
| --- | --- | --- | --- |
| G-01 | 直播期间必须化妆并保持良好的个人形象 | 主播本人应正常出镜，妆容、服装、仪态和直播环境不得明显影响观看体验 | 已明确；细化尺度待确认 |
| G-02 | 高峰时段表现应与申请时上传的视频保持一致 | 高峰直播中的主播身份、主要形象和整体内容表现不得与申请视频产生明显不一致 | 已明确；高峰时段及比对维度待确认 |
| G-03 | 积极向进入房间的用户打招呼 | 主播应持续关注进房用户，并进行自然、可感知的欢迎互动 | 已明确；响应时限待确认 |
| G-04 | 对礼物进行有效互动 | 收到礼物后应进行口头感谢或点名感谢，不得长期无反馈 | 已明确；响应时限待确认 |
| G-05 | 不得同时在多个平台直播 | 同一主播在SANO直播期间，不得同时在其他直播平台进行直播 | 已明确 |
| G-06 | 禁止低质量直播 | 主播不得出现本规范第5章所列低质量或无效直播行为 | 已明确 |

## 5. 单人直播违规规则

下列行为属于直播质量违规。原始要求规定统一采用三级累计处置，具体见第7章。

| 编号 | 违规行为 | 判定说明 | 主要证据 |
| --- | --- | --- | --- |
| V-01 | 长时间坐着不说话 | 主播持续出镜但长时间无语言表达、无有效表演且无用户互动 | 直播片段、音轨、互动日志 |
| V-02 | 静音直播 | 直播间持续无有效声音，或主播主动静音导致无法正常观看 | 音轨、静音状态、直播片段 |
| V-03 | 躺床直播或躺播 | 主播以躺卧姿态进行低参与、低质量直播 | 直播截图或片段 |
| V-04 | 主播长时间离开镜头 | 直播仍在继续，但主播本人持续不在有效画面内 | 直播片段、人像检测记录 |
| V-05 | 黑屏直播 | 直播画面持续黑屏或无可识别内容 | 直播片段、视频质量日志 |
| V-06 | 长时间等待用户进入且不展示内容 | 主播以空等用户为主要状态，没有可感知的内容输出 | 直播片段、互动日志 |
| V-07 | 仅播放音乐且主播未参与 | 直播主要内容为播放音乐，主播未进行演唱、讲解或互动等有效参与 | 直播片段、音轨 |
| V-08 | 长时间看手机 | 主播持续操作或观看其他设备，未面向直播用户提供内容和互动 | 直播片段 |
| V-09 | 画面长期模糊、黑屏、严重抖动或遮挡 | 因设备、操作或环境导致画面长期不可正常观看 | 直播片段、视频质量日志 |
| V-10 | 挂播等其他低质量直播 | 主播仅维持开播状态，没有真实、持续的直播内容或互动 | 直播片段、在线和互动日志 |

### 5.1 合并与区分原则

- V-03包含“躺床直播”和其他明显躺播行为，避免同一行为重复计次。
- V-05强调完整或主要画面黑屏；V-09还包括模糊、抖动和遮挡等画面质量问题。
- V-01强调主播在镜头内但不输出内容；V-04强调主播离开镜头；V-06强调以等待用户为由不展示内容；V-10作为其他挂播行为的兜底项。
- 同一时间段同时命中多项规则时，可以记录多个违规标签，但原则上按一个违规事件累计一次警告；是否存在需要分别计次的严重情形待确认。

## 6. 多人直播规则

### 6.1 房主和嘉宾要求

| 编号 | 规则要求 | 责任主体 | 未履行时的违规认定 |
| --- | --- | --- | --- |
| M-01 | 房主必须保持主要直播内容 | 房主 | 房主未持续主持、表演或组织互动，导致直播间缺少主要内容 |
| M-02 | 嘉宾必须具有实际互动行为 | 嘉宾；房主负管理责任 | 嘉宾仅占麦位但没有语言、表演或其他可感知互动 |
| M-03 | 嘉宾长时间不说话、不出镜或不互动时应及时处理 | 房主 | 房主发现或应当发现后，仍长期不提醒、不调整或不移出麦位 |
| M-04 | 嘉宾长期低活跃时应移出麦位 | 房主 | 低活跃状态持续存在，房主未采取移麦处理 |
| M-05 | 多名嘉宾同时在麦时，应主动放大互动嘉宾的麦位 | 房主 | 未突出当前有效互动嘉宾，影响主要内容呈现 |
| M-06 | 麦上嘉宾出现低质量直播行为时应及时处理 | 房主 | 嘉宾命中第5章相关行为后，房主未提醒、调整或移出麦位 |

### 6.2 多人直播责任边界

- 嘉宾对自身的出镜和互动质量负责。
- 房主对直播间主要内容和麦位秩序承担管理责任。
- 嘉宾发生低质量行为时，应先记录嘉宾行为，同时判断房主是否履行及时处理义务。
- 房主已及时提醒、切换展示或移出嘉宾的，不应仅因嘉宾的短暂异常直接认定房主违规。
- “及时处理”“长期低活跃”“主动放大”的具体时限和操作标准尚未给出，应在评审后形成可配置口径。

## 7. 违规累计与处置

### 7.1 已明确的三级处置

| 累计阶段 | 处置 | 规则解释 |
| --- | --- | --- |
| 第1次警告 | 警告一次 | 通知主播具体违规行为、证据和整改要求 |
| 第2次警告 | 取消奖励 | 在第二次有效警告后取消奖励；奖励类型和取消周期待确认 |
| 第3次警告 | 取消资格 | 在第三次有效警告后直接取消优质主播资格 |

### 7.2 处置状态设计建议

| 状态 | 含义 | 可进入状态 |
| --- | --- | --- |
| 正常 | 当前没有生效警告，或历史警告已按规则清除 | 第1次警告 |
| 已警告 | 已有1次有效警告 | 奖励取消、正常（如存在清除机制） |
| 奖励取消 | 已有2次有效警告，优质主播资格暂保留 | 资格取消、正常（如存在恢复机制） |
| 资格取消 | 已有3次有效警告，优质主播资格失效 | 恢复/重新申请（规则待定） |

### 7.3 计次原则设计建议

- 仅“审核成立”的违规事件计入有效警告次数。
- 同一场直播、同一连续行为被系统重复识别或多人重复举报时，应合并为一个待审核事件，避免重复处罚。
- 主播整改后再次发生同类行为，是否作为新的违规事件，应由“整改完成时间 + 再次发生时间 + 审核证据”共同判断。
- 警告次数按主播账号累计，不因切换单人房、多人房或设备而拆分。
- 警告的累计周期、清零条件、奖励恢复和资格恢复均待业务确认；在规则确认前系统不得自动清零。

## 8. 违规发现与处理流程

1. **发现：**违规可由系统检测、运营巡查或用户举报产生。
2. **生成事件：**记录主播、直播间、直播场次、规则编号、发生时间和证据片段。
3. **去重合并：**合并同一连续行为的重复检测或重复举报。
4. **人工审核：**审核人员确认行为是否命中规则，并判断多人直播中的责任主体。
5. **作出处置：**根据该主播当前有效警告次数执行第1、第2或第3级处置。
6. **通知主播：**告知违规规则、发生时间、处置结果、整改要求和复核入口。
7. **记录留痕：**保存审核意见、证据、处置前后状态和操作人。
8. **复核更正：**复核不成立时撤销本次警告，并恢复因该警告产生的奖励或资格影响。

## 9. 识别与审核口径

### 9.1 系统可辅助识别的信号

- 音频：持续无声、语音活跃度过低、仅有背景音乐。
- 视频：黑屏、模糊、遮挡、抖动、人像长时间缺失或姿态异常。
- 互动：主播发言、评论回应、礼物感谢和点名反馈情况。
- 麦位：嘉宾上麦时长、发言活跃度、出镜状态、房主的移麦或放大操作。
- 跨平台直播：系统可记录疑似线索，但考虑误判风险，建议由人工复核后再处罚。

### 9.2 人工审核要求

- 不以单帧截图判定“长时间”类违规，应检查连续片段。
- 不仅检查主播是否出镜，还要结合声音、动作、内容和互动判断是否有效直播。
- 多人直播必须分别判断嘉宾的直接行为与房主的管理责任。
- 审核结论必须引用稳定的规则编号，并保留支持结论的关键时间段。
- 网络故障、设备突发故障或紧急离场不自动免责，但应允许结合持续时间、主播处置和复播情况进行复核。

## 10. 通知与整改要求

每次违规通知至少包含：

- 违规直播场次和发生时间。
- 命中的规则编号及行为说明。
- 可展示的证据片段或截图。
- 当前是第几次有效警告。
- 本次处置结果及生效时间。
- 主播应采取的整改动作。
- 复核或申诉入口与有效期；具体有效期待确认。

整改建议应与行为对应，例如：

- 静音或无声：检查麦克风权限和设备后恢复有效声音。
- 离镜、黑屏或遮挡：立即回到有效画面并修复视频状态。
- 无互动：恢复内容输出，回应进房用户和礼物互动。
- 嘉宾低活跃：提醒嘉宾互动，必要时切换展示或移出麦位。

## 11. 运营配置与数据记录建议

### 11.1 可配置项

- 高峰时段范围。
- “长时间”“及时处理”“长期低活跃”的时间阈值。
- 警告累计周期和清零条件。
- 第二次警告取消的奖励范围、周期及恢复条件。
- 第三次警告后的资格恢复或重新申请条件。
- 申诉有效期和复核处理时限。

### 11.2 违规记录字段

- 违规事件ID、主播ID、直播间ID、直播场次ID。
- 单人/多人直播场景、房主ID、嘉宾ID和责任主体。
- 规则编号、违规标签、首次发生时间、结束时间和持续时长。
- 来源类型：系统、运营巡查或用户举报。
- 证据地址、审核结论、审核人、审核时间和审核备注。
- 处置前警告次数、处置后警告次数、处置类型和生效时间。
- 通知状态、整改状态、申诉状态和复核结果。

## 12. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 主播持续坐在镜头前但长时间不说话且无互动 | 命中V-01；审核成立后累计一次有效警告 |
| 主播离开镜头并造成黑屏，同一连续时段被多次检测 | 可记录V-04和V-05标签，但合并为一个违规事件，避免重复计次 |
| 主播播放音乐，同时持续演唱并与用户互动 | 不应仅因播放音乐命中V-07 |
| 主播收到礼物后进行口头或点名感谢 | 满足G-04 |
| 多人房嘉宾短暂掉线，房主立即移出麦位 | 记录异常即可，不认定房主违反M-03或M-04 |
| 嘉宾长期不说话，房主不处理 | 嘉宾行为可命中低活跃规则，房主同时命中M-03或M-04 |
| 同一事件被系统和多个用户同时上报 | 合并线索，审核成立后只累计一次警告 |
| 第二次有效警告成立 | 取消已确认范围内的奖励，资格继续保留 |
| 第三次有效警告成立 | 直接取消优质主播资格 |
| 申诉复核认定违规不成立 | 撤销本次警告，并恢复由该警告产生的处置影响 |

## 13. 待业务确认事项

以下问题会直接影响产品提示、审核执行和系统实现，应在规则定稿前确认：

1. “优质主播”的申请条件、有效期和资格复审周期是什么？
2. 高峰时段具体是哪些时段，是否按国家、地区或主播分组配置？
3. 与申请视频“保持一致”具体比较身份、妆容、内容类型、语言、才艺还是综合表现？允许的合理变化范围是什么？
4. “长时间不说话、离开镜头、看手机、画面异常、等待用户”分别达到多久才违规？
5. “及时处理嘉宾”和“长期低活跃”的时间阈值是什么？
6. 房主“主动放大互动嘉宾麦位”是强制产品操作，还是只需保证活跃嘉宾获得主要展示？
7. 警告次数按自然周、自然月、滚动周期还是资格有效期累计？何时清零？
8. 第二次警告取消哪些奖励：本场、当日、当周、当期还是全部优质主播奖励？何时恢复？
9. 第三次警告取消资格后，能否重新申请？如可以，冷却期和重新考核条件是什么？
10. 同一直播场次出现多个独立违规行为时，是按事件分别计次，还是单场最多计一次？
11. 违规发生后即时整改，是否仍累计警告？首次轻微问题是否允许仅提醒不计次？
12. 是否设置严重违规直接取消奖励或资格的例外等级？当前输入只明确三级累计处置。
13. 主播申诉有效期、运营复核时限以及奖励或资格恢复方式是什么？
14. 申请期主播尚无优质主播资格时，违规如何处置和影响申请结果？

## 14. 与Niki参考规则的边界
