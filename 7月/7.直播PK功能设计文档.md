## 1. 背景与目标

### 1.1 项目背景

为提升主播互动体验、增加直播间流水及增强主播竞技氛围，平台计划推出直播PK玩法升级方案。本次调整将原“PK预约”能力升级为“PK Club”，由APP原生完整承载主播发现、兴趣匹配、挑战发布、挑战加入、进行中PK查看等能力，降低主播之间建立PK关系的成本。

直播PK整体仍包含PK Club、实时PK、积分结算、排行榜、奖励发放等完整业务闭环。其中PK日榜、周榜、胜场榜积分规则及结算规则保持不变。

### 1.2 核心目标

+ **APP端**：提供原生PK Club入口，支持All、进行中、唱歌、跳舞、脱口秀、挑战帖分组，主播可创建PK资料卡、发布挑战帖、加入挑战、查看进行中PK。
+ **主播匹配效率**：通过PK兴趣标签、在线状态优先排序、挑战帖关系沉淀，帮助主播快速找到可PK对象。
+ **排行榜与奖励**：保留原PK积分、日榜、周榜、胜场榜及奖励领取逻辑，确保活动激励口径不变。
+ **管理端**：支持PK资料卡、挑战帖、挑战关系、PK记录、排行榜、奖励配置及领取记录的运营管理。
+ **数据一致性**：全链路时间统一采用UTC+8，PK记录作为排行榜与积分结算的唯一数据来源。

## 2. 功能设计

### 2.1 APP端功能设计

#### 2.1.1 PK Club首页

+ **功能描述**：PK Club替代原PK预约模块，由APP原生实现。主播进入后可浏览可PK主播、查看当前进行中PK、发布或加入挑战帖，并维护自己的PK资料卡。
+ **分组标签**：
    - **All**：展示所有已创建PK资料卡且填写PK兴趣标签的主播。
    - **进行中**：展示当前正在进行PK的列表。
    - **唱歌**：展示PK兴趣标签包含“唱歌”的主播。
    - **跳舞**：展示PK兴趣标签包含“跳舞”的主播。
    - **脱口秀**：展示PK兴趣标签包含“脱口秀”的主播。
    - **挑战帖**：展示所有主播发布的挑战信息，支持发布、编辑、加入挑战。
+ **创建自己的PK资料入口**：
    - PK Club首页固定提供“创建/编辑我的PK资料”入口，建议放在页面右上角或顶部个人资料区域。
    - 未创建PK资料卡的主播进入PK Club时，页面顶部展示引导入口，点击进入PK资料卡创建页。
    - 已创建PK资料卡的主播点击入口进入编辑页，可修改PK兴趣标签、语言标签、自定义挑战说明等可编辑内容。
    - 主播在挑战帖分组点击“发布挑战”时，如未创建PK资料卡，系统先跳转至PK资料卡创建页，创建完成后再返回挑战帖发布流程。
+ **基础排序规则**：
    - 已在线主播优先展示。
    - 同为在线或同为离线时，按推荐规则或最近活跃时间排序。
    - 未填写PK兴趣标签的主播不进入All及兴趣标签分组。

#### 2.1.2 主播用户卡

+ **功能描述**：用于在All、唱歌、跳舞、脱口秀等分组中展示可PK主播。
+ **展示字段**：
    - 头像
    - 昵称
    - 国别
    - PK兴趣标签
    - 语言标签
    - 是否在线
+ **点击行为**：
    - 主播已开播：进入直播间。
    - 主播未开播：进入主播资料卡。

#### 2.1.3 进行中PK列表

+ **功能描述**：展示当前正在进行PK的直播列表，便于用户观看或主播了解当前PK氛围。
+ **列表字段**：
    - PK双方主播头像、昵称、国别。
    - PK主题或兴趣标签。
    - 当前比分或双方金币流水。
    - PK剩余时间。
    - 双方在线/开播状态。
+ **交互**：点击列表项进入对应PK直播间或PK观战页。

#### 2.1.4 PK资料卡

+ **功能描述**：主播在PK Club内创建或编辑自己的PK展示资料，资料卡是进入All和兴趣标签分组的前置条件。
+ **入口设计**：
    - PK Club首页顶部提供“我的PK资料”入口。
    - All、唱歌、跳舞、脱口秀、挑战帖分组页面均保留该入口，确保主播在任意分组下都可快速创建或编辑资料卡。
    - 未创建资料卡时，入口文案为“创建我的PK资料”；已创建资料卡时，入口文案为“编辑我的PK资料”。
    - 点击他人用户卡进入的是对方主播资料卡，不进入自己的PK资料编辑页。
+ **资料字段**：
    - 主播头像（系统读取）
    - 主播昵称（系统读取）
    - 国别（系统读取）
    - PK兴趣标签（唱歌、跳舞、脱口秀，可多选）
    - 语言标签（英语、西语、葡语、印尼语、菲律宾语）
    - 自定义挑战说明
    - 在线状态（系统读取）
+ **数据约束**：
    - 一个主播有且仅有一张PK资料卡。
    - 在线状态由系统实时维护，主播不可手动修改。
    - 资料卡未填写PK兴趣标签时，不进入All及兴趣标签分组的数据列表。

#### 2.1.5 挑战帖

+ **功能描述**：挑战帖用于承载主播主动发起的PK挑战信息，其他主播可加入挑战并形成挑战关系。
+ **列表字段**：
    - 发起主播头像、昵称、国别。
    - PK兴趣标签。
    - 语言标签
    - 挑战标题或挑战内容。
    - 是否在线。
    - 当前加入人数。
    - 发布时间或最近更新时间。
+ **发布与编辑**：
    - 主播未发布挑战帖时，可创建自己的挑战帖。
    - 主播已发布挑战帖时，再次进入创建入口应进入编辑当前挑战帖。
    - 未创建PK资料卡的主播，发布挑战帖前需先完成PK资料卡。
+ **加入挑战**：
    - 其他主播可加入挑战，加入后形成挑战关系。
    - 已加入时展示“已加入”状态。
    - 同一主播对同一挑战帖仅允许存在一条有效加入关系。
+ **删除规则**：
    - 挑战帖拥有者可删除自己的挑战帖。
    - 挑战帖拥有者删除后，该挑战帖下所有加入关系同步消除。

#### 2.1.6 实时PK开始

+ **功能描述**：主播可通过PK Club用户卡、挑战帖或直播间入口进入对方直播间并发起实时PK。
+ **开始条件**：
    - 双方均满足直播PK条件。
    - 双方进入直播间并完成PK连接。
+ **PK时长**：固定10分钟。
+ **头像点击行为**：
    - 已开播进入直播间。
    - 未开播进入主播资料卡。

#### 2.1.7 排行榜与奖励领取

+ **功能描述**：展示PK积分日榜、积分周榜、胜场周榜，并提供奖励领取入口。
+ **榜单类型**：
    - 积分日榜
    - 积分周榜
    - 胜场周榜
+ **展示周期**：
    - 今日
    - 昨日
    - 本周
    - 上周
+ **奖励领取**：
    - 领取入口：排行榜页面。
    - 支持昨日日榜奖励，建议系统自动发放。
    - 支持上周周榜奖励，主播主动领取。
+ **奖励状态**：
    - 未领取
    - 已领取
    - 已失效

### 2.2 管理端功能设计

#### 2.2.1 PK Club功能模块

+ **功能描述**：管理端新增“PK Club”一级功能模块，集中承载PK Club相关运营管理能力。
+ **模块入口**：管理端左侧菜单新增“PK Club”，点击后进入PK Club管理模块。
+ **子功能块**：
    - **PK Club资料卡管理**：管理主播在APP端创建的PK资料卡。
    - **PK挑战帖管理**：管理主播发布的挑战帖内容及状态。
    - **PK挑战加入关系查询**：查询挑战帖下的加入关系，排查关系异常。
    - **PK记录与排行榜管理**：查看PK记录、结算结果及榜单快照。
    - **PK奖励配置与领取记录**：配置榜单奖励并查看奖励领取明细。
+ **基础能力**：
    - 支持按主播ID、国别、PK兴趣标签、语言标签、状态、时间范围筛选。
    - 支持查看详情、状态处理、数据导出（如管理端已有导出能力则复用）。
    - 所有人工操作需记录操作人、操作时间、操作前后状态及操作原因。

#### 2.2.2 PK Club资料卡管理

+ **功能描述**：运营查看、筛选、管理主播PK资料卡。
+ **列表字段**：主播ID、昵称、国别、PK兴趣标签、语言标签、在线状态、资料卡状态、创建时间、更新时间。
+ **筛选条件**：主播ID、国别、PK兴趣标签、语言标签、在线状态、资料卡状态。
+ **详情字段**：头像、昵称、国别、PK兴趣标签、语言标签、自定义挑战说明、在线状态、创建时间、更新时间。
+ **操作能力**：
    - 查看资料卡详情。
    - 禁用/恢复资料卡展示。
    - 查看该主播当前挑战帖及历史PK记录。
    - 操作时需填写原因，并记录操作日志。

#### 2.2.3 PK挑战帖管理

+ **功能描述**：运营查看和管理主播发布的挑战帖。
+ **列表字段**：挑战帖编号、主播ID、昵称、国别、挑战内容、兴趣标签、语言标签、加入人数、状态、创建时间、更新时间。
+ **筛选条件**：挑战帖编号、主播ID、国别、兴趣标签、语言标签、状态、创建时间。
+ **操作能力**：查看详情、下架/恢复挑战帖、查看加入关系。
+ **管理规则**：
    - 下架挑战帖后，APP端不再展示该挑战帖。
    - 如需同步失效加入关系，需在操作确认中明确提示运营。
    - 系统自动删除与运营手动下架需区分状态和操作来源。

#### 2.2.4 PK挑战加入关系查询

+ **功能描述**：查看挑战帖下的加入主播关系，便于运营排查异常关系。
+ **列表字段**：挑战帖编号、帖子拥有者ID、加入主播ID、加入状态、加入时间、取消时间、关系失效原因。
+ **筛选条件**：挑战帖编号、帖子拥有者ID、加入主播ID、加入状态、加入时间。
+ **数据约束**：挑战帖删除后，对应有效加入关系需同步失效或删除。
+ **操作能力**：查看关系详情、查看挑战帖详情、查看加入主播资料卡。

#### 2.2.5 PK记录与排行榜管理

+ **功能描述**：查看实时PK记录、积分结算结果及榜单快照。
+ **PK记录字段**：PK编号、双方主播ID、房间ID、开始时间、结束时间、PK时长、双方金币流水、是否有效PK、双方积分、结算状态。
+ **排行榜字段**：榜单类型、榜单日期、主播ID、排名、总积分、胜场、奖励状态。
+ **筛选条件**：PK编号、主播ID、榜单类型、榜单日期、结算状态、是否有效PK。
+ **操作能力**：查看PK详情、查看结算明细、查看榜单快照。

#### 2.2.6 PK奖励配置与领取记录

+ **功能描述**：配置PK榜单奖励并查看奖励领取明细。
+ **奖励配置项**：榜单类型、名次、积分奖励、钻石奖励、穿戴道具、道具有效期、最低积分门槛。
+ **领取记录字段**：主播ID、榜单类型、榜单日期、排名、总积分、胜场、奖励内容、领取状态、领取时间。
+ **操作能力**：新增/编辑奖励配置、启用/停用配置、查看领取记录、按条件导出。

## 3. 核心业务规则梳理

### 3.1 PK Club展示规则

+ **All分组**：展示所有已创建PK资料卡且填写PK兴趣标签的主播。
+ **兴趣标签分组**：唱歌、跳舞、脱口秀分别按资料卡标签加载主播。
+ **在线优先**：All及兴趣标签分组均按在线状态优先排序。
+ **进行中分组**：仅展示当前正在进行PK的列表，不展示未开播或未PK主播。
+ **用户卡字段统一**：头像、昵称、国别、PK兴趣标签、语言标签、是否在线。

### 3.2 挑战帖唯一性与关系保持

+ **挑战帖唯一性**：一个主播有且仅有一个挑战帖。
+ **资料卡前置**：主播创建挑战帖前必须先创建PK资料卡。
+ **加入关系**：其他主播加入挑战后形成挑战关系，关系需要保持。
+ **关系消除**：挑战帖拥有者删除挑战帖后，该挑战帖下所有加入关系同步消除。
+ **重复加入限制**：同一主播对同一挑战帖仅允许存在一条有效加入关系。

### 3.3 有效PK与积分结算规则

+ **有效PK条件**：同时满足PK满10分钟、双方各自直播间总金币流水≥20000金币。
+ **无效PK**：未满足有效PK条件时，不计入积分。
+ **单场积分规则**：

```Plaintext
基础积分      +30
流水积分      floor(金币÷200)
胜者积分      +35
败者积分      +20
连胜积分      +20
```

+ **跨天归属**：跨天PK按照开始时间归属日期。
+ **规则稳定性**：PK日榜、周榜、胜场榜积分规则及结算规则保持不变。

### 3.4 排行榜规则

+ **日榜**：单场积分累计，每5分钟刷新，每日凌晨定榜。
+ **周榜**：单场积分+日榜奖励积分，每周一凌晨定榜。
+ **胜场榜**：按胜场数排序。
+ **排序规则**：
    - 第一排序：总积分。
    - 第二排序：胜场。
+ **时间口径**：统一采用UTC+8。
+ **数据来源**：PK记录表作为排行榜唯一积分数据来源，不再单独建立PK积分流水表。

### 3.5 奖励发放规则

+ **奖励入口**：排行榜页面。
+ **日榜奖励**：昨日日榜奖励，建议系统自动发放。
+ **周榜奖励**：上周周榜奖励，主播主动领取。
+ **幂等要求**：奖励发放需保证幂等，同一榜单同一主播不可重复发放。
+ **定榜限制**：定榜后排行榜数据不可修改。

## 4. 设计角色与环境配置

### 4.1 角色权限

+ **主播**：APP端创建PK资料卡、浏览PK Club、发布/编辑/删除挑战帖、加入挑战、发起实时PK、查看排行榜、领取奖励。
+ **观众**：查看进行中PK，进入PK直播间观看。
+ **运营**：管理端查看和管理资料卡、挑战帖、挑战关系、PK记录、排行榜、奖励配置和领取记录。
+ **系统**：维护在线状态、进行中PK状态、PK结算、榜单刷新、定榜、奖励发放幂等校验。

### 4.2 环境配置

+ **时间服务**：全链路时间统一采用UTC+8，接口返回时间字段需明确时区口径。
+ **在线状态服务**：由系统实时维护主播在线状态，并同步给PK Club列表。
+ **定时任务**：
    - 日榜每5分钟刷新。
    - 每日凌晨执行日榜定榜。
    - 每周一凌晨执行周榜和胜场周榜定榜。
+ **数据一致性**：挑战帖删除与加入关系失效需在同一事务或可靠补偿机制内完成。

### 5.5 PK榜单与奖励表

+ **pk_rank_snapshot**：保存日榜、积分周榜、胜场周榜定榜快照，字段包含榜单类型、榜单日期、主播ID、排名、总积分、胜场、奖励状态。
+ **pk_reward_config**：保存榜单奖励配置，字段包含榜单类型、名次、积分奖励、钻石奖励、穿戴道具、道具有效期、最低积分门槛。
+ **pk_reward_record**：保存奖励领取记录，字段包含榜单类型、榜单日期、主播ID、排名、总积分、胜场、奖励内容、领取状态、领取时间。

## 6. 测试场景推演与预期数据

### 6.1 All分组展示

+ **场景**：主播A已创建PK资料卡并填写“唱歌”标签，主播B创建资料卡但未填写标签。
+ **预期**：主播A展示在All分组，主播B不展示在All分组。

### 6.2 创建自己的PK资料入口

+ **场景**：主播A首次进入PK Club，尚未创建PK资料卡。
+ **预期**：页面展示“创建我的PK资料”入口，点击后进入资料卡创建页；创建成功后返回PK Club并可编辑资料。

### 6.3 兴趣标签与在线优先排序

+ **场景**：唱歌分组中存在多个主播，其中主播A在线、主播B离线。
+ **预期**：主播A排序优先于主播B，列表卡片均展示头像、昵称、国别、PK兴趣标签、语言标签、是否在线。

### 6.4 挑战帖唯一性

+ **场景**：主播A已发布一个挑战帖，再次点击发布挑战。
+ **预期**：系统进入已有挑战帖编辑页，不允许创建第二个有效挑战帖。

### 6.5 挑战关系消除

+ **场景**：主播B、主播C已加入主播A的挑战帖，主播A删除该挑战帖。
+ **预期**：挑战帖删除成功，主播B、主播C与该挑战帖的加入关系同步消除。

### 6.6 有效PK结算

+ **场景**：双方PK满10分钟，且双方各自直播间金币流水均≥20000。
+ **预期**：PK判定为有效，按基础积分、流水积分、胜负积分、连胜积分计算本场积分。

### 6.7 无效PK结算

+ **场景**：双方PK未满10分钟，或任一方金币流水不足20000。
+ **预期**：PK判定为无效，不计入积分。

### 6.8 跨天PK归属

+ **场景**：PK开始时间为23:58，结束时间为次日00:08。
+ **预期**：该场PK积分归属开始时间所在日期。

### 6.9 榜单定榜与奖励领取

+ **场景**：每日凌晨定榜后主播进入排行榜页面。
+ **预期**：昨日榜单数据固定不可修改，符合奖励条件的主播可查看奖励状态并领取或等待自动发放。
