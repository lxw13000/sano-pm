## 1. 背景与目标

### 1.1 项目背景

为优化当前平台直播列表根据热度排序的结果，提升优质主播在开播后的初始曝光能力，平台计划新增“主播综合评分评估系统”。系统通过运营评分与系统数据相结合的方式，给主播生成当前生效综合评分，并在主播开播时将综合评分换算为热度加成，叠加到原有热度中。

V1版本以当前平台可落地能力为前提，不做复杂评分引擎，不做动态评分维度，不强依赖尚未成熟的风控、关联账号、异常交易识别能力。V1固定使用三个评分维度：颜值、直播环境、近7天有效流水。

### 1.2 核心目标

+ **管理端**：新增主播综合评估模块，支持评分参数配置、主播评分查看、运营评分维护、人工锁定评分、评分计算记录查询。
+ **评分体系**：V1固定使用颜值、直播环境、近7天有效流水三个维度计算综合评分。
+ **运营干预**：支持运营设置锁定评分，锁定后主播当前生效综合评分不受系统自动计算覆盖。
+ **热度排序优化**：主播开播时，在原有热度基础上增加 `当前生效综合评分 * 热度换算比例`，用于优化直播列表热度排序结果。
+ **可控落地**：V1先支持影子运行和小流量热度生效，避免一次性影响全量主播排序。
+ **数据可追溯**：每日计算评分并保留计算记录，便于运营解释和问题排查。

## 2. 功能设计

### 2.1 管理端功能设计

#### 2.1.1 主播综合评估功能模块

+ **功能描述**：管理端新增“主播综合评估”一级功能模块，集中管理评分配置、主播评分、评分锁定及计算记录。
+ **模块入口**：管理端左侧菜单新增“主播综合评估”。
+ **子功能块**：
    - **评分参数配置**：配置固定三维度权重、热度换算比例、热度计算评分上限、流水分段规则。
    - **主播评分管理**：查看主播综合评分，维护颜值分、直播环境分，设置人工锁定评分。
    - **评分计算记录**：查看每日自动计算结果及人工调整记录。
+ **基础能力**：
    - 支持按主播ID、国家、当前生效综合评分区间、锁定状态、最近计算时间筛选。
    - 支持查看评分详情、编辑运营评分项、锁定/解锁综合评分。
    - 所有人工操作需记录操作人、操作时间、操作前后值及操作原因。

#### 2.1.2 评分参数配置

+ **功能描述**：配置V1综合评分计算和热度加成所需参数。
+ **配置项**：
    - **颜值权重**：颜值分在综合评分中的占比。
    - **直播环境权重**：直播环境分在综合评分中的占比。
    - **近7天有效流水权重**：流水分在综合评分中的占比。
    - **热度换算比例**：默认 `1分 = 1000热度`，支持配置。
    - **热度计算评分上限**：当前生效综合评分参与热度换算的最高分值；超过上限时，按上限分参与换算。
    - **流水分上限**：近7天有效流水维度最高可得分，默认100分。
    - **流水分段规则**：配置近7天有效流水与流水分之间的分段换算规则。
    - **生效阶段**：影子运行、小流量热度生效、全量热度生效。
+ **数据约束**：
    - 颜值权重、直播环境权重、近7天有效流水权重之和必须等于100%。
    - 热度换算比例必须大于0。
    - 热度计算评分上限必须在综合评分下限和综合评分上限之间。
    - 流水分不得超过流水分上限。
    - 配置变更后，下一次自动计算或下一次开播热度计算开始生效；历史记录不回算。

#### 2.1.3 主播评分管理

+ **功能描述**：运营查看和维护主播综合评分。
+ **列表字段**：
    - 主播ID
    - 主播昵称
    - 国家
    - 颜值分
    - 直播环境分
    - 近7天原始流水
    - 近7天有效流水
    - 流水分
    - 系统计算综合评分
    - 当前生效综合评分
    - 是否锁定评分
    - 锁定评分
    - 最近计算时间
    - 更新时间
+ **筛选条件**：
    - 主播ID
    - 国家
    - 当前生效综合评分区间
    - 是否锁定评分
    - 最近计算时间
+ **操作能力**：
    - 编辑颜值分。
    - 编辑直播环境分。
    - 设置锁定评分。
    - 锁定/解锁综合评分。
    - 查看评分计算明细。
+ **锁定规则**：
    - 运营可设置主播综合评分并开启锁定。
    - 锁定状态下，系统仍可计算该主播的系统综合评分并保留记录，但不覆盖当前生效综合评分。
    - 解锁后，下一次自动计算完成时，当前生效综合评分更新为系统计算综合评分。

#### 2.1.4 评分计算记录

+ **功能描述**：记录系统每日自动计算及运营人工调整产生的评分变更。
+ **列表字段**：
    - 记录ID
    - 主播ID

    - 是否锁定评分
    - 计算状态
    - 触发方式（系统自动、运营手动）
    - 创建时间
+ **筛选条件**：主播ID、计算日期、计算状态、触发方式、是否锁定评分。

## 3. 核心业务规则梳理

### 3.1 综合评分计算规则

+ **V1固定评分维度**：
    - 颜值分：由运营设置，0-100分。
    - 直播环境分：由运营设置，0-100分。
    - 近7天有效流水分：由系统根据近7天有效流水自动计算，0-100分。
+ **综合评分公式**：

```Plaintext
系统计算综合评分 =
颜值分 * 颜值权重
+ 直播环境分 * 直播环境权重
+ 流水分 * 近7天有效流水权重
```

+ **分数范围**：综合评分限制在0-100分之间。
+ **取整规则**：计算结果默认保留2位小数；列表展示可按产品要求取整。
+ **权重约束**：三个维度权重之和必须为100%。

### 3.2 近7天有效流水计算规则

+ **V1计算口径**：近7天有效流水基于当前平台已有可获取数据计算。
+ **有效流水定义**：有效流水指已支付成功、未退款、符合平台当前有效消费口径的直播间流水。
+ **V1剔除项**：
    - 已退款流水。
    - 已撤单流水。
    - 当前系统已明确标记为无效的流水。
+ **V1预留但不强依赖项**：
    - 风控用户消费剔除。
    - 主播关联账号消费剔除。
    - 异常充值/异常支付剔除。
    - 刷量、洗钱、套利等异常交易剔除。
+ **计算频率**：每天只计算一次。
+ **计算时间**：建议每日凌晨执行，计算截至前一日结束的近7天流水。
+ **异常处理**：流水数据缺失或计算失败时，保留上一日流水分并记录失败原因。

### 3.3 流水评分分段规则

+ **功能说明**：近7天有效流水通过分段函数换算为流水分，V1不使用简单线性换算。
+ **V1分段口径**：V1全平台共用一套固定流水分段，不按国家/地区区分；后续如平台收入结构差异明显，再进入V2动态分段。
+ **示例规则**：

| 近7天有效流水 | 流水分 |
| :--- | ---: |
| 0-999 | 0 |
| 1,000-4,999 | 20 |
| 5,000-9,999 | 40 |
| 10,000-29,999 | 60 |
| 30,000-99,999 | 80 |
| 100,000及以上 | 100 |

+ **配置要求**：
    - 仅配置每个分段的最低有效流水和对应流水分。
    - 系统按最低有效流水倒序匹配分段。
    - 流水分不得超过流水分上限。
    - 分段规则调整后，对下一次每日计算生效。

### 3.4 评分锁定规则

+ **未锁定主播**：每日自动计算完成后，当前生效综合评分更新为系统计算综合评分。
+ **锁定主播**：当前生效综合评分使用运营设置的锁定评分，不受系统自动计算影响。
+ **锁定示例**：运营设置主播A综合评分为90分并锁定，则主播A开播热度加成始终按90分计算，直到运营解锁或修改锁定评分。
+ **解锁后处理**：解锁后不立即重算，等待下一次系统自动计算后更新当前生效综合评分；如需立即生效，可由运营触发手动重算。

### 3.5 开播热度加成规则

+ **触发时机**：主播开播时触发。
+ **加成规则**：在原有热度计算结果基础上，增加 `参与热度计算评分 * 热度换算比例`。
+ **默认比例**：`1分 = 1000热度`。
+ **参与热度计算评分**：`min(当前生效综合评分, 热度计算评分上限)`。
+ **评分上限说明**：热度计算评分上限限制的是参与换算的评分，不直接限制最终热度值；例如当前生效综合评分90、热度计算评分上限80、热度换算比例1000，则本场综合评分加成热度为 `80 * 1000 = 80000`。
+ **避免重复叠加**：同一场直播仅在开播初始化热度时叠加一次综合评分热度；如原有热度机制存在周期刷新，需确保综合评分加成项不会被重复累计。
+ **排序影响**：综合评分热度叠加后，参与原有直播列表热度排序逻辑，不单独新增排序规则。

### 3.6 分阶段落地规则

+ **第一阶段：后台影子运行**
    - 仅在管理端计算和展示综合评分，不影响线上热度和风控。
    - 运行周期建议7-14天。
    - 观察评分分布、流水分异常、人工评分稳定性、锁定比例。
+ **第二阶段：小流量热度生效**
    - 仅对指定国家或主播白名单生效。
    - 接入开播热度加成，并启用热度计算评分上限。
    - 监控直播间曝光、流水、主播投诉、热度异常波动。
+ **第三阶段：全量热度生效**
    - 评分稳定后扩大到全部适用主播。
    - 继续保留热度计算评分上限、评分锁定、计算记录。
    - 风控因子不属于V1落地范围，仅作为后续规划。

## 4. 设计角色与环境配置

### 4.1 角色权限

+ **运营**：配置评分参数，维护颜值分、直播环境分，设置/锁定/解锁主播综合评分，查看评分记录。
+ **系统**：每日计算近7天有效流水及系统综合评分，在主播开播时计算综合评分热度加成。
+ **主播**：无直接配置权限，仅受综合评分影响直播间热度排序。

### 4.2 环境配置

+ **定时任务**：每日执行一次近7天有效流水统计及综合评分自动计算。
+ **热度服务**：开播热度计算服务需接入当前生效综合评分、热度换算比例、热度计算评分上限。
+ **流水数据服务**：需提供近7天原始流水、退款/撤单/无效流水等当前平台已具备的数据。
+ **灰度配置**：支持按国家、主播白名单控制综合评分热度加成是否生效。
+ **时间口径**：评分计算、近7天流水统计统一采用UTC+8。
+ **数据一致性**：评分计算结果、当前生效综合评分需保证可追溯。

## 6. 测试场景推演与预期数据

### 6.1 参数配置校验

+ **场景**：运营配置颜值权重40%、直播环境权重30%、近7天有效流水权重30%。
+ **预期**：配置保存成功，占比之和为100%。

### 6.2 参数配置异常

+ **场景**：运营配置颜值权重50%、直播环境权重30%、近7天有效流水权重30%。
+ **预期**：配置保存失败，提示三个维度权重之和必须等于100%。

### 6.3 自动综合评分计算

+ **场景**：主播A颜值分90、直播环境分80、流水分70，占比分别为40%、30%、30%。
+ **预期**：系统计算综合评分为 `90*40% + 80*30% + 70*30% = 81`。

### 6.4 锁定评分不被覆盖

+ **场景**：运营设置主播A锁定评分为90分，系统自动计算分为81分。
+ **预期**：系统计算记录保留81分，但主播当前生效综合评分仍为90分。

### 6.5 解锁后自动更新

+ **场景**：主播A原锁定90分，运营解锁后下一次系统自动计算分为82分。
+ **预期**：主播当前生效综合评分更新为82分。

### 6.6 V1有效流水剔除

+ **场景**：主播A近7天原始流水为100000，其中退款10000、撤单5000、已标记无效流水5000。
+ **预期**：近7天有效流水为80000，被剔除流水金额为20000。

### 6.7 流水分段换算

+ **场景**：配置近7天有效流水30000及以上对应流水分80，主播A近7天有效流水为80000。
+ **预期**：主播A流水分为80。

### 6.8 流水分上限

+ **场景**：流水分上限配置为100，主播A近7天有效流水超过最高分段。
+ **预期**：流水分最高为100，不继续增加。

### 6.9 第一阶段影子运行

+ **场景**：系统处于后台影子运行阶段，主播A综合评分90。
+ **预期**：后台生成评分和计算记录，但不影响线上直播列表热度排序。

### 6.10 第二阶段小流量热度生效

+ **场景**：主播A在灰度白名单内，综合评分90，热度比例1000，热度计算评分上限80。
+ **预期**：参与热度计算评分为80，实际加成热度为80000，并参与直播列表热度排序。

### 6.11 避免重复叠加

+ **场景**：主播A同一场直播已叠加一次综合评分热度。
+ **预期**：后续热度刷新不重复叠加综合评分热度。

## 8. 后续版本规划

### 8.1 V2能力规划

+ **动态评分维度**：支持新增直播间类型、账号可信度、违规率、举报率、开播稳定性等维度。
+ **有效流水增强**：接入风控用户、主播关联账号、异常充值、异常支付、自刷识别等更完整的剔除能力。
+ **流水动态分段**：在固定分段稳定后，可基于平台周期流水中位数/分位数生成动态分段，用于适配平台收入变化。
+ **评分版本管理**：保存配置版本、评分规则版本，支持历史评分按版本追溯。
+ **主播评分解释**：支持查看评分变化原因、维度贡献、扣分项和运营调整记录。
+ **更细粒度灰度**：支持按国家、主播等级、主播白名单、直播间类型控制热度加成生效范围。

#### 8.1.1 流水中位数动态分段说明

+ **适用范围**：该能力属于V2规划，V1仍使用固定流水分段，不按国家/地区区分。
+ **统计对象**：以一个统计周期内参与评分的主播为样本，先计算每个主播该周期的有效流水。周期可按天或近7天配置，建议优先使用近7天有效流水，避免单日波动过大。
+ **中位数定义**：将所有主播的有效流水按从低到高排序后，位于中间位置的值即为中位数。
+ **奇数样本计算**：如果样本数为奇数，例如999个主播，则取第 `(999 + 1) / 2 = 500` 个主播的有效流水作为中位数。
+ **偶数样本计算**：如果样本数为偶数，例如1000个主播，则取第500个和第501个主播有效流水的平均值作为中位数，即 `(第500个主播有效流水 + 第501个主播有效流水) / 2`。
+ **分段方式示例**：以中位数作为基准值，按主播有效流水与中位数的倍数关系换算流水分，例如低于0.5倍中位数为20分，达到0.5倍为40分，达到1倍为60分，达到2倍为80分，达到5倍为100分。
+ **兜底规则**：当参与计算主播数过少、周期流水异常、数据缺失或中位数为0时，不启用动态分段，继续使用V1固定分段。

### 8.2 V3能力规划

+ **综合评分风控因子**：将当前生效综合评分作为涉黄、挂播、直播对比等现有风控策略的辅助因子。
+ **推荐排序因子**：在推荐排序中将综合评分作为质量因子之一，而不仅限于开播热度加成。
+ **自动化质量评分**：探索基于直播画面、声音、互动、留存等数据的自动评分能力。
+ **主播侧透明化**：在适合时机向主播展示部分评分权益、等级说明或优化建议。
+ **策略闭环评估**：持续观察评分对曝光、流水、投诉、违规、主播留存的影响，反向调整评分权重和热度比例。
