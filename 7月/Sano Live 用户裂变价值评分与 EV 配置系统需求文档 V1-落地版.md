# Sano Live 用户裂变价值评分与 EV 配置系统需求文档 V1（落地版）

## 1. 背景与目标

### 1.1 项目背景

平台当前已具备用户邀请关系归因能力，可以查询谁邀请了谁；邀请关系绑定成功后不可修改。平台计划基于受邀用户注册后30天内的真实活跃、付费、平台净贡献及风险情况，评估邀请人的裂变经营价值，并将评分用于运营分析、活动资格、确定性权益和后续EV策略。

当前原始方案已明确评分方向，但缺少成熟样本、有效用户、平台净贡献、风险剔除、评分分段、权益生效和异常处理规则。本版本以当前可落地能力为前提，先完成可解释、可追溯、可灰度的V1闭环。

### 1.2 V1核心目标

- 建立受邀用户注册后30天价值结果，形成统一的成熟样本。
- 每日计算邀请人裂变价值评分和等级。
- 区分正常经营、低价值拉新、疑似奖励型拉新和确认刷奖/套利。
- 风险识别先于价值评分，确认异常用户不参与有效人数、付费率和净贡献计算。
- 为主播、工会、代理及普通邀请用户提供统一的裂变经营能力评价依据。
- 支持活动资格、确定性奖励额度、审核优先级等权益配置。
- 支持影子运行、灰度生效、配置版本、计算记录和操作审计。

### 1.3 V1不做范围

- 不修改现有邀请关系绑定流程。
- 不支持邀请关系人工改绑；风险关系只允许标记为不参与评分，不修改原始关系。
- 不计算二级、三级等间接邀请价值。
- 不将裂变评分直接纳入主播综合评分或直播间热度。
- 不根据用户等级秘密修改同一Luck Gift或Game玩法的底层中奖概率、开奖结果或实际返奖率。
- 不在一局游戏或一次随机活动进行过程中切换权益或EV配置。

## 2. 核心定义

### 2.1 直接邀请关系

- 用户A直接邀请用户B，则B的30天价值归属于A。
- 用户B继续邀请用户C，则C的价值只归属于B，不重复归属于A。
- 邀请关系绑定成功后不可修改。
- 因作弊、账号注销等原因需要排除时，仅修改该关系的评分有效状态，不修改邀请人ID。

### 2.2 受邀用户30天观察周期

- 观察开始时间：受邀用户注册成功时间。
- 观察结束时间：注册成功时间加30个自然日。
- 时间口径：统一使用UTC+8。
- 观察期内统计有效活跃、付费、消费、退款、返奖、平台成本、净贡献和风险信号。
- 注册未满30天的用户为“观察中样本”，仅展示预估数据，不参与正式裂变评分和正式权益等级计算。
- 注册满30天且完成数据结算的用户为“成熟样本”。

### 2.3 邀请人评分样本周期

受邀用户30天观察周期和邀请人评分样本周期是两个不同概念：

- 受邀用户观察周期：固定为注册后30天。
- 邀请人评分样本周期：统计最近一段时间内完成30天观察的成熟样本，默认30天，支持配置为60天或90天。

示例：8月31日计算邀请人评分，样本周期配置为30天，则统计8月2日至8月31日期间完成30天观察的受邀用户价值结果。

### 2.4 有效受邀用户

同时满足以下条件的成熟样本计为有效受邀用户：

- 邀请关系有效且为一级直接邀请。
- 账号注册成功，未被确认注销或封禁为作弊账号。
- 30天内至少存在2个有效活跃日，活跃日阈值支持配置。
- 未命中配置为“直接排除”的强风险规则。
- 未处于高风险待复核状态。

有效活跃日默认定义为：用户当天登录，并产生累计不少于10分钟的有效使用行为。有效使用行为包括观看直播、有效互动、正常消费、内容浏览等；纯后台在线、机器人行为和已确认异常行为不计入。

### 2.5 有效付费用户

- 有效受邀用户在观察期内存在至少一笔支付成功、未退款、未撤单、未拒付的有效充值或消费。
- 由邀请人、关联账号或异常资金提供的消费，在风险确认后不计为有效付费。
- 是否付费只计人数，不按交易次数重复计算。

### 2.6 平台净贡献

单个受邀用户30天平台净贡献按以下口径计算：

```text
平台净贡献 =
有效消费金额
- 主播分成
- 用户返奖及派奖
- 工会、代理及渠道佣金
- 邀请奖励
- 活动补贴
- 支付通道成本
- 退款、拒付及撤单金额
- 其他可归属的直接成本
```

- 普通礼物、Luck Gift、Game及其他消费类型分别按各自结算口径计算后汇总。
- 平台净贡献允许为负数。
- 无法取得完整成本的数据不得直接以消费流水替代净贡献；应标记数据不完整，并按异常规则处理。

### 2.7 评分状态

| 状态 | 说明 |
|---|---|
| OBSERVING | 存在观察中用户，尚未形成成熟样本 |
| INSUFFICIENT | 成熟有效样本不足，不生成正式等级 |
| EFFECTIVE | 正式评分已生成并生效 |
| REVIEWING | 命中高风险，评分及增强权益暂停生效 |
| INVALID | 确认作弊或数据失效，不提供裂变权益 |
| CALCULATE_FAILED | 当次计算失败，按异常兜底规则处理 |

## 3. 角色与权限

### 3.1 运营

- 查看邀请关系、受邀用户30天价值和邀请人评分。
- 配置评分样本周期、最低样本量、评分分段和等级区间。
- 配置风险信号阈值、风险分、是否可独立判定及处置动作。
- 配置各裂变等级对应的确定性权益。
- 发起人工复核、确认风险、解除风险或重新计算。

### 3.2 风控

- 查看设备、IP、实名、支付、提现、资金流和行为协同证据。
- 处理高风险邀请人及受邀用户。
- 配置强风险规则是否可以直接执行处置。
- 对人工结论填写原因并保留操作记录。

### 3.3 财务或结算

- 维护平台净贡献的收入、分成、返奖、佣金、成本和退款口径。
- 核对不同业务类型的净贡献计算结果。
- 查看权益预算、实际发放和成本偏差。

### 3.4 主播、工会、代理

V1默认仅展示汇总经营数据，不展示底层风控规则和其他用户敏感信息。可查看内容由权限配置控制，包括：

- 直接邀请人数。
- 观察中人数、成熟人数和有效人数。
- 付费用户数、付费率。
- 裂变等级及当前权益。
- 无敏感信息的评分提升建议。

## 4. 核心业务流程

```text
邀请关系绑定成功且不可修改
        ↓
受邀用户进入30天观察期
        ↓
采集活跃、付费、净贡献和风险数据
        ↓
注册满30天后生成受邀用户价值结果
        ↓
风险规则判断是否纳入有效样本
        ↓
每日汇总邀请人的成熟样本
        ↓
计算裂变价值评分及等级
        ↓
影子运行或匹配确定性权益配置
        ↓
保留计算记录、权益应用记录和风险证据
```

## 5. 裂变价值评分规则

### 5.1 评分前置条件

- 只统计一级直接邀请的成熟样本。
- 默认统计最近30天内完成观察的成熟样本，样本周期支持配置。
- 正式评分最低有效成熟样本数默认10人，支持配置。
- 有效成熟样本不足时，评分状态为`INSUFFICIENT`，使用平台基础权益，不评为S/A/B/C级。
- 确认异常用户从有效人数、付费人数、付费率、净贡献和用户质量中全部剔除。
- 疑似风险待复核用户暂不纳入正式评分，复核完成后在下一次计算中补入或永久排除。

### 5.2 评分结构

裂变价值总分为100分，V1固定使用四个维度：

| 维度 | 权重/最高分 | 说明 |
|---|---:|---|
| 有效邀请人数 | 20分 | 评价有效拉新规模 |
| 邀请用户付费率 | 30分 | 评价受邀用户付费转化 |
| 邀请用户平台净贡献 | 30分 | 评价受邀用户为平台产生的实际净价值 |
| 邀请用户质量 | 20分 | 评价受邀用户留存和活跃质量 |

风险不作为可以被其他高分抵消的普通维度。风险先执行剔除、暂停或失效，再计算剩余有效样本的价值分。

### 5.3 有效邀请人数分

初始默认分段如下，支持后台配置：

| 成熟有效邀请人数 | 得分 |
|---:|---:|
| 0～9 | 样本不足，不生成正式评分 |
| 10～19 | 5 |
| 20～39 | 10 |
| 40～79 | 15 |
| 80及以上 | 20 |

系统仅配置每个分段的最低人数和对应分数，按最低人数从高到低匹配，避免配置真空区间。

### 5.4 邀请用户付费率分

```text
邀请用户付费率 =
有效付费用户数 ÷ 成熟有效邀请用户数 × 100%
```

初始默认分段如下，支持后台配置：

| 付费率 | 得分 |
|---:|---:|
| 低于2% | 0 |
| 不低于2% | 6 |
| 不低于5% | 12 |
| 不低于10% | 18 |
| 不低于20% | 24 |
| 不低于30% | 30 |

- 退款、拒付后不存在任何有效付费的用户不计为有效付费用户。
- 同一用户发生多次付费只计1个付费用户，但全部有效净贡献参与净贡献分计算。
- 付费率分段应在影子运行后根据平台真实分布校准。

### 5.5 邀请用户平台净贡献分

```text
邀请用户平台净贡献 =
评分样本周期内全部有效成熟受邀用户的30天平台净贡献之和
```

- 使用固定分段换算为0～30分，不使用简单线性换算。
- 分段只配置“最低净贡献金额”和“对应分数”，按最低金额倒序匹配。
- 投产前使用至少60天历史数据计算邀请人净贡献分布，参考P50、P70、P85、P95形成首版固定分段；分段形成后不随每日数据自动变化。
- 净贡献小于或等于0时默认得0分。
- 配置变更只影响下一次计算，历史评分不回算。

建议首版分值结构：

| 净贡献门槛 | 得分 |
|---|---:|
| 0 | 0 |
| 历史P50对应金额 | 6 |
| 历史P70对应金额 | 12 |
| 历史P85对应金额 | 18 |
| 历史P95对应金额 | 24 |
| 运营配置的最高门槛 | 30 |

### 5.6 邀请用户质量分

邀请用户质量分由7日留存率和30天有效活跃天数构成，各10分。

```text
7日留存率 =
注册第7个自然日存在有效活跃的成熟有效用户数
÷ 成熟有效邀请用户数
```

7日留存率初始分段：

| 7日留存率 | 得分 |
|---:|---:|
| 低于5% | 0 |
| 不低于5% | 2 |
| 不低于10% | 4 |
| 不低于20% | 6 |
| 不低于30% | 8 |
| 不低于40% | 10 |

```text
人均30天有效活跃天数 =
成熟有效用户的有效活跃天数之和
÷ 成熟有效邀请用户数
```

人均有效活跃天数初始分段：

| 人均有效活跃天数 | 得分 |
|---:|---:|
| 低于2天 | 0 |
| 不低于2天 | 2 |
| 不低于4天 | 4 |
| 不低于7天 | 6 |
| 不低于10天 | 8 |
| 不低于15天 | 10 |

### 5.7 总分公式与等级

```text
裂变价值总分 =
有效邀请人数分
+ 邀请用户付费率分
+ 邀请用户平台净贡献分
+ 邀请用户质量分
```

- 总分范围为0～100分。
- 计算结果保留2位小数，等级按最终分数判断。
- 正式评分每天计算一次，默认有效24小时。

| 等级 | 分数 | 说明 |
|---|---:|---|
| S | 90～100 | 高价值裂变用户 |
| A | 70～89.99 | 重点经营用户 |
| B | 40～69.99 | 正常裂变用户 |
| C | 0～39.99 | 低价值裂变用户 |
| N | 无正式评分 | 样本不足或尚在观察期 |
| R | 风险状态 | 评分及增强权益暂停或失效 |

## 6. 邀请风险识别设计

### 6.1 风险设计原则

- 低付费、低留存和低净贡献属于低价值，不直接定义为作弊。
- 同IP、相同地区、相同设备型号等弱关联不能单独判定作弊。
- 风险识别应同时考虑账号关联、资金关联、行为协同和奖励套利闭环。
- 高价值和高利润不能抵消确认作弊风险。
- 所有风险结论必须保留命中规则、证据数据、处理动作和操作人。

### 6.2 风险信号初始规则

以下为V1初始建议，阈值、风险分、是否可单独判定和处理动作均支持配置：

| 风险信号 | 初始风险分 | 初始等级 | 是否可单独确认 |
|---|---:|---|---|
| 同IP一小时内集中注册不少于5个受邀账号 | 10 | 弱 | 否 |
| 同一设备注册不少于2个受邀账号 | 30 | 中 | 否 |
| 邀请人与受邀用户使用同一设备且存在付费行为 | 50 | 中 | 否，需结合资金或行为证据 |
| 不少于3个受邀用户共用同一支付账户 | 35 | 中 | 否 |
| 多个账号使用同一提现账户 | 80 | 强 | 支持配置 |
| 邀请人与受邀用户存在资金提供、消费、返还闭环 | 80 | 强 | 支持配置 |
| 命中批量模拟器、改机或自动化注册 | 80 | 强 | 支持配置 |
| 退款、拒付金额占有效支付达到30% | 40 | 中 | 否 |
| 不少于80%的用户只完成奖励最低动作且7日留存低于5% | 20 | 中 | 否 |
| 经人工或既有风控确认自充、自送、自领邀请奖励 | 100 | 强 | 是 |

### 6.3 风险等级

| 风险分/命中情况 | 风险等级 | 默认处理 |
|---|---|---|
| 0～29 | 正常 | 正常参与评分和权益 |
| 30～49 | 观察 | 数据参与评分，增强权益延迟至下一次复核 |
| 50～69 | 疑似 | 涉及用户暂不纳入正式评分，奖励待发 |
| 70～89 | 高风险 | 邀请人评分暂停生效，使用基础权益并进入复核 |
| 90～100或确认强命中 | 确认风险 | 相关数据失效，取消未发权益并执行配置的原有风控流程 |

- 强命中是否直接执行原有流程必须支持配置，不能在代码中固定。
- 人工复核可以确认风险、解除风险或维持观察，并必须填写原因。

### 6.4 受邀用户与邀请人分层处理

- 单个受邀用户异常：优先剔除该用户，不直接否定邀请人的全部样本。
- 邀请人风险需同时考虑异常人数和异常占比，避免小样本误判。

邀请人聚合风险初始规则：

| 条件 | 默认处理 |
|---|---|
| 异常用户少于3人且占比低于10% | 仅剔除异常用户 |
| 异常用户不少于3人且占比达到20% | 邀请人进入观察状态 |
| 异常用户不少于5人且占比达到30% | 暂停邀请人评分及增强权益 |
| 命中资金闭环、同提现账户等强证据 | 按强命中配置执行复核或处置 |

### 6.5 风险解除与数据补算

- 疑似用户复核正常后，在下一次每日任务中补入评分。
- 已确认异常后又解除风险的，需要保留原风险记录，并由运营或风控触发补算。
- 评分补算必须记录原评分、新评分、补算原因和规则版本。

## 7. EV及权益配置设计

### 7.1 V1定位

V1中的EV配置定位为“裂变等级权益策略配置”，不直接改变同一Luck Gift或Game玩法的隐藏中奖概率。基础玩法概率、基础EV和开奖逻辑由原业务系统统一管理。

裂变等级可以影响：

- 是否具有指定活动参与资格。
- 确定性邀请奖励额度。
- 每日或每期参与次数上限。
- 固定赠送金币、优惠券或任务奖励。
- 专属活动入口。
- 人工审核优先级。
- 主播、工会、代理的运营扶持额度。

### 7.2 默认权益策略

| 等级/状态 | 默认权益 |
|---|---|
| S | 高级活动资格、较高确定性奖励额度、优先审核 |
| A | 增强活动资格、标准增强奖励额度 |
| B | 标准活动资格和基础奖励 |
| C | 基础活动资格，不提供增强奖励 |
| N | 使用平台基础配置，不因样本不足降级 |
| R | 暂停增强权益，按风险配置决定是否保留基础权益 |

具体金额、次数和预算不在评分规则中硬编码，由权益策略配置管理。

### 7.3 权益生效规则

- 评分等级更新后，在下一权益周期生效，默认次日生效。
- 用户已进入的活动、已开始的游戏局或已购买的随机产品不在过程中切换配置。
- 已满足发放条件且已发放的确定性权益原则上不自动追回；确认作弊时按平台现有奖励追回规则执行。
- 配置必须包含国家/地区、业务类型、适用等级、生效时间、失效时间、预算上限和版本号。
- 配置修改需经过创建、复核、发布流程，创建人与复核人不得为同一人。
- 达到单日预算、活动预算或异常成本阈值时自动停止增强权益并告警。

### 7.4 后续真实EV能力前置条件

V2如需支持不同用户群组的真实EV或随机概率配置，必须同时满足：

- 完成目标国家/地区的法务及应用商店合规评估。
- 在用户参与前明确披露概率或选择方式。
- 按活动和配置版本隔离奖池，不在单局过程中动态变化。
- 配置理论EV、实际EV、单用户成本、单日预算和总预算上限。
- 支持双人复核、灰度、实时监控、自动熔断和一键回滚。
- 保存用户实际命中配置版本、开奖输入、开奖结果和成本记录。
- 评分模型和EV策略之间设置上限，避免形成“高权益促进流水、流水继续提高评分”的无限正反馈。

### 8.7 权益策略配置

- 配置国家/地区、业务类型、等级、权益类型和权益值。
- 配置单用户、单日、单活动预算上限。
- 配置生效时间、失效时间和灰度范围。
- 支持创建、复核、发布、停用和回滚。
- 展示实际发放人数、发放成本和预算使用率。

## 10. 定时任务与异常处理

### 10.1 定时任务

建议每日按以下顺序执行：

1. `02:00`：完成前一日已到观察结束时间的受邀用户30天价值结算。
2. `02:30`：执行成熟样本风险规则，生成或更新风险结果。
3. `03:00`：按邀请人汇总成熟有效样本并计算正式评分。
4. `03:30`：根据生效阶段计算下一权益周期的等级策略。
5. `04:00`：生成数据质量、评分异常和预算监控报表。

### 10.2 幂等与重复执行

- 受邀用户ID和计算版本形成唯一约束，同一版本不得重复生成成熟结果。
- 邀请人ID、评分日期和配置版本形成唯一约束，同一日自动任务不得重复生成记录。
- 任务重试只能覆盖失败或未完成记录，不重复发放权益。

### 10.3 数据缺失

- 活跃、支付、成本或风险数据缺失时，受邀用户标记为数据异常，暂不进入正式评分。
- 当日邀请人评分任务失败时，保留上一日有效评分并告警。
- 连续失败超过72小时后，增强权益自动降为平台基础配置，恢复计算后次日重新生效。

### 10.4 退款和迟到数据

- 观察期结束后发生退款、拒付或风险确认时，更新受邀用户价值结果并触发邀请人补算。
- 补算不修改原评分记录，新增一条补算记录并标记关联的原记录。
- 已发权益是否追回按平台原有奖励追回规则执行，评分系统只提供失效金额和原因。

## 11. 分阶段落地

### 11.1 第一阶段：数据回溯与影子运行

- 回溯至少60～90天邀请关系和受邀用户行为数据。
- 生成30天成熟样本和裂变评分，但不影响线上权益。
- 运行不少于30天。
- 观察评分分布、样本不足率、风险命中率、净贡献分布和任务成功率。

### 11.2 第二阶段：确定性权益灰度

- 仅对指定国家、活动或白名单用户生效。
- 优先接入活动资格、固定奖励额度、参与次数和审核优先级。
- 灰度流量建议从5%～10%开始。
- 保留对照组，比较有效邀请、留存、净贡献、奖励成本和风险率。

### 11.3 第三阶段：全量确定性权益

- 评分和风险规则稳定后扩大生效范围。
- 继续保留预算上限、灰度开关、自动熔断和配置回滚。
- 每月复核评分分段和等级分布，不进行无版本的临时修改。

### 11.4 后续EV能力

- 真实EV、随机概率或奖池差异化作为独立V2项目评审。
- 未完成合规、披露、预算、审计、熔断和回滚前，不进入开发上线阶段。

## 12. 核心监控指标

### 12.1 数据质量

- 邀请关系归因成功率。
- 观察期成熟任务成功率。
- 活跃、支付、成本和风险数据完整率。
- 每日评分任务成功率和执行耗时。

### 12.2 业务效果

- 有效邀请人数及有效率。
- 受邀用户7日留存率、人均活跃天数。
- 受邀用户付费率和平台净贡献。
- 各等级人数、等级迁移和样本不足率。
- 单个有效邀请用户的平均奖励成本。

### 12.3 风险与成本护栏

- 异常受邀用户数量及占比。
- 邀请人观察、高风险和确认风险数量。
- 退款、拒付、异常提现金额。
- 权益预算使用率和超预算次数。
- 用户投诉、申诉和误判解除率。

## 13. 测试场景与验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| TC-REL-01 | A邀请B，绑定后尝试改为C邀请B | 关系不可修改，保留原邀请人A |
| TC-REL-02 | A邀请B，B邀请C | B价值归A，C价值只归B |
| TC-SAMPLE-01 | 受邀用户注册未满30天 | 状态为观察中，不参与正式评分 |
| TC-SAMPLE-02 | 受邀用户注册满30天且数据完整 | 生成唯一成熟价值结果 |
| TC-SAMPLE-03 | 邀请人成熟有效用户少于最低样本量 | 等级为N，使用基础权益 |
| TC-VALUE-01 | 用户存在退款和拒付 | 从有效支付和平台净贡献中扣除 |
| TC-VALUE-02 | Luck Gift消费高但返奖成本高 | 按净贡献计算，不按消费流水直接评分 |
| TC-SCORE-01 | 邀请人四维度分分别为15、24、18、16 | 总分73，等级为A |
| TC-SCORE-02 | 评分分段配置变更 | 下一次计算使用新版本，历史记录不回算 |
| TC-RISK-01 | 多个用户仅命中同IP | 不单独判定作弊，记录弱风险信号 |
| TC-RISK-02 | 单个受邀用户确认异常 | 只剔除该用户并补算邀请人评分 |
| TC-RISK-03 | 邀请人命中资金闭环强风险 | 按配置进入复核或确认风险，不由代码固定动作 |
| TC-RISK-04 | 疑似用户复核正常 | 下一次任务补入评分并保留复核记录 |
| TC-RIGHT-01 | 用户等级由B升级为A | 下一权益周期使用A等级策略，不影响进行中的活动 |
| TC-RIGHT-02 | 用户等级为R | 暂停增强权益，按策略使用基础权益或限制权益 |
| TC-RIGHT-03 | 权益预算达到上限 | 自动停止增强权益并告警，不继续超额发放 |
| TC-TASK-01 | 每日评分任务重复执行 | 不重复生成评分记录，不重复发放权益 |
| TC-TASK-02 | 连续72小时计算失败 | 增强权益降为基础配置并产生告警 |

V1验收标准：

- 邀请关系查询与现有数据一致，绑定关系不可被评分系统修改。
- 受邀用户30天价值结果可按原始数据复算，金额和人数口径一致。
- 同一配置版本下，相同输入得到相同评分和等级。
- 所有被排除样本均可查看排除原因和风险证据。
- 正式评分、补算、人工复核和权益应用均有完整记录。
- 影子运行期间任务成功率、数据完整率达到平台设定上线标准。
- 灰度权益未超过单用户、单日及活动预算上限。

## 14. V2/V3规划

### 14.1 V2

- 支持按国家、渠道、主播、工会分别配置评分分段。
- 增加小样本平滑、长期趋势分和等级升降保护期。
- 增加设备、支付、提现和资金关系图谱识别。
- 支持邀请人、主播、工会多角色经营价值看板，但仍避免同一价值重复归因。
- 在满足合规和审计前提后，评估群组级EV策略。

### 14.2 V3

- 建立增量价值模型，区分自然注册用户和邀请真正带来的新增价值。
- 基于对照实验评估邀请权益的增量留存、增量净贡献和边际成本。
- 建立评分、权益、风险和预算的自动化策略闭环。
- 将裂变经营分作为主播、工会运营评估的独立因子，不直接混入直播内容质量评分。
