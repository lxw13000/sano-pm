## 1. 背景与目标

### 1.1 项目背景

为提升主播推荐、直播间热度计算及运营分层管理的精细化能力，平台计划新增“主播综合评分评估系统”。系统通过颜值、直播环境、近7天流水等维度对主播进行综合评估，并将综合评分按配置比例换算为直播间热度，在主播开播时叠加到原有热度计算中。

该系统同时支持运营人工干预。对于重点主播，运营可在主播表中设置固定综合评分并锁定，锁定后该主播不再受系统自动评估影响。

### 1.2 核心目标

+ **管理端**：新增主播综合评估模块，支持评分参数配置、主播评分查看、人工设置评分、锁定评分、评分计算记录查询。
+ **评分体系**：综合评分由颜值、直播环境、近7天流水按配置占比计算得出。
+ **运营干预**：支持主播综合评分人工设置及锁定，锁定后系统自动评估不覆盖人工评分。
+ **热度加成**：主播开播时，在原有直播间热度计算基础上，增加 `主播综合评分 * 热度比例` 得到的热度值。
+ **数据稳定性**：近7天流水由系统每天计算一次，评分计算需保留记录，便于运营追溯。

## 2. 功能设计

### 2.1 管理端功能设计

#### 2.1.1 主播综合评估功能模块

+ **功能描述**：管理端新增“主播综合评估”一级功能模块，集中管理综合评分配置、主播评分、评分锁定及计算记录。
+ **模块入口**：管理端左侧菜单新增“主播综合评估”。
+ **子功能块**：
    - **评分参数配置**：配置热度换算比例、评分维度占比、流水评分规则等参数。
    - **主播评分管理**：查看主播综合评分，维护颜值分、直播环境分，设置人工评分及锁定状态。
    - **评分计算记录**：查看每日自动计算结果及评分变更明细。
    - **热度加成记录**：查看主播开播时综合评分对直播间热度的加成情况。
+ **基础能力**：
    - 支持按主播ID、国家、评分区间、锁定状态、计算状态筛选。
    - 支持查看评分详情、编辑运营评分项、锁定/解锁综合评分。
    - 所有人工操作需记录操作人、操作时间、操作前后值及操作原因。

#### 2.1.2 评分参数配置

+ **功能描述**：配置主播综合评分计算所需参数。
+ **配置项**：
    - **热度换算比例**：默认 `1分 = 1000热度`，支持运营配置。
    - **评分维度配置**：默认包含颜值、直播环境、近7天流水，后续支持新增直播间类型等其他评分维度。
    - **维度权重配置**：每个评分维度均可配置权重占比。
    - **流水评分规则**：配置近7天流水与流水分之间的换算规则。
    - **综合评分上限**：默认100分。
    - **综合评分下限**：默认0分。
+ **数据约束**：
    - 所有启用状态的评分维度权重占比之和必须等于100%。
    - 默认启用维度为颜值、直播环境、近7天流水；新增直播间类型等维度后，同样参与权重合计校验。
    - 热度换算比例必须大于0。
    - 配置变更后，下一次自动计算开始生效；已生成的历史评分记录不回算。

#### 2.1.3 主播评分管理

+ **功能描述**：运营查看和维护主播综合评分。
+ **列表字段**：
    - 主播ID
    - 主播昵称
    - 国家
    - 颜值分
    - 直播环境分
    - 近7天流水
    - 流水分
    - 系统计算综合评分
    - 当前生效综合评分
    - 是否锁定评分
    - 锁定评分
    - 最近计算时间
    - 更新时间
+ **筛选条件**：
    - 主播ID
    - 国家
    - 当前生效综合评分区间
    - 是否锁定评分
    - 最近计算时间
+ **操作能力**：
    - 编辑颜值分。
    - 编辑直播环境分。
    - 设置人工综合评分。
    - 锁定/解锁综合评分。
    - 查看评分计算明细。
+ **锁定规则**：
    - 运营可设置主播综合评分并开启锁定。
    - 例如运营设置主播综合评分为90分且锁定，则该主播当前生效综合评分固定为90分。
    - 锁定状态下，系统仍可计算该主播的系统综合评分并保留记录，但不覆盖当前生效综合评分。
    - 解锁后，下一次自动计算完成时，当前生效综合评分更新为系统计算综合评分。

#### 2.1.4 评分计算记录

+ **功能描述**：记录系统每日自动计算及运营人工调整产生的评分变更。
+ **列表字段**：
    - 记录ID
    - 主播ID
    - 计算日期
    - 颜值分
    - 直播环境分
    - 近7天流水
    - 流水分
    - 系统计算综合评分
    - 当前生效综合评分
    - 是否锁定评分
    - 计算状态
    - 触发方式（系统自动、运营手动）
    - 创建时间
+ **筛选条件**：主播ID、计算日期、计算状态、触发方式、是否锁定评分。

#### 2.1.5 热度加成记录

+ **功能描述**：记录主播开播时因综合评分产生的热度加成，便于排查直播间热度变化。
+ **列表字段**：
    - 记录ID
    - 主播ID
    - 直播间ID
    - 开播时间
    - 原有热度
    - 当前生效综合评分
    - 热度换算比例
    - 综合评分加成热度
    - 最终初始热度
    - 创建时间
+ **计算公式**：

```Plaintext
综合评分加成热度 = 当前生效综合评分 * 热度换算比例
最终初始热度 = 原有热度 + 综合评分加成热度
```

## 3. 核心业务规则梳理

### 3.1 综合评分计算规则

+ **评分维度**：
    - 颜值分：由运营设置。
    - 直播环境分：由运营设置。
    - 近7天流水分：由系统根据主播近7天流水自动计算。
    - 可扩展维度：后续可增加直播间类型等评分维度，维度来源可配置为运营设置或系统计算。
+ **综合评分公式**：

```Plaintext
系统计算综合评分 =
SUM(启用维度分 * 对应维度权重)

默认维度示例：
颜值分 * 颜值权重
+ 直播环境分 * 直播环境权重
+ 流水分 * 近7天流水权重
```

+ **分数范围**：综合评分默认限制在0-100分之间。
+ **取整规则**：如计算结果存在小数，默认保留2位小数；展示时可按产品要求取整或保留小数。
+ **配置约束**：所有启用维度权重占比之和必须为100%。

### 3.2 近7天流水计算规则

+ **计算口径**：统计主播最近7天直播间有效流水。
+ **计算频率**：系统每天只计算一次。
+ **计算时间**：建议每日凌晨执行，计算截至前一日结束的近7天流水。
+ **流水分换算**：根据管理端配置的流水评分规则，将近7天流水换算为流水分。
+ **异常处理**：流水数据缺失或计算失败时，保留上一日流水分并记录失败原因。

### 3.3 评分锁定规则

+ **未锁定主播**：每日自动计算完成后，当前生效综合评分更新为系统计算综合评分。
+ **锁定主播**：当前生效综合评分使用运营设置的锁定评分，不受系统自动评估影响。
+ **锁定示例**：运营设置主播A综合评分为90分并锁定，则主播A开播热度加成始终按90分计算，直到运营解锁或修改锁定评分。
+ **解锁后处理**：解锁后不立即重算，等待下一次系统自动计算后更新当前生效综合评分；如需立即生效，可由运营触发手动重算。

### 3.4 开播热度加成规则

+ **触发时机**：主播开播时触发。
+ **加成规则**：在原有热度计算结果基础上，增加 `当前生效综合评分 * 热度换算比例`。
+ **默认比例**：`1分 = 1000热度`。
+ **比例配置**：热度换算比例可在管理端配置。
+ **避免重复叠加**：同一场直播仅在开播初始化热度时叠加一次综合评分热度；如原有热度机制存在周期刷新，需确保综合评分加成项不会被重复累计。

### 3.5 参数配置生效规则

+ **权重配置**：修改评分维度或维度权重后，对下一次评分计算生效。
+ **热度比例配置**：修改后对下一次开播热度计算生效。
+ **历史记录**：配置变更不影响已生成的评分计算记录和已产生的开播热度加成记录。
+ **操作日志**：参数配置变更需记录操作人、操作时间、变更前后值及变更原因。

## 4. 设计角色与环境配置

### 4.1 角色权限

+ **运营**：配置评分参数，维护颜值分、直播环境分，设置/锁定/解锁主播综合评分，查看评分记录和热度加成记录。
+ **系统**：每日计算近7天流水及系统综合评分，在主播开播时计算综合评分热度加成。
+ **主播**：无直接配置权限，仅受综合评分影响直播间热度。

### 4.2 环境配置

+ **定时任务**：每日执行一次近7天流水统计及综合评分自动计算。
+ **热度服务**：开播热度计算服务需接入当前生效综合评分及热度换算比例。
+ **时间口径**：评分计算、近7天流水统计、开播热度加成记录统一采用UTC+8。
+ **数据一致性**：评分计算结果、当前生效综合评分、热度加成记录需保证可追溯。

## 6. 测试场景推演与预期数据

### 6.1 参数配置校验

+ **场景**：运营配置颜值权重40%、直播环境权重30%、近7天流水权重30%。
+ **预期**：配置保存成功，占比之和为100%。

### 6.2 参数配置异常

+ **场景**：运营配置颜值权重50%、直播环境权重30%、近7天流水权重30%。
+ **预期**：配置保存失败，提示启用维度权重之和必须等于100%。

### 6.3 新增评分维度

+ **场景**：运营新增“直播间类型”评分维度，并配置颜值30%、直播环境25%、近7天流水30%、直播间类型15%。
+ **预期**：配置保存成功，下一次评分计算按4个启用维度计算综合评分。

### 6.4 自动综合评分计算

+ **场景**：主播A颜值分90、直播环境分80、流水分70，占比分别为40%、30%、30%。
+ **预期**：系统计算综合评分为 `90*40% + 80*30% + 70*30% = 81`。

### 6.5 锁定评分不被覆盖

+ **场景**：运营设置主播A锁定评分为90分，系统自动计算分为81分。
+ **预期**：系统计算记录保留81分，但主播当前生效综合评分仍为90分。

### 6.6 解锁后自动更新

+ **场景**：主播A原锁定90分，运营解锁后下一次系统自动计算分为82分。
+ **预期**：主播当前生效综合评分更新为82分。

### 6.7 开播热度加成

+ **场景**：主播A当前生效综合评分90分，热度换算比例为1000，原有热度为50000。
+ **预期**：综合评分加成热度为90000，最终初始热度为140000。

### 6.8 每日只计算一次

+ **场景**：系统当天已完成主播A近7天流水及综合评分计算。
+ **预期**：当天定时任务不重复生成自动计算记录；如需重算，应通过运营手动触发并标记触发方式。
