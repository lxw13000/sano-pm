## 参考与规格

目录组织与管理端参考同级 `sano提现管理`：深蓝侧栏、紫色主操作、浅色卡片、表格内部横向滚动、右侧抽屉、固定抽屉头尾及中部滚动。管理端导出视口 1760×1120；H5 430×1080，主页面导出完整长图，面板导出当前视口。已补充 360/390 与 1280/1440 宽度验证。

H5 使用紫金万圣节主题，以 CSS 绘制南瓜装饰和头像框示意，不依赖外部素材。产品时间统一显示 Sano Time · UTC+8，首屏完整日期范围与秒级倒计时并列。H5 顶部浅色演示栏用于跳转导航及演示新增积分，不属于正式产品界面。

## 推荐演示路径

### 1. 积分持续累计与每日资格

打开 H5 进行中，默认今日单场最高 680 分，今日尚未达标，今日领取按钮不可用；另有两份历史达标奖励可独立补领。点击顶部演示栏“演示单场1000分”，以本次单场 1000 分产生当天一份奖励资格；再次结算单场 1000 分，榜单总积分继续增加，但不增加第二份每日奖励。当天已领取后保持“今日已领取”。切换三个榜单，查看单位、获奖人数及本人排名。页签下直接展示 NO.1–3 的头像框与金币。

两场各 600 分只增加榜单总积分，不会合并成 1200 分授予每日资格。跨 UTC+8 的 00:00，今日单场最高分重新统计，历史奖励和活动总分保留。

### 2. 多日期补领

打开“每日达标奖励 · 跨天补领”，示例 10-28、10-27、10-26 均有单场达标，三天待领，10-25 已领；列表按日期显示当日单场最高分。逐天领取或领取全部，观察已领取状态、钱包及背包到账提示。领取不扣积分，也不改变其他日期次数。源文件模拟 350ms 处理时间，期间禁重复提交。

### 3. 活动结束与最终奖励

打开“已结束 · 待发放”，每日奖励关闭，历史未领均失效；活动倒计时消失，显示最终榜单及奖励发放时间。再打开“最终奖励待领取”，点击最终领奖按钮，查看示例账号在主播礼物榜与用户榜的独立权益，逐份手动领取。每日入口仍保持关闭。

“最终奖励已领取”展示两份已到账结果。“页面已下线”只保留结束说明，不提供领取入口。未获奖状态可通过 `源文件/index.html?scene=h5-final-none` 查看。

### 4. 管理端配置与校验

从活动配置保存草稿；将结束改早于开始会提示时间顺序错误。“检查并发布”列出游戏、礼物、地区范围及奖励资源待确认项，不会发布未确认配置。

活动区域配置直接展示列表，没有地区概览卡片。编辑第三区域，将国家改为 `PH, IN` 保存会被阻止，因为 PH 已属于 PH 地区；恢复 `IN, BD` 可保存演示草稿。新增区域同样校验其他区域的国家占用。第三地区名称及国家映射并未业务确认。

排名奖励无样式档位预览，保留筛选和列表，新增与编辑均从现有商城道具目录选择有效头像框，不手输道具名称。前三不能使用同一头像框；第 4 名起共用道具，修改其中一名的头像框会同步后续已有名次，金币仍独立。

打开“新增排名奖励”场景，示例第 10 名尚未配置，选择商城头像框、填写金币后新增，列表补齐。对已配置名次重复新增会被阻止。后台“预览 H5 奖励展示”与 H5 使用同一配置对象，可即时核对编辑值；刷新仍恢复原型初始配置。商城目录仅为接口结构的本地样例，不代表已经连接线上商城。

### 5. 榜单与领取流水

榜单数据仅筛选条件和列表，无累计/概览卡片。按地区、榜单、账号/昵称筛选，查看来源明细及导出当前结果。阶段和更新时间放在列表工具栏，最终榜单场景展示最终快照。

奖励记录支持用户、榜单区域、每日/榜单、权益状态筛选和导出。增加总投入金额（USD）、总参与人数、总参与主播数、南瓜灯投放/赠送、金币投放/领取汇总。默认全部区域；筛选 PH 后汇总显示 PH 数据，例如总投入 $1,764.00，按 `(9,240,000 + 42,000 × 200) ÷ 10000` 计算。用户、奖励类型和状态筛选只影响明细，不影响区域汇总。

打开异常记录详情：金币已到账，背包接口结果待核对；不能把整份标为成功，也不提供重新整份发奖按钮。汇总使用全量独立样例，列表是少量代表记录，不直接按列表当前页求和。

## 文件维护与重新生成

源文件：`源文件/index.html`、`styles.css`、`app.js`。场景由 `生成工具/scenes.json` 维护。新增或调整场景后重新验证和导出，保持导航、图和业务文档一致。

```powershell
node .\生成工具\validate-prototypes.js
node .\生成工具\render-prototypes.js
```

或运行 `生成工具/重新生成.ps1`。工具沿用参考专项本机 Node、Playwright、Chrome、Sharp 路径；其他机器可通过 `SANO_NODE_MODULES` 指定包含 Playwright 与 Sharp 的目录，通过 `SANO_CHROME` 指定 Chrome 路径。使用交互原型本身无需这些工具。

## 原型边界及待定项

全部为本地虚构数据，不调用真实游戏、钱包、背包或管理接口。源文件提供演示时钟及只读来源展示，不构成生产接口实现。

日期、第三地区名称、所有国家清单、游戏/礼物 ID、各名次金币及头像框有效期均待确认。原型已标记示例，不得直接作为正式上线配置。跨榜奖励按确认原型分别展示和领取；同分顺序、地区锁定、异常事件撤销等见产品文档的上线待定项。
