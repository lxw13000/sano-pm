## 1. 核心规则

### 1.1 游戏与每日奖励

所有用户均可参与，无需报名。用户可在直播间反复玩指定切水果游戏，活动总积分持续累计，不因跨日或领奖清零。

| 项目 | 规则 |
| --- | --- |
| 用户积分 | 每局有效结算积分计入本人活动总积分；另记录当日单场最高分用于展示领奖状态 |
| 主播积分 | 同一局积分计入该局所在直播间的主播，结算后归属不随用户换房改变 |
| 每日达标 | 当天任意一场指定游戏达到 1000 分，产生当天一份奖励资格；多场分数不合并，同一天多次单场达标仍只有一份 |
| 每份奖励 | 200 金币进入钱包，南瓜灯 ×1 进入礼物背包；用户手动领取，不扣游戏积分 |
| 跨天补领 | 活动期间可领取所有已达标、未领取日期的奖励；支持逐份或领取全部 |
| 领取截止 | 活动结束即停止领取每日奖励，未领取的资格失效 |
| 南瓜灯 | 普通礼物，面值 200 金币，仅通过每日奖励获得，商城不售卖 |
| 礼物使用 | 赠送、接收及主播收益沿用现有普通礼物逻辑；统一在活动结束时失效，不兑换金币 |

例如在 A 房一场获得 600 分、B 房一场获得 500 分，用户活动总积分增加 1100 分，A 主播加 600 分、B 主播加 500 分；两场均未达到 1000 分，不能领取当天奖励。只有后续任意单场达到 1000 分才获得当天资格。领取时同时发放金币和礼物，不需要用户另付 200 金币。

### 1.2 区域榜单与最终奖励

账号按**注册国家**匹配活动榜单区域，H5 自动展示所属区域；不按 IP、设备时区或语言判断。同一国家在本活动中只能属于一个区域。

| 榜单 | 计分对象与方式 | 每区域获奖范围 |
| --- | --- | --- |
| 主播南瓜灯榜 | 接收主播，活动内有效收到 1 个南瓜灯计 1 分 | 前 10 名 |
| 主播游戏积分榜 | 房间主播，活动内房间有效游戏结算积分之和 | 前 10 名 |
| 用户游戏积分榜 | 游戏用户，活动内本人有效游戏结算积分之和 | 前 20 名 |

- 用户和主播分别进入自身注册国家所属区域。跨区域互动时，游戏分或礼物分仍归各自参榜账号，不随对方区域迁移。
- 南瓜灯榜按实际接收件数统计，不按背包持有量、每日领取量或礼物金额统计。背包礼物过期不回滚已形成的有效榜单积分。
- 榜单实时更新，活动结束停止接收新发生的计分；完成活动内事件核对后确定最终排名。
- 每榜奖励均为金币 + 头像框。前三使用不同头像框，第 4 名起使用同一头像框道具，金币逐名次配置；人数不足不补虚拟获奖者。
- 最终奖励在活动结束后一天生成待领取权益，用户或主播手动领取；页面保留期间可领，页面下线后不可领。同账号跨榜的奖励分别展示和领取。

奖励权益指一份可领取的奖励记录。本文统一术语：**发放**指生成待领取奖励权益；**领取**指用户申请兑现权益；**到账**指钱包、背包或头像框资产实际发放成功。生成权益不等于资产到账。

## 2. 时间与活动阶段

配置四个时间点：开始 `T_start`、结束 `T_end`、最终奖励发放 `T_issue`、页面下线/最终领奖截止 `T_close`，要求 `T_start < T_end < T_issue < T_close`。

活动计入范围为 `[T_start, T_end)`，最终领奖范围为 `[T_issue, T_close)`。到截止时刻即不可新申请相应领取。每日按 UTC+8 的 00:00 切日，首末日仅统计与活动时间重叠的部分。最终发放的具体日期和时刻必须配置，不能仅按前端“次日”文案执行。

| 阶段 | 榜单 | 每日奖励 | 最终榜单奖励 | H5 时间展示 |
| --- | --- | --- | --- | --- |
| 开始前 | 空榜，可查看奖项 | 不可领 | 不可领 | 完整活动时间段、距开始倒计时 |
| 进行中 | 实时累计 | 当日及历史达标奖励可领 | 未发放 | 完整活动时间段、距结束倒计时 |
| 已结束待发放 | 核对后展示最终榜；未完成则标记核对中 | 未领取奖励失效 | 显示发放时间 | 活动已结束 |
| 已发放、页面保留中 | 最终榜单 | 不可领 | 获奖且未领者可领取 | 活动已结束、最终领奖截止 |
| 页面下线后 | 移除入口，直链显示已下线 | 不可领 | 未领取权益到期 | 页面已下线 |

南瓜灯统一于 `T_end` 失效，哪天领取都不延长有效期。头像框使用自身配置的有效期，不随活动结束失效。

H5 的倒计时显示天、时、分、秒。进入页面、恢复前台和跨阶段时校准服务端时间；设备改时区不影响切日、计分、赠送或领取判断。

## 3. 必要业务流程

### 3.1 游戏结算 → 积分累计 → 每日资格

1. 接收指定游戏的有效结算，取得唯一事件 ID、用户、房间、主播、积分和服务端认定的结算时间。
2. 校验游戏、事件有效性及活动时间，按事件 ID 去重。
3. 将本局积分分别加到用户活动总积分、该局主播活动总积分，并用本局得分更新当日单场最高分；跨日只重置单场最高分及当天资格判断，不清空活动总分或历史权益。
4. 判断**本局得分是否达到 1000 分**。达到且当天尚无奖励权益时，创建当天一份待领取奖励，记录达标游戏局 ID、单场分数及结算时间；后续继续计榜，同一天其他达标局不再创建第二份。

无有效房间或主播的事件隔离核对，不能随意归属。活动结束前已有效结算但异步处理延迟的事件，在最终奖励生成前补齐；不计入结束后才发生的结算。

### 3.2 手动领取 → 资产到账

1. 用户选择一份奖励或“领取全部”。服务端校验身份、权益、领取期限和当前状态。
2. 以权益 ID 创建或复用唯一领取单，记录受理时间；处理中禁止重复发起。
3. 每日奖励分别发放金币和南瓜灯；最终奖励分别发放金币和所配置的头像框。
4. 所有子资产成功后，整份标为已领取并记录到账流水；部分成功时保留异常状态，查询或补齐原单缺失资产。

| 权益/领取状态 | 含义与操作 |
| --- | --- |
| 待领取 | 已达标或已获奖，在领取期内可以领取 |
| 处理中 | 请求已受理，查询原单结果，不重复发资产 |
| 已领取 | 所有子资产成功，不可再次领取 |
| 发放异常 | 部分或全部资产结果异常，按原单核对、只补缺失资产 |
| 已失效 | 截止前未受理领取，到期不可再领 |

“未达标”属于每日进度状态，尚不产生奖励权益。批量领取按每份权益独立处理并返回结果，不能因一份失败重发全部。

以**服务端受理时刻**判断是否在领取期内。截止前已受理的领取单可以在截止后完成；截止后的新请求拒绝。每日原单晚到账的南瓜灯仍按 `T_end` 失效，不延长使用期。网络超时应查询原单，不能直接新建领取单或重发已到账金币。

### 3.3 南瓜灯赠送 → 主播礼物榜

按现有普通礼物流程校验、扣减背包并完成赠送；使用服务端确认的成功交易结果累计接收主播榜分。交易 ID 去重，一次多件按件数累计。达到 `T_end` 后拒绝新赠送；截止前成功但异步处理延迟的交易，在封榜核对时补齐。

### 3.4 结束核对 → 定榜 → 最终奖励

1. 到 `T_end`，停止新增活动行为，关闭每日领奖并使南瓜灯到期。
2. 核对活动内游戏及礼物事件，生成各区域、各榜单的最终排名快照。
3. 按快照和绑定的奖励配置，在 `T_issue` 生成获奖账号的待领取权益，不直接发资产。
4. H5 展示各榜获奖奖励，用户按第 3.2 节手动领取，截止到 `T_close`。

快照保留区域、榜单、账号、名次、分值、奖励配置版本、金币、头像框及有效期。生成任务重试不能多发权益；数据核对未完成时显示核对中，不将临时排名或缺失数据当作最终结果发奖。

## 4. 页面与管理功能

### 4.1 App 内 H5

| 模块 | 必要内容与交互 |
| --- | --- |
| 活动头部 | 活动名称、完整起止时间、Sano Time · UTC+8、阶段及倒计时 |
| 榜单区域 | 自动显示注册国家所属区域；缺映射时提示区域暂不可用，不影响游戏和每日领奖 |
| 每日单场达标奖励 | 明确“当天任意单场达到1000分，每天仅可领取一次，多场分数不合并”；展示今日单场最高分、今日资格及领取状态；历史待补领奖励单独展示 |
| 三榜切换 | 当前区域榜单、计分单位、前三及后续名次、本人在当前榜的排名、最近更新时间和刷新 |
| 排名奖励展示 | 页内直接展示 NO.1–3 的头像框图片/名称、金币及有效期；全部奖励可逐名次查看 |
| 最终奖励 | 每份显示区域、榜单、名次、奖励及状态；明确发放时间和领取截止 |
| 规则与反馈 | 玩法和两类领奖期限；空榜、加载失败、未获奖、处理中、已领取、已下线等状态 |

排名奖励读取“当前区域 + 当前榜单”的已发布配置，图片和名称取自所选商城道具，不写死金币或资源。后台草稿预览读取草稿；最终领奖以封榜绑定的奖励快照为准。

活动结束只关闭每日领奖，不同时关闭最终领奖。无主播排名时不能展示用户榜排名代替。接口失败不能伪装为空榜或成功到账。

每日奖励卡不展示“今日新增/累计达到1000分”或累计进度条。未达标时“领取今日奖励”不可用；有历史奖励也只开放独立的历史补领入口。当天已领取后继续单场达标，仍显示今日已领取。活动累计积分在榜单中展示，不作为每日达标进度。

### 4.2 管理端

导航：活动运营 → 万圣节活动 → 活动配置 / 活动区域配置 / 排名奖励 / 榜单数据 / 奖励领取记录。

| 页面 | 配置/查询内容 | 保存与展示要求 |
| --- | --- | --- |
| 活动配置 | 名称、指定游戏、四个时间点、南瓜灯礼物；展示单场门槛 1000、每日金币 200、礼物 ×1、面值 200 和失效时间 | 已确认每日规则只读；发布校验时间顺序、资源、国家范围和完整名次奖励 |
| 活动区域配置 | 区域编码、名称、国家列表、状态、更新时间；支持新增/编辑 | 直接列表，无地区概览；新增/编辑均校验其他区域占用国家，编辑排除自身；同表单重复或未知国家阻止保存，错误列出归属 |
| 排名奖励 | 按区域/榜单筛选；新增/编辑名次、金币、商城头像框、有效期；显示配置列表和金币合计 | 无样式档位预览；区域+榜单+名次唯一，名次在获奖范围内，金币为非负整数；草稿可逐条新增，发布须覆盖全部获奖名次 |
| 榜单数据 | 区域、榜单、账号查询；排名、注册国家、区域、分值、来源明细及导出 | 只保留筛选和列表，无累计卡片；阶段、更新时间放工具栏；只读追溯，不直接改分 |
| 奖励领取记录 | 用户、区域、每日/榜单、状态查询；含待领取权益、领取单和资产流水，支持导出 | 筛选下方展示区域汇总，详见第 5 节；详情区分金币与礼物/头像框的独立结果 |

头像框直接选择现有商城中的有效头像框道具，保存道具 ID，读取名称和图片；非头像框、下架或失效资源不可新选，保存/发布时服务端复验。第 4 名起修改头像框会同步本区域本榜后续已有名次，金币仅改当前名次。发奖按快照执行，不随后续商城或配置修改变化。

领取记录至少包含权益 ID、账号/区域、来源日期或榜单名次、奖励、领取截止、领取时间、权益和资产状态。详情显示原领取单、各资产流水号、受理/完成时间及异常原因，不能将部分到账显示为整份成功。

## 5. 区域汇总与投入金额

领取记录默认汇总全部榜单区域；选择区域并查询后，汇总与明细同步切换。汇总读取全量活动数据，不累加当前页明细。用户、奖励类型和状态等筛选只作用于明细，不改变区域汇总。

| 指标 | 统计定义 |
| --- | --- |
| 总投入金额（USD） | **（金币投放总数 + 南瓜灯投放总数 × 200）÷ 10000**，保留 2 位小数；固定业务换算，不取实时汇率，不加入头像框价格或再次计算赠送价值 |
| 总参与人数 | 活动内有有效游戏或南瓜灯赠送/接收行为的账号去重，含参与主播，不累加三榜人数 |
| 总参与主播数 | 活动内房间有有效游戏积分或有效收到南瓜灯的主播去重，跨房间和跨榜不重复 |
| 南瓜灯投放总数 / 赠送总数 | 已产生每日奖励权益的南瓜灯累计件数 / 活动内实际成功有效赠送件数，交易去重 |
| 金币投放总数 / 领取总数 | 每日及最终榜单已生成权益的金币累计数 / 钱包子流水实际成功入账金币数 |

投放包含已生成但未领、已领、失效及异常的原始权益，重试不重复计数；领取只计算实际成功资产，即使整份领取单还有其他资产异常，已到账金币仍计入领取数。因此总投入按投放口径统计，不等于实际已领取金额。

区域归属：参与人数按该账号；主播数按主播账号；投放/领取按权益所属账号；南瓜灯赠送按赠送账号。主播接收榜仍按接收主播区域统计，不能用收礼榜分数替代赠送总数。各区域账号归属互斥，跨区域送礼在全局只统计一次赠送。

例如 PH 区域金币投放 9,240,000、南瓜灯投放 42,000，投入为 `(9,240,000 + 42,000 × 200) ÷ 10000 = $1,764.00`。原型汇总和少量明细均为样例，不据此确定正式预算。

## 6. 开发对接约束

### 6.1 唯一性与最小数据

下表为业务约束，不限定数据库表名或技术栈。

| 数据 | 必须保留的内容 / 唯一约束 |
| --- | --- |
| 活动及配置 | 活动 ID、四个时间点、游戏/礼物 ID、奖励参数与版本；本活动国家到区域唯一映射 |
| 游戏结算 | 唯一事件/游戏局 ID、用户、房间、主播、有效结算时间、积分 |
| 礼物交易 | 唯一交易 ID、送出者、接收主播、件数、有效时间 |
| 每日奖励权益 | 活动 + 用户 + UTC+8 达标日期唯一；保存达标游戏局 ID、单场分数、有效结算时间、奖励及截止时间 |
| 最终排名/权益 | 区域、榜单、账号、名次和奖励快照；活动+区域+榜单+获奖账号唯一权益 |
| 领取与子资产 | 一个权益复用唯一领取单，各资产有独立幂等标识、流水和结果；重试只补缺失资产 |

积分事件、权益创建、领取和资产发放都需服务端去重；前端按钮防重复不能替代以上约束。统计以唯一权益、有效交易和成功资产流水计算，不按请求次数计算。

### 6.2 对接能力

- **H5 查询**：活动配置、服务端时间、账号区域、三榜与本人排名、当前榜奖励展示、今日单场最高分、今日奖励状态、活动总积分、历史每日权益、最终权益及领取结果。
- **资产流程**：逐份/批量领取、钱包金币、普通礼物背包、头像框资产发放及结果核对；复用现有资产系统。
- **管理端**：配置及发布校验、国家字典、有效商城头像框目录、榜单来源、权益/流水查询和导出、区域汇总及统计时间。
- **后台处理**：游戏与礼物事件汇总、每日资格、活动结束核对、最终排名快照、定时生成最终权益、异常原单修复。

具体接口路径、存储及刷新频率由研发确定。时间判断与资格校验全部由服务端执行；H5 展示最新状态，并在边界及恢复前台时重新同步。

## 7. 核心验收

| 场景 | 验收结果 |
| --- | --- |
| 两场600分、单场999/1000分、同日多次单场达标 | 两场合计1200仍未达标；单场999未达标、1000达标；当天仅一份，继续游戏仍全量计榜 |
| UTC+8跨日、跨房间 | 跨日重置当日单场最高分，保留活动总分及历史奖励；换房不合并单场分数，各主播按所在局累计 |
| 多日补领、重复点击、请求超时 | 每日期一份，领取不扣分；复用原单，不重复发金币或礼物 |
| 活动结束边界、原领取单晚完成 | 新请求拒绝，已受理单完成；每日未领失效，南瓜灯不延长有效期 |
| 多件南瓜灯、交易重放、礼物过期 | 按有效接收件数计榜且只计一次，过期不回滚历史榜分 |
| 活动结束及次日发放 | 活动外行为不改最终榜；先定榜后按快照生成权益，未领不自动到账 |
| 最终奖励、跨榜、页面下线 | 各榜分别可领；每日入口关闭不影响最终领奖；页面下线拒绝新领取 |
| 钱包成功、另一资产异常 | 展示部分异常，只补缺失资产；金币领取统计按实际到账计一次 |
| 国家缺失/重复、区域筛选 | 缺映射不影响游戏和每日奖励；新增/编辑阻止一国多区；区域汇总与明细同步切换 |
| 排名奖新增、商城道具及 H5 展示 | 重复/越界名次、无效道具阻止；H5 直接展示对应区域、本榜已发布头像框和金币 |
| 统计及换算 | 全量去重、重试不放大；金额严格按第 5 节公式计算，明细筛选不改变区域汇总 |
