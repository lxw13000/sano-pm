# SANO公会运营页面原型

本版包含31张桌面管理后台页面与操作状态原型，每张1672×941。沿用“sano用户任务体系”的深蓝侧栏、紫色操作按钮、浅色内容卡片及PNG＋SVG输出方式；公会详情采用“固定摘要＋标签页”的结构，参考用户画像。

本次以“先看自己的盘子 → 比较公会 → 查看具体公会”为主线。经营工作台按角色自动展示范围内公会概况、收益、平台价值、主播结构、发展和Top10；列表优先经营比较，具体画像保留“性质＋一句话结论＋关键依据”。5个主模块、7个详情标签不变；31张图含角色、历史、全树和抽屉状态，不代表31个独立模块。

## 输出说明

- `原型图/`：31张PNG评审图及1张总览图。
- `源文件/`：31张可编辑SVG源文件。可在浏览器打开；侧栏、主要标签和主要流程按钮支持页面跳转。
- `生成工具/`：生成、渲染脚本及页面清单。
- 原型是静态页面和操作状态示意；输入框、筛选、分页、审批提交及树节点展开不执行真实业务。SVG链接演示主要流程，部分链接进入对应模块的代表性示例页面，不表示数据上下文完整传递。
- 用户画像、直播场次详情复用已有模块，本版展示下钻入口，不复制其页面。
- 全部人名、账号、公会、交易、金额、指数及结论均为虚构示例。综合评分用于检查信息呈现，不由本原型规则引擎计算；风险页单项按文档试运行公式演示展开内容，也不代表已确定上线算法。
- 文件已参考用户任务体系统一为`端类型-一级模块-二级功能-页面序号-页面名称`，例如`admin-02-06-02-奖励明细抽屉-超级主播奖励`。PNG/SVG同名，文件编号今后保持稳定。
- 清单中的旧编号仅用于对照此前评审，不是现行文件标识或独立路由。五张奖励明细图为同一抽屉的五种Tab状态；新增的子公会贡献图为同一“分层与奖励”标签的筛选状态。

## 模块职责与信息归属

主导航：经营工作台、公会管理、评估中心、风险审核、运营与BD业绩。工作台为经营角色默认入口；评估、审核及负责人业绩按权限作为辅助，不要求运营先进入。

同一工作台复用管理者、运营、BD范围。普通运营不需要手动选负责人，也不能选择全平台。Nina示例默认只保留工作台、我的公会两个主入口；评估/重评按独立权限开放，跨负责人业绩和审核菜单不默认展示。范围由服务端贯穿汇总、Top10、列表、导出、评估及详情；没有负责公会显示空状态。我的工作台并非另建一套业务计算。全平台主播身份数仅全平台授权管理者可见，明确拆公会内/未归属；运营仅见自己的主播结构。

经营列表默认可比较每公会的发展、身份结构、消费、公会自身收益、平台贡献和风险；画像才解释性质与依据。发展看可比完整周的有效开播、独立消费、复购事实，与经营评分/风险分开。高风险包含疑似，数量不相加。经济、供给、用户价值分别展示，不增加综合价值分。

| 公会详情标签 | 唯一主要职责 |
| --- | --- |
| 画像概览 | 先给性质和一句话结论；经营/风险各最多3条关键依据，标题右侧显示对应评分，不堆完整指标表 |
| 组织与归属 | 公会树、主播与公会长、运营/BD责任归属、关系变动；不放分层金额 |
| 主播经营 | 仅单人/多人直播的时长、场次、连续性及留存；房间总消费仅记给场次房主，个人收入独立统计 |
| 消费与收入总览 | 公会消费、主播收益、公会收益和整体业务收益，收入含分层与奖励；关联账号奖励单列，保留平台贡献 |
| 分层与奖励 | 本公会五项收益汇总；直属主播/子公会贡献标签；贡献者自身收益与给本公会的分层分列；公会奖励按周榜/超级达标/其他来源展开 |
| 资金流向 | 账户资金总览、逐笔链路及追溯事实；不在此下套利定性 |
| 套利风险与证据 | 实际指标、风险解释、涉及对象/金额、证据强度和待核验事项；引用原始业务记录 |

评估中心的三个标签为日常风险扫描、正式周期评估、手动重评记录。正式周评估进入同一画像的历史版本，不再生成另一套分析页。全树是画像范围状态；异常和版本对比是结果状态。风险审核只维护事项与人工结论；运营/BD在同一模块分别按各自负责人分组。

### 分层与奖励及奖励抽屉的交互关系

从“分层与奖励”的五类奖励链接打开右侧“奖励明细”抽屉，进入对应Tab。统一标题和上下文位于抽屉顶部，其下先放五个Tab，再放分类汇总，然后是筛选、逐笔明细和选中记录凭证。遮罩和左侧露出的父页面明确表示当前仍在原页面，不再重画一套公会主导航或使用“返回分类汇总”。

SVG中可点击五个Tab切换展开状态，点击“关闭×”或遮罩返回分层与奖励；实际产品关闭后还应保留父页的滚动/筛选/评估状态，并支持Esc与焦点返回。滚动固定、筛选、分页和记录选中仍是静态交互说明，不执行真实业务。导航按“分层与奖励”的抽屉状态分组，使用新的业务层级文件名；旧文件已重命名，目录不保留另一套重复设计。

## 三个Top10平铺与指标隔离

管理者、运营者工作台均将平台贡献Top10、公会收益Top10、经营增长Top10横向平铺，不再使用标签切换。每榜仅排名、公会、对应指标和详情：

- 平台贡献榜：平台贡献净收益（美元），按所选业务周期。
- 公会收益榜：公会自身收益（分层＋公会奖励，美元），同业务周期。
- 经营增长榜：独立用户消费环比，明确当前完整周和对比完整周；可比且基期>0。

排行榜不显示风险/审核、身份或其他指标，也不依赖风险评估成功。风险概况仍在工作台其他区域，经营关注项与榜单分开。点击详情进入对应公会画像，来源范围/业务周期/返回位置保留；画像自己的评估窗口独立标明。静态原型只有星河存在可点击详情状态，其余行是详情操作占位，不跳到星河冒充目标。

旧两张切换图的PNG/SVG保存在[旧版归档说明](归档/2026-10-09-榜单标签旧版/README.md)，可恢复，当前有效原型31张。

## 本次角色工作台调整

- 首屏先展示自己的经营盘子，收益和平台贡献升为主要信息，不再以性质/风险名单占据整个平台首页。
- 默认最近完整自然周；金融指标该周，身份/组织截至周末，发展对比前周，风险/性质仍注明30/60日正式窗口。
- 正向/回落/平稳/混合/待判采用需求20.2的透明事实规则，不改旧评分；增长榜只按独立消费环比，不冒充质量榜。
- 平台价值分别看经济、供给、用户；公会自身收益不等于平台贡献，也不等于主播收益。
- 运营只见自己，BD只见业务归属，负责人业绩用于有权限管理者比较。未负责子公会不纳入盘子；本会收到的子公会差额仍计本会收益。

## 本次补充口径

- 评分在经营与风险依据块的标题右侧，以27px数字和“/100”显示；主性质标题仍为29px。直属、全树、历史画像同步调整。
- 时长、场次及依赖有效直播的开播/留存仅单人、多人直播，排除语言房；财务总览和风险资金追溯不因此排除语言房。效率指标分子分母匹配相同直播范围。
- 多人房消费仅归场次房主；上麦主播只记本人收入。房间消费可展开单人/多人并进入场次订单，不能用该列直接推算个人收入。
- 主播收益=直接收入+主播奖励；公会收益=分层+公会奖励；整体业务收益为两者去重之和，关联消费账号奖励不加入。
- 三类主播奖励分别按业务类型统计金额与净获奖人数，优质主播可同时领取其周奖和等级时长奖；跨类人数不能相加。各分类可进入发放明细及代表记录凭证。
- 奖励明细是“分层与奖励”右侧同一抽屉的五种Tab状态，不增加主导航、第八个详情标签或独立页面。Tab在分类汇总上方；筛选与原始记录查询仍为静态示意。

## 本次贡献与公会奖励调整

- “分层与奖励”顶部固定当前公会五项：直属主播贡献、直属子公会贡献、分层合计、公会奖励、自身收益，不将全树各公会收益冒充当前公会实际所得。
- 分层明细下设“直属主播贡献”“直属子公会贡献”两个子标签，新增08仅为后者的标签状态，不增加业务模块。主播显示直接收入、本人奖励、本人总收益、分层比例及给当前公会的贡献；子公会显示其直属主播直接收入、自身收益、双方比例差及给父公会的贡献，点击辰星可查看收益来源。
- 主播奖励不向任何公会贡献分层；子公会已得分层、下级差额和公会奖励也不向更高层二次分层。只按原主播直接收入分给直属公会及直接上级一层正比例差，祖父级为0。
- 公会奖励分别显示公会周榜、超级主播达标公会奖励、其他公会奖励的净有效金额/笔数及入口；为0也可查。来源筛选及凭证复用“公会与关联账号奖励”抽屉Tab，明细明确业务受益主体与收款账号，避免将公会长个人奖励误归为公会奖励。
- 主播本人奖励与平台另发给公会的超级达标奖励互不混算。消费与收入总览将公会分层展开为直属与子公会贡献；平台成本和整体收益引用原合计，不因拆分类别而重复累计。
- 汇总、明细、原订单均保留公会、周期、版本、关系及比例历史，按净有效原始记录计算。静态原型只展示指定示例，筛选/逐笔查询入口不执行实际业务。
- 五张奖励抽屉统一使用父页直属主播标签作为底层示例，关闭SVG返回该示例；生产须恢复实际打开时的直属主播/直属子公会子标签、子公会筛选及滚动。来源链接在静态SVG进入全部来源的代表性抽屉，实际产品按触发来源带入筛选，0记录也可查询。
