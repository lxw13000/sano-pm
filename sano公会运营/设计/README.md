# SANO公会运营页面原型

本版包含25张桌面管理后台页面与操作状态原型，每张1672×941。沿用“sano用户任务体系”的深蓝侧栏、紫色操作按钮、浅色内容卡片及PNG＋SVG输出方式；公会详情采用“固定摘要＋标签页”的结构，参考用户画像。

本次调整将“公会性质＋一句话结论＋关键依据”提升为首页、列表和画像概览的主信息，评分保留为辅助信息，并适当放大至经营/风险依据分块标题右侧。主导航收敛为5个模块，公会详情固定7个标签；25张图包含标签、历史版本、全树及弹窗等状态，不代表25个独立模块。

## 输出说明

- `原型图/`：25张PNG评审图及1张总览图。
- `源文件/`：25张可编辑SVG源文件。可在浏览器打开；侧栏、主要标签和主要流程按钮支持页面跳转。
- `生成工具/`：生成、渲染脚本及页面清单。
- 原型是静态页面和操作状态示意；输入框、筛选、分页、审批提交及树节点展开不执行真实业务。SVG链接演示主要流程，部分链接进入对应模块的代表性示例页面，不表示数据上下文完整传递。
- 用户画像、直播场次详情复用已有模块，本版展示下钻入口，不复制其页面。
- 全部人名、账号、公会、交易、金额、指数及结论均为虚构示例。评分值用于检查信息呈现，不由需求文档中的试运行公式计算，也不代表已确定风险算法。
- 为保持已有链接可用，文件编号及文件名不变；页面内标题和下表显示名已按职责调整。21为手动重评记录；22—25为07“分层与奖励”页内的四种奖励明细抽屉状态，不是独立页面。

## 模块职责与信息归属

主导航：经营总览、公会管理、评估中心、风险审核、运营与BD业绩。

| 公会详情标签 | 唯一主要职责 |
| --- | --- |
| 画像概览 | 先给性质和一句话结论；经营/风险各最多3条关键依据，标题右侧显示对应评分，不堆完整指标表 |
| 组织与归属 | 公会树、主播与公会长、运营/BD责任归属、关系变动；不放分层金额 |
| 主播经营 | 仅单人/多人直播的时长、场次、连续性及留存；房间总消费仅记给场次房主，个人收入独立统计 |
| 消费与收入总览 | 公会消费、主播收益、公会收益和整体业务收益，收入含分层与奖励；关联账号奖励单列，保留平台贡献 |
| 分层与奖励 | 直属分层、子公会差额、贡献者/基数/比例、主播/公会/关联消费账号奖励及分配 |
| 资金流向 | 账户资金总览、逐笔链路及追溯事实；不在此下套利定性 |
| 套利风险与证据 | 实际指标、风险解释、涉及对象/金额、证据强度和待核验事项；引用原始业务记录 |

评估中心的三个标签为日常风险扫描、正式周期评估、手动重评记录。正式周评估进入同一画像的历史版本，不再生成另一套分析页。全树是画像范围状态；异常和版本对比是结果状态。风险审核只维护事项与人工结论；运营/BD在同一模块分别按各自负责人分组。

### 07与22—25的交互关系

从07的四个奖励链接打开右侧“奖励明细”抽屉，进入对应Tab。统一标题和上下文位于抽屉顶部，其下先放四个Tab，再放分类汇总，然后是筛选、逐笔明细和选中记录凭证。遮罩和左侧露出的07明确表示当前仍在原页面，不再重画一套公会主导航或使用“返回分类汇总”。

SVG中可点击四个Tab切换展开状态，点击“关闭×”或遮罩返回07；实际产品关闭后还应保留07的滚动/筛选/评估状态，并支持Esc与焦点返回。滚动固定、筛选、分页和记录选中仍是静态交互说明，不执行真实业务。导航将22—25集中标注为07的抽屉状态，文件编号保留以兼容现有链接。

## 建议评审顺序

1. 从经营总览进入公会列表，再看星河公会画像概览及各标签页。
2. 切换到全树画像，查看全树范围和逐层展开的组织关系示意。
3. 在评估中心切换三种评估记录，从正式评估进入历史画像，再发起重评或查看版本对比。
4. 从日常风险扫描查看新增风险，再进入风险审核列表和人工审核详情。
5. 查看运营与BD业绩，以及新公会与数据异常状态。

## 已确认口径在原型中的体现

- 时区UTC+8，全部金额为美元USD。源资产可以说明类型，但不以金币或钻石数量作为画像金额展示。
- 正式评估示例：2026-09-07周一执行，截止2026-09-06周日23:59:59；周指标为08-31至09-06。
- 正式评估经营窗口：08-08至09-06，共30个完整自然日；风险窗口：07-09至09-06，共60个完整自然日。
- 日常扫描示例：09-09执行，截止09-08；经营08-10至09-08，风险07-11至09-08。
- 最新观察、正式快照、手动重评及人工结论分别呈现，重评不会直接覆盖历史人工结论。
- 四类账号：SANO内部账号、公会成员、公会关联账号、独立用户。邀请关系或同IP不单独构成强关联。
- 公会周榜按结算时最终归属统计整周收入，公会长兼主播时只计一人。
- 公会分层只展示直属分层和直属子公会一层差额；全树统计不表示多层继续分账。
- 平台贡献明确标注按消费金额计算，使用普通礼物16%、幸运礼物1.1%、游戏2%；公会分层不再次扣除。
- 人工审核仅记录结论及依据，具体处置由运营自行处理。

## 本次补充口径

- 评分在经营与风险依据块的标题右侧，以27px数字和“/100”显示；主性质标题仍为29px。直属、全树、历史画像同步调整。
- 时长、场次及依赖有效直播的开播/留存仅单人、多人直播，排除语言房；财务总览和风险资金追溯不因此排除语言房。效率指标分子分母匹配相同直播范围。
- 多人房消费仅归场次房主；上麦主播只记本人收入。房间消费可展开单人/多人并进入场次订单，不能用该列直接推算个人收入。
- 主播收益=直接收入+主播奖励；公会收益=分层+公会奖励；整体业务收益为两者去重之和，关联消费账号奖励不加入。
- 三类主播奖励分别按业务类型统计金额与净获奖人数，优质主播可同时领取其周奖和等级时长奖；跨类人数不能相加。各分类可进入发放明细及代表记录凭证。
- 新增明细是07“分层与奖励”右侧抽屉的四种Tab状态，不增加主导航、第八个详情标签或独立页面。Tab在分类汇总上方；筛选与原始记录查询仍为静态示意。

## 示例数据对账

星河公会近30日直属消费为50,000.00美元：独立用户20,000.00、公会成员18,000.00、公会关联账号12,000.00。SANO内部账号消费600.00美元单独展示，不进入该消费合计。

普通礼物消费10,000.00、幸运礼物20,000.00、游戏20,000.00，对应主播直接收入7,000.00、400.00、100.00，合计7,500.00。直属分层为1,500.00，直属子公会贡献240.00，公会分层合计1,740.00。

平台业务净收入为2,220.00美元；主播及公会奖励1,760.00美元，关联账号可归属奖励400.00美元，平台贡献净收益为60.00美元。奖励表只展示部分记录，其行合计不等于全部奖励汇总。

本次将主播及公会奖励1,760.00拆为：超级主播600.00（2人）、优质主播320.00（2人）、等级时长240.00（3人）、其他主播0.00、公会奖励600.00。三类主播奖励共1,160.00，获奖主播并集6人，Nok在优质周奖与时长奖分别出现。超级主播Lina/Sam奖励360.00/240.00，优质主播Nok/Pim奖励200.00/120.00，时长奖励June/Ari/Nok为120.00/60.00/60.00。示例均无追回；发放09-01，奖励考核周W35，不把W36截止后发放的奖励倒计入本次金额。

主播收益7,500.00+1,160.00=8,660.00；公会收益1,740.00+600.00=2,340.00；整体业务收益11,000.00。关联账号归属奖励400.00仍单列为风险及平台成本，不加入整体业务收益。

主播经营前4行房主房间总消费18,000.00、14,000.00、10,000.00、4,000.00，示例其余主播合计4,000.00；本例语言房消费为0，故房主消费合计恰好等于全量消费50,000.00，这不是实际系统必须相等的规则。个人收入不由房主消费直接乘固定比例推算。

重评V2将2,000.00美元消费从独立用户重分类为公会关联账号，总消费仍为50,000.00美元。所有评分及其变化均为展示示例。

近60日风险示例独立于近30日经营金额：总消费90,000.00美元，成员30,600.00、关联账号25,200.00，合计55,800.00，占62%；关联账号奖励归属700.00美元。不得把这组数与近30日的60%或400.00美元直接对比为“数据变化”。

资金页总览为成员及关联账户侧的事件分类示例，包含其在范围外的消费，与直播间侧50,000.00美元不属于同一统计集合。充值、转账、兑换、消费、提现不可相加充当收入、资金余额或闭环金额。单笔100.00美元转账/消费与70.00美元主播收入是同一订单链的不同事件，不能累加。

生产实现必须在下钻时保留公会、范围、版本、截止日与指标窗口；静态SVG仅演示目标页标注的数据状态，不模拟动态带参查询。未实现的其他公会详情入口只作视觉说明，不能跳到星河公会冒充其结果。

## 后续迭代

资金闭环评分、闭环涉及消费与实际回流金额的计算规则继续按需求评审细化。本版确定对应结果、说明及证据的展示位置，不通过原型固化尚未确认的算法。第08页的“后续回流待核验”不能视为已确认闭环。

## 重新生成

在公会运营目录执行：

```powershell
.\设计\生成工具\generate-prototypes.ps1
.\设计\生成工具\render-prototypes.ps1
```

生成工具只写入本项目`设计/`目录。SVG、导航及页面清单由生成脚本创建，PNG与总览由渲染脚本创建。渲染使用本机已有Node.js和sharp；运行时路径可以通过脚本参数调整。
