# 主播日数据统计需求

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 需求名称 | 主播日数据统计 |
| 统计模式 | T+1 |
| 统计粒度 | 统计日期 + 主播ID |
| 统计范围 | 单人直播、多人直播 |
| 金额币种 | 美元（USD） |
| 文档状态 | 待评审 |

## 2. 需求背景

为评估主播每日直播表现、收入及成本、用户观看质量、关注转化和拉新贡献，需要建设主播日数据统计能力，为主播运营、财务分析及经营决策提供数据支持。

## 3. 需求目标

1. 每天定时统计前一个自然日的主播数据。
2. 支持按主播、所属运营及国家查看每日经营表现。
3. 统一收入、消费、奖励、观看、关注、拉新和互动指标口径。
4. 支持任务重试、历史补跑以及迟到数据回刷。
5. 保证汇总结果能够追溯至直播场次、用户行为和交易明细。

## 4. 统计规则

### 4.1 统计模式

- 采用 **T+1统计模式**。
- 系统每天定时执行一次，统计前一个自然日的数据。
- 具体执行时间应安排在充值、消费、直播、关注等上游数据完成后，例如每日03:00；最终时间由上游数据就绪时间确定。
- 如果任务在2026年8月12日执行，则统计2026年8月11日00:00:00至23:59:59的数据。

### 4.2 数据粒度

一条数据代表一个主播在一个统计日的汇总数据。

唯一键为：

`统计日期 + 主播ID`

同一统计日期重复执行时，应按照唯一键覆盖更新，不得重复插入。

### 4.3 统计时区

所有时间按照平台统一业务时区切分自然日。统计任务、明细数据和报表展示必须使用同一时区。

> 统一业务时区需在开发前由业务确认。

### 4.4 直播范围

直播相关指标仅统计以下直播类型：

- 单人直播；
- 多人直播。

不统计语音房、派对房、游戏房等其他类型，除非其业务类型已经明确归类为单人直播或多人直播。

直播时长、观看、停留、关注转化和互动指标使用相同的有效直播场次范围。

### 4.5 有效数据

以下数据不纳入统计：

- 测试账号、系统账号和机器人产生的数据；
- 测试直播、无效直播及系统判定的异常挂机数据；
- 已退款、撤销、冲正或被风控判定无效的交易；
- 系统自动消息、入场通知等非用户主动发言。

### 5.2 基础维度

| 字段 | 定义 |
| --- | --- |
| 日期 | 数据所属自然日 |
| 主播ID | 主播用户唯一标识 |
| 所属运营ID | 优先取主播直属运营ID；没有直属运营时，取主播所属公会的运营ID；两者均没有时为空 |
| 国家 | 主播注册时选择的国家，取用户信息表中的国家字段 |

所属运营ID取统计任务执行时主播资料中的最新归属关系，不追溯统计日当天的历史运营归属。对历史日期进行补跑或回刷时，仍取执行时最新的运营ID，因此历史数据的运营ID可能随重新统计而变化。国家直接取用户信息表中主播注册时选择的国家。

### 5.3 提现指标

| 指标 | 统计口径 |
| --- | --- |
| 申请提现成功金额（按申请日）（$） | 统计日提交提现申请，并且截至当前已进入最终打款成功状态的提现金额之和 |
| 提现成功金额（按打款日）（$） | 在统计日实际完成打款，并进入最终成功状态的提现金额之和 |

示例：主播在8月1日申请提现100美元，8月3日打款成功，则8月1日的申请提现成功金额增加100美元，8月3日的提现成功金额增加100美元。

失败、取消、处理中或风控拒绝的提现订单不计入上述两个指标。

由于按申请日统计的成功金额依赖后续状态，申请日的历史数据允许在订单打款成功后发生变化，系统需要定向回刷对应申请日的数据。

### 5.4 收入与消费指标

| 指标 | 统计口径 |
| --- | --- |
| 主播普通礼物收入金额（$） | 统计日普通礼物给主播产生的有效分成收入 |
| 主播幸运礼物收入金额（$） | 统计日幸运礼物给主播产生的有效分成收入 |
| 主播游戏收入金额（$） | 统计日游戏业务给主播产生的有效分成收入 |
| 主播收入金额（$） | 普通礼物收入、幸运礼物收入和游戏收入之和 |
| 直播间普通礼物消费金额（$） | 用户在该主播直播间赠送普通礼物产生的有效消费金额 |
| 直播间幸运礼物消费金额（$） | 用户在该主播直播间参与幸运礼物玩法产生的有效消费金额 |
| 直播间游戏消费金额（$） | 用户在该主播直播间参与游戏产生的有效消费金额 |

计算公式：

`主播收入金额 = 主播普通礼物收入金额 + 主播幸运礼物收入金额 + 主播游戏收入金额`

收入金额表示主播分成收入；消费金额表示用户侧有效消费，两类指标不得混用。

#### 5.4.1 金额规则

- 原始数据为金币或其他币种时，按照平台统一业务汇率折算为美元。
- 汇率版本、汇率生效日期、金额精度及四舍五入规则应保持统一。
- 金额建议使用 `decimal(18,2)` 或更高精度存储，不得使用浮点类型。
- 后续发生退款、追回或冲正时，应按照财务统一口径回刷交易发生日，或者在冲正日记录负向金额。

### 5.5 邀请用户指标

| 指标 | 统计口径 |
| --- | --- |
| 当日邀请用户数 | 统计日通过该主播邀请码成功注册并绑定邀请关系的去重用户数 |
| 累计邀请人数 | 截至统计日结束，通过该主播邀请码成功注册并绑定有效邀请关系的累计去重用户数 |
| 当日邀请用户充值人数 | 统计日通过该主播邀请码成功注册并绑定邀请关系，且在统计日充值成功的去重用户数 |
| 当日邀请用户充值金额（$） | 统计日通过该主播邀请码成功注册并绑定邀请关系的用户，在统计日充值成功的金额之和 |
| 当日邀请用户消费人数 | 统计日通过该主播邀请码成功注册并绑定邀请关系，且在统计日产生有效消费的去重用户数 |
| 当日邀请用户消费金额（$） | 统计日通过该主播邀请码成功注册并绑定邀请关系的用户，在统计日产生的有效消费金额之和 |
| 邀请用户充值人数 | 该主播历史邀请用户中，在统计日充值成功的去重用户数 |
| 邀请用户充值金额（$） | 该主播历史邀请用户在统计日充值成功的金额之和 |
| 邀请用户消费人数 | 该主播历史邀请用户中，在统计日产生有效消费的去重用户数 |
| 邀请用户消费金额（$） | 该主播历史邀请用户在统计日产生的有效消费金额之和 |
| 邀请新人抽奖金额（$） | 统计日主播通过“邀请新人抽奖”活动获得的有效奖励金额 |

邀请关系统计规则：

- 一个用户只能归属于一个有效邀请人；
- 以最终生效的邀请绑定关系为准；
- 仅点击邀请码但未完成注册和绑定的用户不计入；
- 充值人数仅统计充值成功的用户；
- 同一用户当天充值或消费多次，人数计1，金额累计；
- “当日邀请用户”相关充值和消费指标仅统计当日完成注册及邀请绑定的用户在注册当日产生的行为；
- 不带“当日邀请用户”前缀的充值和消费指标，统计该主播全部历史邀请用户在统计日产生的行为，包含当日新邀请用户；
- 邀请新人抽奖金额统计主播获得的活动奖励，不统计被邀请用户的抽奖消费。

### 5.6 奖励、成本与净收益指标

| 指标 | 统计口径 |
| --- | --- |
| 直播时长奖励金额（$） | 主播因达到有效直播时长要求获得的奖励金额 |
| 优质主播奖励金额（$） | 主播因达到优质主播标准获得的奖励金额 |
| 周奖励金额（$） | 主播对应的周维度金额，按照业务确认的归属日期计入 |
| 其他奖励金额（$） | 不属于上述类型的其他金额，按照业务确认的归属日期计入 |
| 总成本（$） | 周奖励金额与其他奖励金额之和 |
| 主播净收益（$） | 主播收入金额减去总成本 |

计算公式：

`总成本 = 周奖励金额 + 其他奖励金额`

`主播净收益 = 主播收入金额 - 总成本`

> 业务确认项：如果周奖励和其他奖励是平台发给主播的奖励，则不能作为主播成本从收入中扣除。此时应将其定义为奖励收入，并将公式调整为“主播总收益 = 主播收入金额 + 各类奖励金额”。当前文档暂按业务给出的成本及净收益公式执行。

### 5.7 直播时长指标

| 指标 | 统计口径 |
| --- | --- |
| 当日直播时长 | 主播当日单人直播和多人直播的有效开播时长之和 |
| 当日上麦时长 | 主播在多人直播中实际处于上麦状态的有效时长之和 |

统计规则：

- 跨自然日的直播按照自然日边界拆分；
- 同一主播存在重叠直播记录时，重叠时段只统计一次；
- 异常中断后重新开播的，按照不同直播场次记录；
- 测试直播、无效直播、封禁期间直播和异常挂机时长不计入；
- 单人直播时长不计入多人直播上麦时长；
- 时长统一以秒存储，展示层可转换为小时或分钟。

### 5.8 观看与停留指标

| 指标 | 统计口径 |
| --- | --- |
| 观看用户人次 | 每场直播内按用户ID去重，再将各场去重人数相加；同一用户观看两场计2人次 |
| 日去重观看人数 | 主播当天所有有效直播场次跨场按用户ID去重；同一用户当天只计1人 |
| 观看总时长 | 所有用户在该主播有效直播场次中的有效观看时长之和 |
| 平均停留时长 | 观看总时长除以观看用户人次 |

计算公式：

`观看用户人次 = Σ 每场直播去重观看人数`

`平均停留时长 = 观看总时长 ÷ 观看用户人次`

统计规则：

- 同一用户在同一场直播中多次进入，观看用户人次计1，观看时长累计；
- 同一用户观看主播两场直播，观看用户人次计2，日去重观看人数计1；
- 同一用户多端同时观看同一场直播时，重叠观看时间只统计一次；
- 主播本人、系统账号、机器人及测试账号不计入观看用户；
- 跨自然日观看区间按照自然日边界拆分；
- 单个用户在单场直播中的有效观看时长不得超过该场直播的有效时长；
- 观看用户人次为0时，平均停留时长返回0。

### 5.9 关注指标

| 指标 | 统计口径 |
| --- | --- |
| 日末累计关注人数 | 截至统计日结束时，仍处于关注该主播状态的用户数 |
| 当日新增关注人数 | 统计日内由未关注变为已关注状态的去重用户数 |
| 当日取消关注人数 | 统计日内由已关注变为未关注状态的去重用户数 |
| 当日净增关注人数 | 当日新增关注人数减去当日取消关注人数 |
| 观看关注转化率 | 当日观看该主播且新增关注的用户数除以日去重观看人数 |

计算公式：

`当日净增关注人数 = 当日新增关注人数 - 当日取消关注人数`

`观看关注转化率 = 当日观看且新增关注人数 ÷ 日去重观看人数`

统计规则：

- 当日新增关注人数可以包含直播间、主播主页和推荐页等所有入口产生的关注；
- 观看关注转化率的分子必须限定为统计日观看过该主播直播的新增关注用户；
- 同一用户当天多次关注或取消关注，新增人数和取消人数分别按用户去重；
- 日末累计关注人数以统计日结束时的最终关注状态为准；
- 日去重观看人数为0时，观看关注转化率返回0。

### 5.10 新用户指标

新用户定义为在统计日完成有效注册的用户。

| 指标 | 统计口径 |
| --- | --- |
| 新用户观看人次 | 当天注册用户中，每场直播内按用户去重后跨场求和的观看人次 |
| 日去重新用户观看人数 | 当天注册且进入该主播有效直播场次的去重用户数 |
| 新用户新增关注人数 | 当天注册并在当天关注该主播的去重用户数 |
| 新用户观看总时长 | 当天注册用户在该主播有效直播场次中的有效观看时长之和 |
| 新用户平均停留时长 | 新用户观看总时长除以新用户观看人次 |
| 新用户关注转化率 | 当天观看该主播且新增关注的新用户数除以日去重新用户观看人数 |

计算公式：

`新用户平均停留时长 = 新用户观看总时长 ÷ 新用户观看人次`

`新用户关注转化率 = 当天观看且新增关注的新用户数 ÷ 日去重新用户观看人数`

统计规则：

- 新用户注册时间和主播日数据使用相同业务时区；
- 新用户新增关注人数可以包含所有入口产生的关注；
- 新用户关注转化率的分子必须限定为当天观看过该主播直播的新用户；
- 分母为0时，新用户平均停留时长或新用户关注转化率返回0。

### 5.11 直播间互动指标

| 指标 | 统计口径 |
| --- | --- |
| 发言用户人次 | 每场直播内至少产生一条有效发言的用户数，每场按用户ID去重后跨场求和 |
| 直播间互动率 | 发言用户人次除以观看用户人次 |

计算公式：

`发言用户人次 = Σ 每场直播去重发言人数`

`直播间互动率 = Σ 每场直播去重发言人数 ÷ Σ 每场直播去重观看人数`

互动率采用“各场人数分别求和后再计算比例”的方式，不采用每场互动率的简单平均，也不使用“观看人数除以发言人数”的反向公式。

有效发言规则：

- 发言用户必须进入过对应直播场次；
- 用户在同一场直播发送多条有效消息，发言用户人次计1；
- 同一用户在两场直播中均发言，发言用户人次计2；
- 排除主播本人、机器人、系统账号和测试账号发言；
- 排除系统通知、入场消息等自动消息；
- 观看用户人次为0时，直播间互动率返回0。

## 6. T+1调度与补数机制

### 6.1 正常调度

每天执行以下处理：

1. 检查前一自然日上游数据是否就绪；
2. 汇总前一自然日各主播数据；
3. 按“统计日期 + 主播ID”覆盖写入主播日表；
4. 执行数据质量校验；
5. 记录任务执行时间、数据日期、处理行数、异常行数及执行状态。

### 6.2 重试机制

- 任务失败后支持自动重试；
- 自动重试仍失败时触发告警；
- 支持按指定日期进行人工补跑；
- 重试及补跑必须满足幂等要求。

### 6.3 历史数据回刷

以下数据可能在T+1任务完成后继续变化：

- 按申请日统计的申请提现成功金额；
- 延迟入账的充值、消费及奖励；
- 后续退款、冲正和风控追回数据。

建议处理方式：

1. 每天正常统计T-1数据；
2. 每天滚动重算最近7个自然日的数据；
3. 对超过7天才发生状态变化的提现订单，根据状态变更记录定向回刷其申请日期；
4. 提供指定日期及日期区间补跑能力。

## 7. 数据验收规则

1. 同一统计日期、同一主播只能存在一条记录。
2. 所有人数、次数、时长和非冲正金额不得小于0。
3. 日去重观看人数不得大于观看用户人次。
4. 日去重新用户观看人数不得大于日去重观看人数。
5. 新用户观看人次不得大于观看用户人次。
6. 发言用户人次不得大于观看用户人次。
7. 观看关注转化率、新用户关注转化率和直播间互动率应处于0%至100%。
8. 当日净增关注人数必须等于当日新增关注人数减去当日取消关注人数。
9. 主播收入金额必须等于三类主播收入金额之和。
10. 总成本必须等于周奖励金额与其他奖励金额之和。
11. 主播净收益必须等于主播收入金额减去总成本。
12. 比例及平均值的分母为0时，结果统一返回0。
13. 跨自然日直播和观看记录必须按照自然日边界拆分。
14. 提现按申请日和按打款日的数据应能追溯至对应提现订单。
15. 随机抽取主播、直播场次及用户明细重新计算时，应与主播日表结果一致。
16. 累计邀请人数不得小于当日邀请用户数。
17. 当日邀请用户充值人数和消费人数均不得大于当日邀请用户数。
18. 当日邀请用户充值人数、充值金额、消费人数和消费金额均不得大于对应的历史邀请用户当日指标。

## 8. 开发前待确认项

1. 平台统一业务时区。
2. 每日T+1任务的具体执行时间。
3. 美元折算汇率及精度规则。
4. 周奖励、其他奖励是主播承担的成本，还是平台发给主播的奖励。
5. 周奖励及其他奖励按照业务归属日期还是实际结算日期统计。
