# SANO Time 产品需求设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 需求名称 | SANO Time 官方平台时间 |
| 文档状态 | 需求设计稿，待业务与视觉评审 |
| 涉及端 | SANO App、H5及涉及时间的业务页面 |
| 目标用户 | 全球主播、公会、公会成员和普通用户 |
| 核心目标 | 让用户能够查看并核对平台统一时间，减少跨时区引起的结算、周期和有效时长误解 |
| 官方时区 | UTC+8，全年固定，不使用夏令时 |

## 2. 背景与问题

SANO 面向多个国家和时区，但结算、活动周期、榜单、每日重置和有效直播时长统一按 UTC+8 计算。多数用户不了解 UTC+8 的含义，容易将设备当前时间误认为平台结算时间。

SANO 同时包含 App、H5 等多种客户端，其中部分 H5 页面和介绍内容包含活动时间、周期时间及规则时间，无法保证所有时间均根据用户所在时区实时转换。自动换算本地时间还可能受到设备时区设置错误、系统时区数据异常、跨国移动和 VPN/IP 判断不可靠等因素影响。若不同客户端分别展示本地时间，容易造成时间口径不一致，并形成新的结算争议。

因此，App、H5 统一以 `SANO Time（UTC+8）` 作为官方时间口径。这样既不要求所有 App、H5 内容进行复杂的本地时区换算，也能避免每个时间点重复显示 UTC+8 而显得突兀。

## 3. 设计决策

1. 平台唯一正式时间命名为 `SANO Time（UTC+8）`。
2. 个人中心在接口数据有效时展示 SANO 当前日期和时间。
3. 不自动展示“用户本地时间”，也不计算与用户所在地的时差。
4. 已有结算、任务和活动页面继续以服务端倒计时作为主要行动信息。
5. 具体规则和记录中的时间点统一标注 `SANO Time`，不混用“系统时间”“北京时间”或未注明时区的时间。
6. SANO Time 必须来自服务端时间基准，不能直接使用设备系统时间作为官方时间。
7. App、H5 及运营配置内容统一使用 SANO Time，不要求转换为用户本地时间。

### 3.1 功能描述

在个人中心新增 SANO Time 模块，由服务端提供标准时间及跳转配置。

- 接口返回时间戳、跳转类型和跳转链接。
- App 将服务端时间戳按 UTC+8 转换，显示为“年月日 时分秒”。
- 请求成功后，App 在服务端返回时间的基础上每秒累加 1 秒，无需每秒调用接口。
- 重新进入页面或 App 恢复前台时，重新请求接口并校准时间。
- 跳转配置有效时，点击模块按指定类型跳转。
- 跳转配置无效时，仅展示时间，不响应点击。
- 接口请求失败、超时、无数据或时间戳无效时，整个模块不展示。
- 模块隐藏后页面布局自然衔接，不保留空白占位。
- 模块的加载、计时或跳转异常不能影响个人中心其他模块的展示与操作。
- 不展示加载占位、错误提示或重试入口。

## 4. 展示方案

### 4.1 个人中心默认态

在关注数据与 Coin/VIP 卡片之间增加轻量时间条，不改变原有主操作层级。

```text
SANO TIME · UTC+8
2026-09-21 10:12:35                         ⓘ
```

- 日期采用 `YYYY-MM-DD`，避免不同国家的月/日顺序歧义。
- 时间采用 24 小时制并显示秒，强化“官方平台时钟”的实时感。
- 数字使用等宽或表格数字，避免秒数变化造成布局抖动。
- 跳转配置有效时，点击整条时间区域按服务端指定的跳转类型和链接执行跳转。

### 4.2 跳转规则

服务端通过跳转配置决定点击模块后的目标页面，目标页面可用于解释 SANO Time 的业务含义，但不提供本地时间换算。

- `jumpType` 与 `jumpUrl` 均有效时，App 按指定类型执行跳转。
- 无需跳转时，服务端可返回不跳转类型，模块正常展示且不响应点击。
- 跳转类型未知、链接为空或链接校验失败时，模块继续展示，但不响应点击。
- 跳转失败不得影响个人中心当前页面及其他模块。

目标说明页面需明确：

- SANO Time 固定为 UTC+8。
- 适用于每日重置、活动周期、榜单及结算。
- 设备时区不会改变 SANO Time。
- 各业务页面的倒计时继续作为剩余时长提示。

### 4.3 业务页面规则

- 已经有倒计时的页面不新增常驻双时区模块。
- 需要展示确切截止时间时使用：`2026-09-22 00:00:00 SANO Time`。
- 历史结算记录使用：`Settled at 2026-09-22 00:00:00 SANO Time`。
- 单个时间点直接在时间后标注 `SANO Time`。
- 同一页面包含多个时间点时，可在页面顶部或时间区域统一标注 `All times are based on SANO Time (UTC+8)`，无需在每个时间点后重复显示 UTC+8。
- App、H5 和运营配置的活动介绍、周期说明及规则内容均使用相同时间口径，不进行用户本地时区换算。
- 页面空间有限时，可将完整时间放在倒计时的说明、详情或规则弹层中。
- 禁止只写 `00:00`、`today`、`tomorrow` 等依赖用户所在地日期理解的表达。

## 5. 接口、时间同步与展示控制

### 5.1 接口返回

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `timestamp` | 是 | 服务端当前时间戳；前后端需统一秒或毫秒单位 |
| `jumpType` | 否 | 跳转类型，使用双方约定的固定枚举 |
| `jumpUrl` | 否 | 跳转目标，由 App 按跳转类型进行校验和处理 |

### 5.2 App 处理规则

1. App 进入个人中心时请求接口，取得服务端时间戳及跳转配置。
2. App 将时间戳固定转换为 UTC+8，并显示为 `YYYY-MM-DD HH:mm:ss`。
3. 首次显示后，以接口返回的时间为基准，由前端每秒累加 1 秒，不需要每秒调用服务端接口。
4. App 恢复前台或重新进入个人中心时，再次请求接口并校准时间。
5. 结算倒计时与 SANO Time 应使用相同的服务端时间基准。
6. 不得使用设备系统时间替代接口返回时间。

### 5.3 隐藏规则

以下任一情况发生时，整个 SANO Time 模块不展示：

- 接口请求失败或超时。
- 接口返回为空或无有效数据。
- 时间戳缺失、格式错误、超出有效范围或无法转换。
- 其他导致模块无法安全展示的异常。

模块隐藏后不保留占位，不显示骨架屏、错误提示或重试按钮；该模块的请求、解析、计时和跳转均需与个人中心其他模块隔离。

## 6. 交互与可用性

- 时间条整行可点击，点击区域高度不低于 44dp。
- 秒钟更新不得导致卡片宽度、文字位置或页面布局跳动。
- 页面进入后台后可暂停逐秒重绘；恢复前台时立即根据服务端基准校正。
- 屏幕阅读器应朗读完整日期、时间和 UTC+8，例如：“SANO Time，2026年9月21日，10点12分35秒，UTC加8”。
- 模块展示或隐藏时不得造成个人中心其他模块错位、闪烁、无法点击或加载失败。
- 模块内部异常必须被独立处理，不得阻断个人中心页面渲染或其他接口请求。

## 7. 埋点建议

| 事件 | 触发时机 | 目的 |
| --- | --- | --- |
| `sano_time_exposure` | 个人中心时间条进入可视区域 | 了解功能覆盖 |
| `sano_time_click` | 用户点击时间模块 | 统计跳转使用情况 |
| `sano_time_sync_failed` | 无法取得服务端时间 | 监控同步质量 |
| `sano_time_hidden` | 因无数据或数据异常隐藏模块 | 监控模块可用性 |

## 8. 验收标准

1. SANO Time 与服务端 UTC+8 时间一致，正常网络下误差不超过 1 秒。
2. 日期跨日时按 UTC+8 正确切换，不受设备时区和夏令时影响。
3. 用户手动修改设备日期、时间或时区后，SANO Time 不发生对应跳变。
4. App 基于服务端返回时间每秒累加 1 秒，过程中不产生每秒接口请求。
5. 接口失败、超时、无数据或时间戳无效时，模块完全隐藏且不保留空白。
6. 模块请求、解析、计时或跳转异常时，个人中心其他模块仍能正常展示和操作。
7. 跳转配置有效时可正确跳转；配置无效时模块正常展示但不可点击。
8. 模块在常见移动端宽度下无截断或横向滚动。
9. 所有新增文案统一使用 `SANO Time（UTC+8）`。

## 9. 本期范围外

- 自动计算或展示用户本地时间。
- 根据 IP、SIM、GPS 或语言推断用户实际时区。
- 允许用户修改 SANO 官方时区。
- 改造现有业务页面的倒计时逻辑。
